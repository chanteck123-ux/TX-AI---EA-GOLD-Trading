# A186 skill-rl-portfolio-allocator — Claude 全文审核（2026-11-05）

## P0221 尾段（FULL_READ；FILES 1860–1866：AGENTS、CLAUDE、runbook rl-oos-research、HERMES、OPENCLAW、README.en、README）
- 定位：用 PPO 学习 K 维**因子权重**（不是个股权重），每周调仓；从 100 个候选因子中，在每个 fold 的训练段选出 20 个；按综合得分做多 Top-30、做空 Bottom-15（名义空头上限 30%）；reward 为净收益减回撤、换手和集中度惩罚；嵌入佣金、印花税、冲击和融券成本；8 道研究 gate 全部通过才允许发布。中英文 README 一致（中文版多一张合规状态表）。
- **优点（工程纪律好）**：
  - gate 采用 fail-closed，**gate 失败时保留产物用于诊断，不改阈值、不凑 fold、不发布**；
  - 测试集只跑一次，候选、reward、buffer、scaler 和 benchmark 的选择都只用训练和验证段；
  - smoke 运行强制 publishable=false；
  - 发布前保留整份生产目录，恢复时整体原子替换，并记录操作者；
  - 2 倍成本下的 OOS Sharpe 仍须为正；
  - 证据缺失即判为失败。
- **问题**：
  1. **做空假设不现实**：在沪深300 成分股中做空 Bottom-15、融券年化成本 8%，A 股融券券源有限且常常不可得（还有监管限制），回测默认想借就能借到。
  2. **股票池可能有幸存者偏差**：用 `get_stock_daily_post` 的 `indicator="000300"` 筛选成分股，如果返回的是**当前**成分股而不是历史时点的成分股，会产生幸存者偏差（需要核实 SKILL 和 features 的实现）。
  3. 压力测试的四个场景（2008、2015、2020、2022）都落在 2004–2024 的样本内，对后面的 fold 来说可能已经进入训练窗口。训练时还对危机段做了 3 倍超采样，所以压力测试结果可能部分是样本内的。
  4. reward 有多个变体（none / low / gentle / constrained / legacy_dsr），在验证段上挑选，加上 3 fold × 5 seed，**搜索空间没有做多重检验校正**；gate 的阈值（如 Sharpe 提升 ≥0.1）是固定值，fold 只有 3 个，"正超额 fold ≥2"的统计效力很弱。
  5. 冲击成本取 5bps × 换手，对周频多空 45 只股票的策略来说偏乐观。
- 子目录中的研究和生产 SKILL、DSR 推导、因子选择文档在 P0222 中，待读。

## P0222 前段（FULL_READ；FILES 1867–1871：dsr_derivation、factor-selection、研究 SKILL、生产 SKILL、根 SKILL）
- **DSR 公式核对正确**：DSR_t = (B_{t−1}ΔA − ½A_{t−1}ΔB)/(B_{t−1} − A_{t−1}²)^{3/2}，与 Moody & Saffell (1998) 一致。
- **修正上一段的判断**：研究 SKILL 写明压力测试的模型训练窗口在"各压力段之前"，所以压力场景对该模型是样本外的，**不是**我先前推测的样本内。危机段 3 倍超采样只作用于主训练环境。
- **新发现**：
  1. **因子选择会逐级放宽阈值，直到凑够 20 个**：level 0 到 4 依次放宽 mean_ic、icir、符号一致性、同族上限和相关性上限，最后一级全部"不限制"。这意味着**无论候选质量如何，总会选出 20 个因子**，"选出"本身不代表通过了质量门槛。放宽过程虽然记录在 relaxation_log 中，但 gate 并不检查放宽到了第几级。
  2. **gate 数量和语义不一致**：factor-selection.md 列出 6 道 gate，README 列出 8 道（多了 stress_calmar 和 long_exposure_util）。压力回撤的 gate 在 README 中写作 `candidate_stress_mdd_excess ≥ 0.05`（超额不低于 0.05），在 factor-selection 中写作"相对 control 恶化不超过 0.05"，两种写法方向相反，含义不清。
  3. 选因子时，用滞后一日的因子与 1 日收益 `ret_1d` 计算 IC，组合却按周调仓，**评价期限与持有期不一致**。
  4. 生产模型用"数据起点到最新日、无样本外尾巴"的全量数据重新训练，**发布的模型与通过 gate 验证的模型不是同一个**。这是常见做法，但 approval 实际批准的是方法，不是这个 checkpoint，文档应该写明。
  5. 成分股筛选用 `indicator="000300"`，是否为历史时点的成分股，仍需看脚本确认。
- 优点：factor contract 包括目录 hash、有序的选中因子、方向和 schema 版本，加载、发布和推理时都要校验，任何不一致就拒绝；approval 绑定 method、gates、comparison 的 sha256，发布前重新计算并重新评估 gate。工程上的可追溯性非常好。

## A186 结论
- 研究工程是本批中**最严格**的之一：fail-closed gate、只跑一次测试集、证据哈希绑定、原子发布与回滚。主要问题在研究设计：①A 股融券做空的假设不现实；②因子选择最终会无条件选满 20 个；③gate 的数量和方向在文档间不一致；④3 个 fold 的统计效力弱；⑤IC 期限与持仓周期不一致。
- 对 V1.2：approval 绑定证据哈希、smoke 结果永远不可发布、gate 失败不改阈值，这三条可以直接对应本项目"候选、合格最佳、验证通过、Champion 分开记录"的规则。scripts 未审。
