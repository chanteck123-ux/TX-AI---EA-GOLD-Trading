## 独立发现
1. **`discount_rate` 单位与符号在三份文档中互相矛盾（关键）**：README/SKILL 写"按**小数比例**换算，0.003 = 30bps"；data-fields 写"贴水率(**%**)"；methodology 写 `premium_bps = −discount_rate × 100`（这只在单位为 % 时成立，且带符号反转）。若字段实为小数，按 ×100 换算会把 30bps 算成 0.3bps（差 100 倍）；若 README 换算不做符号反转，溢价/折价方向会颠倒。脚本未核，无法判断实际采用哪一种。
2. **"实时"与日频数据不符**：description 称"real-time premium/discount"，但数据为日频收盘（盘中只有分钟线代理）；收盘价算出的折溢价窗口在收盘后已无法同时完成申购与二级卖出，不能直接视为可执行窗口。
3. **成本假设偏简**：固定 20bps 粗估；折价套利需卖出成分股，A 股卖出印花税、"必须现金替代"成分的现金替代溢价比例、IOPV 估算误差都未纳入 gross_bps；`|premium| − cost > 0` 不足以说明可执行。
4. 成交额阈值单位"万元"与 `amount` 字段单位未在字段表中统一说明。

## 静态源码核查（scripts/premium.py 全文 117 行；不在文本 manifest；未运行）
1. **单位矛盾的实际答案**：第 36 行 `premium_bps = -raw * 10_000.0`，并记录 `discount_rate_unit: "ratio"`——实现按**小数比例**换算并做符号反转，与 README 的"0.003=30bps"一致；`references/methodology.md` 的 `−discount_rate × 100`（% 口径）是**过时或错误文档**。字段真实单位仍取决于供应商，本审查未调用接口核实。
2. **成分缺价被静默跳过（新发现）**：`iopv_from_constituents` 第 61–67 行只累加有收盘价的成分，`priced>0` 即返回；缺价成分（停牌、代码不匹配）的市值直接漏掉，IOPV 偏低→虚假溢价。只在全部缺价时才返回 None，部分缺价不计入 `degraded`。与 README"关键数据缺失 fail closed"不一致。
3. **路径 A 不校验日期对齐**：`premium_from_interface` 取最新一行，不与 `data_date` 对齐；路径 B1 才按 `data_date` 选篮子。
4. 现金差额取 `cash_component`（通常为前一日实际值），而成分价为当日收盘；申赎清单的 `estimated_cash_component` 未使用——两者日期口径是否匹配未说明。
