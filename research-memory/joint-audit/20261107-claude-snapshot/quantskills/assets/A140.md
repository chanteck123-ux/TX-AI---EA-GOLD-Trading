# A140 skill-minuteflow-alpha（分钟特征 → LLM 生成日频 Alpha，Draft，GPL-3.0-only）— 文本审核

范围：P0142 FILE 1448 portable-loader、1449 README.en、1450 README、1451 references/agent-integration、1452 references/minute_alpha_ops、1454 SKILL.md 全文。FILE 1453 requirements.txt 为 HASH_REUSE（与 skill-fundamental-alpha 的同名文件字节相同）；scripts、config.json、operators.json 不在计划内，**未读**。

要点：
- 由 PandaData 分钟线（默认 5m，沪深 300，20250102–20250624）提取 44 个日聚合特征（8 个族），再由 LLM 根据文档、URL、自然语言或"自由发明"生成表达式，经校验（NaN、极端值、窗口 n≥1）和最多 5 次自动修正后，导出 date,ticker,value 的日频 CSV。
- 特征数核对：6 + 6 + 7 + 6 + 7 + 5 + 4 + 3 = 44 ✓。

发现：
1. **【安全】SKILL.md 明文写入了一组 PandaData 用户名、密码和 base URL**（FILE 1454 第 926–928 行，位于 `.env` 示例处）。形式不像占位符，**疑似真实共享凭证**。本审核**不转录其值**。属严重的凭证泄露问题，应由仓库维护者撤除并轮换；本项目不得使用。
2. **【安全】operators.json 中的 `numpy_impl` 是 lambda 字符串，"validator 和 generator 自动加载、无需改代码"**，而 LLM 还可以通过 `new_operator` 提议新算子。若实现方式是 eval/exec，就等于执行数据文件中的任意代码；叠加"--doc 可抓取任意 URL 内容作为输入"，存在提示注入导致代码执行的风险（未读代码，属设计层面的推断）。
3. **占位特征参与表达式**：Lead-Lag 族中 `sector_lead_rank`=0.5、`peer_correlation_lag1`=0.0、`lead_lag_strength`=0.0 都是**常数占位**，示例却给出 `rank(sector_lead_rank)`，横截面排序全部相同，信号退化。
4. 特征命名与计算不符：
   - `gap_fill_ratio` 被定义为"open_30m_return（proxy）"，与 `open_30m_return` 完全相同，并不是缺口回补；
   - "Order Flow"族用的是 K 线收盘位置（类似 CLV 的方式）乘以成交量来代理，**不是真实的买卖盘流向**；
   - `institutional_participation = 1 − retail_flow_ratio` 基于笔数中位数切分，命名过度解读；
   - `close_auction_return` 用最后一根 5m bar，它包含 14:55–14:57 的连续竞价，并不只是收盘集合竞价。
5. **样本太短**：默认约 6 个月（文档说"5m 大约只允许 6 个月"），日频因子评估的有效样本只有约 115 个交易日；LLM 又可以反复生成和修正，**多重试验偏差**没有任何控制。
6. 校验只覆盖 NaN 比例、极端 z 值和窗口 n≥1，**不检查预测力，也不检查与已有因子的相关性**；所谓"look-ahead 校验"只是语法层面的。
7. 要求每个 alpha 引用论文（APA/MLA）和 DOI，但**没有核实引用真伪的机制**，LLM 可能编造来源。
8. SKILL.md 的 front matter 结尾出现了两行 `---`（格式瑕疵）。

**A140 结论**：文本全部覆盖（6 份全文 + 1 份 HASH_REUSE）。凭证泄露与动态算子执行是**安全阻断级**问题；特征定义存在占位和命名不符，结果不能作为因子证据。与 EA 无关；**不得安装或运行**。
