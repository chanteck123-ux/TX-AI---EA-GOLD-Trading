# A044 skill-build-b10-factor-evaluation（全文审核笔记）
- 读取（P0045）：agents/portable-loader.md、FILE_MANIFEST.md、README(.en.md, .md)、SKILL.md（开发产物/SKILL.md、生产版和 references 见后续包）。
- 内容：因子评估 BUILD：横截面 IC/RankIC、ICIR、Newey-West HAC t（Andrews 自动选滞后阶数）、分层回测、单调性、Jaccard 换手、1–20 期衰减曲线、日内打乱的 bootstrap 噪声基线（双侧 p 值和 95% CI）、成本扫描、行业和风格 OLS 中性化（**必须由调用方提供暴露面板，否则抛 ValueError**，并有"红线测试"锁定）、HTML 报告、生产 Parquet（overwrite/append、主键 upsert、原子写入）。**不联网**——"断网能跑 demo"被作为最强证明；提交前用 grep 检查三条红线（不得调用 panda_data、不得硬编码盘符、不得跨 track import）。
- 好的做法：清单列出全部 37 个文件、每个文件的作用和删除后果；删除死代码时逐项记录；保留 `close_to_close_untradable` 样本做回归对照。
- **独立发现**：
  - ①**forward_return 由调用方提供**（"aligned by the caller"）——评估器无法核实收益口径和执行时点，A22 和 A26 那类时点问题会被原样接收，前视责任转嫁给了上游。建议评估器至少要求调用方声明口径元数据（入场价格类型、滞后、持有期），并写入报告。
  - ②`factor_direction = auto`：如果在全样本上根据 IC 符号自动选方向，等于**在评估数据上选择方向**，会让 IC 和多空收益偏乐观（实现不在清单内，待核实）。
  - ③**版本号不一致**：FILE_MANIFEST 写"最终交付版本 v1.5.0"，同一文件描述 skill.json 为 version = 1.4.1，CHANGELOG 最新也是 1.4.1。
  - ④换手用 Jaccard 距离（持仓集合变化），而 A43 在 v1.1 中明确把 Jaccard 替换成了等权单边换手——Jaccard 不反映权重变化，用于成本估算不准确。
- 对黄金 EA：
  - ①**"断网可运行"和 grep 红线**作为交付前的机械检查——对应我们"MQL5 交易与风控独立运行、Python 只做 MCP 监控"的边界检查（例如 grep EA 源码中不得出现 WebRequest 或 DLL 导入，除非已登记）；
  - ②中性化缺少输入时直接报错，而不是静默跳过；
  - ③评估工具要记录收益口径元数据。
- 续读（P0046）：开发产物/references/api_guide.md、references/CHANGELOG.md、开发产物/SKILL.md（共 46 KB，全部逐行阅读）。
- 补充：
  - 推荐的收益口径：t 日收盘后出信号时，`forward_return = close[t+2]/close[t+1] − 1`（t+1 收盘入场）——保守且可执行，比 A22/A26 正确。
  - 衰减曲线优先使用真实的分周期收益列，缺失时才回退到兼容计算。
  - 横截面不足以切出 10 组时，保留配置组数并报告实际组数，同时给出质量提示。
  - 非法类型、非有限数字、重复主键**始终报错**；`drop_missing` 只针对缺失值。
  - 请求非全 A 股票池但缺少池标签时**直接报错**，"避免误把全样本当成目标股票池"。
  - 换手 tie-break 按 ts_code 字典序——作者主动披露这是有偏的，需要无偏时由调用方加微小扰动。
  - IC 达标阈值：|IC| ≥ 0.02、|ICIR| ≥ 0.5；关键项不达标时结论为"研究中"。
- **CHANGELOG 中值得记录的诚实修正**：v1.4.0 删除了中性化时隐藏的联网取数——作者原话说这一行为"打脸 SKILL 的'不直接拉取'承诺"，随后把代码和文档对齐，并用红线测试锁住；还统一了三份独立的 Spearman 实现；修正了研究子表分组数不一致的 bug；成本扫描从"隐式 0 bps 行"改为显式 opt-in。这是**文档与代码一致性审计**的好例子。
- **独立发现（补充）**：
  - ⑤**多空成本只计顶部组合的换手**：净收益 = 日多空收益 − 顶部组合换手率 × 单边成本 × 2。多空组合有多头和空头两条腿，空头（底部组）的换手没有计入，成本被低估。
  - ⑥股票池标签（is_pool_*）由上游提供，B10 不校验是否是历史时点的成分——如果上游用当前成分打标签，就会带入幸存者偏差（责任同样在上游）。
  - ⑦CHANGELOG 中的版本号相互缠绕：1.4.1 条目写"skill.json 从 1.3.0 抬到 1.4.0"，而 1.5.0 又把编号从 B01 改为 B10；生产库中会同时存在 B01 和 B10 两种 build_id，下游需要兼容两者（作者已提示）。
- **A44 逐资产结论**：工程化和自我修正记录很好；主要风险在于评估输入的口径完全依赖上游、多空成本低估、auto 方向可能在评估数据上选择方向。**源码未读（不在清单内），未运行**。
