## P0199 后半（FULL_READ；FILES 1670–1674：portable-loader、README.en、README、legacy-metadata、warehouse-playbook）
- 定位：把 PandaData 行情增量缓存到本地 DuckDB 加 Parquet 仓库的数据工程技能，依赖 A158。
- 优点：原始层保留 API 字段，衍生计算放在下游；先写临时文件，校验后再替换，水位线只在写入、元数据和校验三者都成功后才推进；失败分区保留旧数据；破坏性操作必须列出文件并获得确认；凭证不写入元数据和日志；全市场分钟线下载前先确认范围；明确区分"追加稳定"和"历史可变"两类数据集。中英文 README 内容一致（逐段对照，英文版多出 "Contract interface and limits" 一节的位置不同，内容等价）。
- 问题：
  1. **没有 vintage 历史**：对"历史可变"数据集（前复权、厂商修订的因子）采用整分区重写，元数据只记录 last_refresh_at，不保留旧版本快照。回测因此无法复现某一历史时点看到的数据，与 PIT 研究的要求冲突。应改为按快照或 as-of 版本保存。
  2. 把"后复权日线"列为追加稳定，前提是"API 契约记录了稳定历史"。A158 的文档没有这样的保证，而且我在 A158 中发现前、后复权示例完全相同等问题，这个前提无法核实。
  3. 校验依据是"小样本与实时 API 一致"，只能发现本地与源头的漂移，不能发现源头本身的错误（A158 中的占位值和缩放错误会原样进入仓库）。
  4. 没有处理退市或代码复用问题（幸存者偏差和 PIT 身份）；分钟线表没有时区字段规范（README 提到的 envelope CLI 要求时区，但仓库元数据中没有）。
  5. 视图示例在 DuckDB 中使用 `~` 路径，可能不会展开；文档自己也提示要解析为绝对路径。
  6. README 提到的 `scripts/market_bar_envelope.py` 和 fixture 未审（属 .py，列入 GAPS）；`agents/openai.yaml`、`cursor-rule.mdc` 不在本清单中。
- legacy-metadata.md 只是维护者归属的存档，没有技术内容。
- SKILL.md 在 P0200，待读。

## A159 结论
- 数据工程规范质量较高（原子写入、水位线、可恢复、破坏性操作需确认、凭证隔离），可以作为本项目 LEAN/MT5 数据缓存规范的**参考条目**。
