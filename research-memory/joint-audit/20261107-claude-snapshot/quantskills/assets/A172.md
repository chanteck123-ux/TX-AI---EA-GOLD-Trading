# A172 skill-quant-execution-microstructure — Claude 全文审核（2026-11-05）

## P0212 后段（FULL_READ；FILES 1759–1765：portable-loader、CLAUDE.md、README.en、README、execution-models、market-microstructure、tca-and-operations）
- 定位：把已批准的组合交易转成执行方案，覆盖 VWAP/TWAP/POV/IS 等执行算法、订单类型、成交模拟、TCA、订单状态控制和对账。**与本项目的 RiskExecution（Claude 的职责）直接相关。** 中英文 README 一致。
- **方法核对（均正确）**：
  - microprice = (ask·bid_size + bid·ask_size)/(bid_size+ask_size)，是按对手量加权的中间价，正确；
  - effective spread = 2·side·(P−mid)/mid·1e4，正确；
  - IS = s·(fill−benchmark)·qty，买入为 +1，成交价高于基准记为成本，符号约定正确；
  - 成本分解为 explicit + spread + impact + delay + opportunity + residual，并明确注明"分解依赖基准，不可唯一识别的项要标注"。
- **对 RiskExecution 可直接借鉴**：
  1. **"超时不等于被拒，重试前先查询或对账"**，与本项目"CTrade 返回成功不等于成交"的原则一致，也适用于 MT5 的超时和 requote 处理。
  2. 订单状态机分为 created→validated→released→acknowledged→partially_filled→canceled/rejected/expired/filled/reconciled；每次状态转换都要持久化事件时间、接收时间、序号、幂等键、剩余数量和原因码。
  3. 必须测试的边界情况：空盘口、交叉盘口、行情陈旧、序号缺口、零成交量、跳空、停牌、涨跌停、拒单、重复确认、部分成交、撤单后的剩余量、收盘残量。"静默跳过这些状态的模拟器会高估执行质量。"
  4. 监控分 amber/red 两级阈值并对应具体动作；出现无法解释的成交或持仓不一致时，阻止重试并先对账；独立风控或场所状态丢失时进入文档化的安全模式。
  5. **"只有 OHLCV 时，不得声称达到队列级、场所级或盘口级的执行精度"**：MT5 Real Tick 只有 tick 数据，没有盘口深度，所以 V1.2 不能宣称达到队列级成交精度。
  6. 执行模型更新要做时间切分校准、样本外检验、压力测试，并准备回滚方案；"平均成本降低但尾部成本或操作风险上升，不能算改进"。
- **缺口**：
  - (a) 没有覆盖外汇和差价合约的特有问题：last look、requote、经纪商单边报价、点差在新闻时扩大、周末跳空、隔夜利息（swap）、Stop Out 和强平顺序；
  - (b) 状态机没有列出 pending_cancel 和 pending_replace 等中间态，"撤单失败但订单已成交"的竞态只在对账中提到；
  - (c) 默认行为是"未经明确授权不提交、撤销或修改实盘订单"，这一点好，但 SKILL 中的授权机制还要在下一段核实。
- SKILL.md 和 scripts 在后续包中，待读。

## P0213 前段（FULL_READ；FILE 1766：SKILL.md）
- 质量很高，规定了一套"不可协商的控制项"：
  - 完整的事件时间线；
  - 区分决策价、到达价、提交价、中间价、买卖价、最新价、VWAP、收盘价和标记价，**没有证据时不得假设按收盘价或中间价成交**；
  - 父单与子单分离，订单 ID 幂等，保留撤改单链路；
  - 发送前校验价格带、tick、手数、TIF 和重复订单，任何硬检查失败都阻止发送；
  - 队列位置未知时，结果必须标注为乐观、有界或探索性；
  - 不能把下单后的有利价格走势当作执行能力。
- 分层架构：parent_intent / market_state / policy / order_manager / cost_model / controls / analytics；结果必须带决策标签（reject / exploratory / paper-ready / production-candidate）；明确列出要捕捉的失效模式（超时后重复下单、撤改单风暴、在同一样本上优化 TCA 并隐藏失败试验）。
