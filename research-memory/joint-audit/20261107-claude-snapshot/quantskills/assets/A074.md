要点：
- 定位为信号层合并：输出 `composite_signal[date×symbol]` 截面 z-score，不做资金分配。
- 8 步流程：校验契约 → 读 ScoreReport → 过滤 → 相关矩阵加 top-bucket Jaccard → 去冗余 → 选权重 → 加权并逐日 z-score → 重新评价。

独立发现（文档间一致性，静态阅读）：
1. **去冗余阈值三处不一致**：README/SKILL 管线写 corr >0.7 同簇只保留 ICIR 最高者；weighting.md 写 rank corr >0.8 同簇保留 **score** 最高者，0.6–0.8 考虑正交化；危险信号又以 0.8 为界。阈值与保留依据（ICIR 还是 score）都不统一。
2. **权重公式不一致**：weighting.md 中 score 权重 = max(0, score) 截断后归一，icir 权重 = max(0, ICIR)；SKILL"权重计算逻辑"写 icir ∝ max(0.01, ICIR)（负 ICIR 因子仍保留小权重），score ∝ ICIR×√coverage/(1+turnover)，与 weighting.md 的"factor-evaluate 主分"完全不同。实际 blend.py 采用哪种未核查。
3. **cap 截断后再归一化会突破上限**：weighting.md 的 `min(cap, w)` 之后除以 s2<1，被截断的权重会重新升到 cap 以上。例如 3 个因子原始权重 0.8/0.1/0.1，cap 0.35 → 0.35/0.1/0.1 → 归一化后 ≈0.64/0.18/0.18，突破 0.35，也触发自身">50%"的危险信号。需要迭代截断（water-filling）才能保证上限。这是代码片段可直接推出的确定行为（未运行）。
4. `combine_factors` 中 `out.add(contribution, fill_value=np.nan)` 与 NaN 填充等同于不填充：任一因子在某股票缺值，该格合成结果即为 NaN，缺失会降低覆盖率，文档未说明。
5. **因子选择用的数据与评价数据可能重叠**：要求"权重只用 train/val"，但第 3 步按 ScoreReport 过滤、第 8 步重新评价；若两者都在 val 段，复合因子相对最佳单因子的提升就存在同段选择偏差（同 A62 类）。报告示例的 Period 就是 val 段。
6. SKILL 要求 Agent 必须反问用户权重方案，这是交互约定，不是方法约束。
