# A181 skill-regulatory-risk-radar — Claude 全文审核（2026-11-05）

## P0217 中段（FULL_READ；FILES 1822–1829：portable-loader、examples/sample_report、README.en、README、data-fields、risk-taxonomy、requirements、SKILL）
- 定位：A 股持仓的治理和监管风险雷达，覆盖解禁、减持、质押、举牌、冻结、停牌和 ST。每类事件的子分 = 基准分 × 规模因子 × 时间邻近因子，综合分 = 1 − ∏(1 − 子分/100)，分为低、中、高三档。
- **问题**：
  1. **样本数据回退可能把演示数据当成真实结果（关键）**：中文 README 写"无 SDK 时回退"到 `examples/sample_data`，即**自动回退**；英文 README 写"falls back to samples **when requested**"。两个版本的说法相反。如果是自动回退，在没有安装 SDK 的环境里跑"真实扫描"，输出的就是样本数据的风险清单，而且是针对用户提交的真实持仓。是否会在 `degraded_sources[]` 中注明，需要看脚本，脚本未审。
  2. **示例报告给真实上市公司贴风险标签**：sample_report 用"后端 sample"列出 4 家真实上市公司及其"风险分"和"主要触发项"（例如某公司"前十大股东股权冻结"、风险分 71.4、高风险）。如果样本事件是虚构的，就是**对真实公司发布了不实的风险信息**。本记录不复述具体分值与公司的对应关系，只记录有此问题。
  3. 综合分公式 1 − ∏(1 − s_i) 是"至少一项发生"的概率并集形式，前提是各子分是已校准且相互独立的概率。这里的子分只是主观基准分乘以因子，并不是概率；各类事件之间（如质押与冻结）也高度相关。所以这个公式只是一种单调的聚合方式，不能读作概率。
  4. 风险类别数量不一致：taxonomy 写 7 类，SKILL 写 6 类；减持的规模因子"1% 记满"、质押"30% 记满"、半衰期 90 天和 180 天、控股股东系数 ×1.15，都是主观设定（文档承认"方法论默认值"）。
  5. 依赖 A158 的 info_date，而 A158 中事件类数据的 info_date 是记录维护日期，不是信息首次可得的时间，所以时间邻近因子的口径可能失真。
- 优点：每条风险都要带公告日期，可以溯源；数据源降级要显式声明；大股票池分批取数；全市场返回的数据先按 symbol 过滤再入池。

## A181 结论
- 规则雷达的结构合理，但"自动回退到样本数据"（中英文说法矛盾）以及"示例中给真实公司贴风险标签"是两个实质性问题。综合分不应解读为概率。对 V1.2 没有直接关系。scripts 未审。
