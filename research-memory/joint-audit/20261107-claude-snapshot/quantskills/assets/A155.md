# A155 skill-pandaai-factor-online（经 pandaai-cli 参加平台因子大赛的挖掘流程）— 文本审核

## P0158 部分（FILE 1615 AGENTS.md、1616 portable-loader、1617 CLAUDE.md、1618 HERMES.md、1619 README.en、1620 README、1621 references/cli、1622 references/competition_proxy 全文）

要点：
- 冷启动三步：把仓库放到持久目录 → 运行 install.py → 按 SKILL 的核心流程执行（体检 → 用户自己登录 → 把余额换算成可运行次数 → 与用户确认调仓周期、窗口和预算 → 给出试探批次清单等用户批准）。**用户批准之前不花算力**。
- 不可违反的规则：登录由用户在自己的终端执行，Agent 不接触密码，不读取或提交 config、token、uid；结果按扣除换手成本后的**多头组超额**汇报，不单独引用平台的多空年化；**保留全部候选（含失败）作为多重检验的分母**。
- CLI 已知问题（作者自述，**未核实**）：新机器上 login 必然失败（配置先于命令加载）；`--json` 会静默关闭 `--download`；`factor_delete --pattern` 不可用；0.1.3 之前 `factor_update` 会丢参数；分组按因子值升序排列，多头端由方向参数决定。
- 比赛代理脚本只处理本地 JSON，结果明确写明"不是官方积分"。

评价：
1. **研究纪律好**：成本后的多头超额、保留全部候选、短窗口试探后再批量运行、每次运行都扣算力需先确认预算、凭证不由 Agent 接触。
2. 注意事项：
   - references/cli 给出了一行 python 命令，用 `factor_delete --yes` 按名称前缀批量删除因子，属于**不可逆的删除操作**；执行前应列出 id 清单并取得用户确认（文档没有强调确认步骤）。
   - 文档引导用户注册账号并参加大赛，带有平台推广属性。
   - "沙盒认证"一节建议考虑宿主侧只读检查，同时明确"不能假定可以越出沙盒，也不要复制 token"，表述得当。
3. "`MEAN(CLOSE,20)` 不是 20 日均线"等平台算子陷阱属于平台特定信息，**未核实**。

## P0161（FULL_READ；FILES 1636–1641）
**fields-oscillators.md**：公式导出有多处损坏或非标准写法。
1. TR = SUM(…, M1=9)，ATR = MA(TR,14)：TR 先做 9 日求和，结果约为常规 ATR 的 9 倍。
2. ROC 少了右括号。
3. DMI 的 `(HD 0) & (HD LD)` 丢了比较运算符；ADXR 末尾多一个引号。
4. DKX 序列跳过 REF(MID,19)，直接到 REF(MID,20)。
5. SWL/SWS 丢了乘号。
6. MARSI = MA(RSI,N) 复用 N；RSI6 用 MA，MARSI 内部的 RSI 却用 SMA，两处口径不一。
7. OSC = 100·(CLOSE−MA)，是价格差而不是比率；MABIAS 的 M 未定义。
8. OBOS 是全市场涨跌家数，属于市场宽度，不是个股字段。

**fields-volume-indicators.md**：
1. VR 的 `CLOSE LC` 丢了 `>`。
2. WMA 公式括号位置错误。
3. PCNT 分母用当日 CLOSE（非 REF）。
4. AMP 分母用 REF(CLOSE,N)。

**fields-valuation.md**：`ratio_ev_no_cash_ebit_*` 标签是"企业倍数"，但字段名是 EBIT，与 EBITDA 版同名，名实不符。

**operators.md**：
1. **`CONST(X)` 返回序列最后一个值组成的常数序列。** 若按全样本计算，这就是未来函数。pitfalls 只点名了 `FUTURE_RETURNS`，漏掉了 CONST（重要漏项）。
2. `ATR(X,N)`、`CCI(X,N)` 的示例只传 CLOSE，无法计算真实波幅，签名可疑。
3. `SHARPE(CLOSE,20)` 说是"收益率均值/标准差"，示例却传价格。
4. Python 示例 `SCALE(volume_ratio / volume_ma)`：用比率除以成交量均值，量纲混杂。
5. TS_ARGMAX/ARGMIN 的"位置索引"未说明方向；FORCAST 为原文拼写。
6. "MEAN 不是滚动均值"的批注是本技能所加，平台行为**未核实**。

**pitfalls.md**：总体质量高，覆盖以下各项：MEAN 误用、未来函数、截面与时序混用、方向参数、预热期、基本面阶梯与披露滞后、负分母、哨兵值、规模污染、换手成本折算、服务端上限、按年拆分。
- 缺陷：未列 CONST；第 6 条承认披露滞后，但没有给出处理方法（只提醒）。
- "IC>0.15 先怀疑未来函数"是经验阈值，可借鉴为 EA 的异常收益告警。

**playbook.md**：
- 优点：算力预算分配为 40/30/20/10；记录所有候选作为多重检验分母；决策只能三选一；证伪菜单（N±50% 悬崖、分年、规模剔除）；样本外区间先定后看。方法论可借鉴。
- 缺陷：
  - 第四阶段英文仍写"Because of the ten-year cap"，中文却改为"以当前服务端探测结果为准"，**双语不一致**；
  - "2026-08-05 扣 2 算力"属于**未核实**的运行声明；
  - "Trend position direction 0 or 1"方向未定。
- 组合部分承认权重网格是多重检验集中处，要求统计所有组合，做法得当。

**SKILL.md**：
1. **成本公式不一致（实质缺陷）**：
   - SKILL 写"annual cost ≈ turnover × round_trip_cost × 252/rebalance"，同时默认"0.3% one-way"，示例"60% 换手、5 日约 9 点/年"＝0.6×0.003×50.4，**只算了单边**；

2. **样本外口径前后紧张**：Core Workflow 第 7 步要求在预留区间做 OOS；Statistical hygiene 却说"不要强制预留 holdout"，可用最近五年直接选提交。Output Contract 只要求"说明是否经过 OOS"。最终可以选不做 OOS，选择偏差由用户承担。
3. **代理处理密码**："If the user hands you the credentials and your tooling permits it, run it for them"。它放宽了 source_boundary 的精神，按本项目规则不可采用。
4. CLI 版本漂移：文中混用 0.1.1、0.1.3、0.1.6 的行为描述；`factor_delete --pattern` 的已知 bug 为**未核实**声明。
5. "Duplicate names, look-ahead operators and MEAN(X,N) are rejected while parsing"：是否覆盖 CONST 未说明（结合 P0161 的 CONST 漏项）。
6. 竞赛细则（0811 指引、50 因子上限、月度快照、B 只能来自生效后记录）属于平台声明，**未核实**。B 不可用历史代理冒充，这一点写得正确。
7. 元数据 `validation_level: runnable`，本审核未运行（按边界不运行）。

## A155 结论
- 定位：PandaAI 因子大赛的 CLI 上手与在线挖掘流程，含平台推广属性。
- 可借鉴（方法论）：
  - 研究循环四步：归因、证伪、成本、三选一决策；
  - 保留全部候选作为多重检验分母；
  - 候选状态文件带指纹，修改即拒绝续跑；
  - 公开名不泄露研究思路；
  - IC 过高先疑未来函数；
  - 按年拆分，N±50% 悬崖检验。
  这些可映射到 EA 研究登记（run_id、配置指纹、试验总数）。
- 主要缺陷：
  - 成本公式相差一倍；
  - CONST 未来函数漏列；
  - 字段/公式目录导出损坏多处（TR 求和、DMI/VR 运算符丢失、DKX 跳项、标签错位、重复键）；
  - `_mrq_n` 时点语义不明；
  - OOS 可选导致选择偏差；
  - 允许代理代输密码；
  - 双语不一致。
- 对 V1.2 的适用性：A 股截面因子平台工具，**不能直接用于 FxPro GOLD 单品种 EA**。仅流程纪律可参考。未运行，未验证任何收益声明。
- 未定：batch.py 实际使用的成本口径，及是否拦截 CONST，需回查本资产 scripts 文件（若在既有包中已读，交叉核对时补记）。
