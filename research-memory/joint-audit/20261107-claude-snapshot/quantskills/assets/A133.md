# A133 skill-macro-altdata-nowcast（宏观另类高频数据行业景气 nowcast，社区 Draft，GPL-3.0）— 文本审核

## P0137 部分（FILE 1394 portable-loader、1395 README.en、1396 README、1397 references/altdata-playbook 全文）

要点：
- 必须先调 `get_macro_detail(category)` 把不透明代码解析为名称、单位、频率、stat_type、来源、覆盖区间，再拉 10 类 `get_macro_<x>`。
- 已经是同比口径的序列不再二次求同比；末端 1–2 期视为暂定值；"领先官方数据"只作观察。
- 景气打分约定：同比与环比同时上升记 +1、同时下降记 −1、其他记 0，再取均值，并要求声明这是自定口径、不是官方指数。

发现：
1. **没有可得日期（PIT）**：序列字段只有 symbol、period_date、data_value，没有发布日或修订版本（vintage）。数据期不等于可得日，末端还会修订；用于历史回测或"领先性"判断时会前视，文档只说"末端暂定"，没有说明不可做 PIT 回放。
2. **周频同比按 52 周对齐**，没有处理春节等农历节假日错位；电商、商超、招聘、地产等序列受春节影响很大，同比可能大幅失真。文档没有提到季节/节假日调整。
3. 景气打分是等权的符号投票，忽略幅度；"key indicators"由 importance 字段挑选，选择本身没有规则，结果对挑选很敏感。
4. "领先官方"并排观察没有给出滞后检验或显著性方法，文档也明确说"不声称因果"，结论只能定性。
5. 另类数据是单一平台样本，有覆盖偏差，文档每次都要求声明，做法良好。
6. README 嵌入社群二维码（外部图片），属推广内容。

与 EA 的关系：无直接关系（A 股宏观另类数据）。对本项目 NR07/NR08 外部数据的通用启示是"数据期 ≠ 可得时刻"，外部序列必须记录可得时间才能进入回测。**未实现**。

待续：P0138 读取 SKILL.md 与 scripts/validate_report.py（若在计划内）。

## P0138 补读（FILE 1398 SKILL.md 全文）
- 内容与 README / playbook 一致：先解字典，遵守 stat_type，声明另类数据是样本，领先性只作观察，结尾附固定免责声明。
- `status: draft` 却同时标注 `validation_level: runnable`；scripts/validate_report.py 只检查章节、标注与免责是否齐全（格式校验），**不校验数值和同比是否算对**，文档对此没有区分。
- 定时任务以"覆盖重写同名报告"实现幂等，会丢失历史报告版本，不利于事后核对"当时看到了什么"（与发现 1 的 vintage 问题叠加）。
