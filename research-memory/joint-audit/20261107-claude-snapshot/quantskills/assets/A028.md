# A028 skill-alpha-f5-member-position-concentration（全文审核笔记）
- 读取（P0031）：AGENTS.md、CLAUDE.md、HERMES.md、OPENCLAW.md、README(.md, .en.md)、SKILL.md（根目录）、开发版 SKILL.md 与 references/data_guide.md、production/SKILL.md。
- 内容：前 5 大净多和净空席位的保证金集中度。raw = bear_ratio − bull_ratio；对 raw 的水平值和一阶差分各做 60 日时序 z（min 20），等权相加得到 factor。
  - 信号：bull_ratio > 0.6 且 factor > 0 且 rank ≤ ceil(0.9n) → buy；bear_ratio > 0.6 且 factor < 0 且处于后 10% → sell。
  - 回测 Method A：close(t+1, c_t)/close(t, c_t) − 1，固定使用 t 日的主力合约，避免换月价差进入收益（这一点做得对）。
  - 另有可交易口径：data_lag = 1 日，换月成本 5 bps，交易成本 5 bps；成本敏感性分 0/0.05/0.15/0.30% 四档；1D–20D 的 IC 衰减和 Bootstrap IC 置信区间。
- **独立发现（逻辑层面，未运行）**：
  - ①**符号方向自相矛盾（严重）**：raw = bear − bull，所以多方集中时 raw 为负，z 值通常也为负。但 buy 要求"bull_ratio > 0.6 **且** factor_value > 0"——多方高度集中通常对应 factor < 0，两个条件方向相反。只有当多方集中度从更高水平回落时才可能同时满足。"factor_value 越大越好"与"正值代表空方更集中"放在一起，说明因子方向和"跟随主力"的假设相互冲突。sell 端同理。
  - ②**买卖不对称**：buy 用 rank ≤ ceil(n×0.9)，也就是前 90%，几乎不构成过滤；sell 用后 10%。文档却写"BUY_QUANTILE = SELL_QUANTILE = 0.1"，代码意图可能是前 10%，**疑似 bug 或笔误**（源码不在清单内，无法核实）。
  - ③研究口径 close(t)→close(t+1)：信号在 t 日收盘后才能知道（席位数据收盘后发布），研究口径按 t 日收盘价入场，在时点上不可执行；好在另有 data_lag = 1 的可交易口径并列报告——这一做法**值得肯定**，前提是以可交易口径为准。
  - ④MVP 版本不计成本、滑点和保证金占用。
  - ⑤生产文档的路径写的是 `claude_code_skills/...`，属于作者本地的环境残留。
