要点：
- 调用 `get_cumu_guarantee`，按以下三维把每只股票分为 high / medium / low：
  - 担保总额占净资产比率；
  - 超额担保；
  - 高负债率对象担保。
- 输出标准 BUILD 格式。

独立发现：
1. **文档之间分级规则矛盾**：
   - README（中、英）：比率 ≥ 阈值但没有其他标志时为 medium；
   - api_guide、生产 SKILL 及代码（89–94 行）：比率 ≥ 50 单独触发即为 high（硬编码 `NET_ASSET_RED_LINE_RATIO = 50`）。
   
   README 与实现不一致。
2. **阈值配置被硬编码红线覆盖**（静态推导）：
   - 若用户把 ratio_threshold 设为 70，比率在 50–70 之间仍会因 50% 红线判为 high，即 config 无法放宽；
   - 若设为 30，比率在 30–50 之间单独时为 medium。
   
   文档没有说明这一交互。
3. **缺失数据被静默判为 low**（静态推导，**未运行**）：
   - 74–76 行写 `row.get(...) or 0`，但 pandas 的 NaN 在 Python 布尔上下文中为真，`NaN or 0` 返回 NaN；
   - 随后 `NaN >= 50`、`NaN > 0` 均为 False，没有任何标志，结果为 `low/normal`；
   - 也就是说，字段缺失的公司被报告为"低风险"，而不是"数据缺失"；
   - 对风控类工具来说，这属于 fail-open 方向的缺陷。
4. **时点问题**：159 行 `trade_date = info_date or end_date`。info_date 缺失时退回到报告期末日期，会把公告前的日期标作数据日（前视）。info_date 为 NaN 时同样受第 3 点 `or` 语义的影响——NaN 为真，会被直接选中，日期为 NaN。
5. 代码注释写"《公司法》/上交所指引：50% 触发股东大会特别决议"。这条法规引用**未核实**（已列入 GAPS），引用的条文名称与具体要求需要核对原文。
6. 生产 SKILL 写了自动重试、"主数据源失败时使用前日数据"、每日备份、保留 1 年等运维承诺，但 build.py 中没有相应实现（grep 无），属于未实现的文档声明。
