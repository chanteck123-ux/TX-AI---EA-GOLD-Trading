## P0143 补读（FILE 1457 README、1458 references/leakage-control、1460 requirements、1461 SKILL.md 全文）

要点：
- purge 的近似实现：`train_end = start − H`；每个测试块之后再 embargo；只用 OOS 预测计算 Rank IC 和 ICIR，并与"逐日各因子 zscore 后等权"的基线比较。
- 标签口径：T+1 开盘到 T+1+H 开盘。
- 列出的常见陷阱：全样本标准化、全样本选因子或调参、复权/ST/停牌没有用 PIT 快照。

发现：
1. **purge 可能差一个 bar**：标签区间从 T+1 开盘到 T+1+H 开盘，信息区间延伸到决策日之后 H+1 个交易日；`train_end = start − H` 只丢弃 H 天，最后一个训练样本的标签终点可能落入测试块的第一天。应按完整信息区间（参见 A142 的 Information Interval）或 H+1 清除（静态推导，未读代码）。
2. **walk-forward 中 embargo 的作用**：训练始终在测试之前，测试块之后的 embargo 只影响"下一轮训练尾部是否包含刚测过的样本"，这对单向前推并不构成泄漏。A142 的术语把 Embargo（双向 CV 的测试后隔离）和 Pre-Test Gap（因果前推的测试前隔离）区分开，本资产混用了这两个概念，SKILL 描述中还出现了"Purged & Embargoed K-fold CV"，但正文只有 walk-forward。
3. **ICIR 年化偏高**：日度 IC 对应 H=5 的重叠前瞻收益，序列自相关很强，`mean/std·√252` 会高估 ICIR，需要 Newey-West 校正或不重叠采样。
4. 等权基线对各因子 zscore 后直接取平均，**没有按训练窗确定因子方向**；方向混杂的因子会互相抵消，基线被人为削弱，使"ML 提升"显得更大。
5. 超参数（ElasticNet 的 alpha 与 l1_ratio、train_window）由用户在 CLI 指定，文档要求"选择也要纳入 walk-forward"，却没有提供嵌套搜索。
6. **"真实数据测试结论（2026-07-27）"实际上没有真实数据结果**：只写了 smoke test 通过，就得出"代码可靠"的结论，标题有误导性。
7. requirements 把 lightgbm 列为依赖（注释写"可选"）；panda-data 钉为 0.0.9，与"不绑定 Pandadata"的说法并存。

**A141 结论**：文本全部覆盖（5 份全文 + FILE 1459 source_boundary 为 HASH_REUSE）。泄漏控制方向正确，但存在 purge 差一位、embargo 概念混用、ICIR 自相关高估、基线方向未对齐等问题。可作为 EA 研究中"重叠标签需完整清除"的提醒，**未实现**。
