# A147 skill-numerical-leak-check（数值型未来泄露检查：前缀重放 + 未来扰动）— 文本审核

## P0153 部分（FILE 1551 portable-loader、1552 examples/README、1553 README.en、1554 README、1555 references/adapter-contract、1556 checkpoint-design、1557 numerical-causality、1558 report-template、1559 result-interpretation 全文）

要点：
- 方法：对每个 case 计算完整输出，然后做两种测试——
  - ① **prefix replay**：只用截至 cut 的输入重算，比较 cut 及以前的输出；
  - ② **future mutation**：保持 cut 之前不变、替换 cut 之后的输入，比较历史输出。
  - 结果状态为 PASS / WARN / FAIL / ERROR，其中 ERROR ≠ 无泄露。
- adapter 协议：discover_cases、load_input、run_target、make_prefix、mutate_future、compare_outputs，可批量检查多个因子或 pipeline 节点。
- 切点设计：固定比例 + 固定位置 + 敏感点（period、window、warmup、换月、调仓日）邻域 ±10；严检模式下做连续扫描，并在 FAIL 附近二次局部扫描。
- 结论措辞："当前数值测试未发现……"，**禁止**写"证明没有未来函数"。
- 局限自述：切点没打中、扰动后被 sign/clip/rank 压平、容差掩盖、生产日历边界未覆盖、缓存或全局状态等情况都会漏检。

评价：
1. **方法正确且通用**：能覆盖 A130 的 `rank()` 全样本前视、A137 的全样本 HMM/StandardScaler、A140 的居中滚动等问题——这正是本轮审核中最常见的一类缺陷的**可执行检测手段**。
2. 示例用 `np.convolve` 构造一个泄露因子和一个不泄露因子做盲测，返回码 1 表示发现泄露，设计合理（examples 中的代码不在计划内，**未读**）。
3. 不足：
   - 默认切点中固定位置偏向日频（如 252）；对分钟级或 tick 数据，应以 session 和 bar 边界为敏感点。
   - "未来扰动要足够强"只是建议，没有给出扰动的分布（例如替换为独立随机游走，或打乱顺序）；扰动太弱可能漏检。

与黄金 EA 的关系（**直接相关**）：
- 用户 Scalping SOP 的"最近有效供需区"以及摆点、zigzag 类指标常有**重绘或前视**风险。本资产的前缀重放与未来扰动方法可以移植为 MT5/LEAN 中的指标因果性检查：在截断历史上重算指标，与全历史结果对比已收盘 bar 的值。
- 只作方法参考，**未实现**，也不改变 SOP；任何实际接入都要按项目流程编译、测试并留证。
