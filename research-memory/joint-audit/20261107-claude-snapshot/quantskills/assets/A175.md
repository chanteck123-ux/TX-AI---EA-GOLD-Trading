## P0214 前段（FULL_READ；FILES 1776–1779：README.en、README、acceptance_checklist、SKILL）
- 定位：因子工厂。`generate_factor_skill_batch.py` 按 `--count 200` 这样的批量参数生成因子 Skill 文件夹，并在缓存的真实面板（AkShare A 股 98 只、Yahoo 美股 50 只）上计算覆盖率、5 日 RankIC、ICIR、Q5−Q1、换手和无前视检查。中英文 README 一致。
- **关键发现（解释了 A173/A174 的"全部通过"）**：
  1. 因子是**工业化批量生成**的（示例从 all_1000_index 扩到 all_1200_index），已发布的三个库（296 + 288 + volume-stat）只是生成总量中的一部分。如果是从 1000 多个生成的因子中挑出来发布的，**挑选过程本身就会产生幸存者偏差和多重检验偏差**，而文档没有说明挑选标准。
  2. 验收清单要求"每行 `status: pass`，除非有意接受 review 行"。"pass"由生成脚本自己判定，所以"296/296 pass"只表示**通过了自家脚本的门槛**，门槛内容没有在文档中公开。
  3. 去重只按 `slug` 判断，不按因子值的相关性判断，所以"5 日 z-score 动量"与"10 日 z-score 动量"这类高度相关的变体会被当作不同因子计数。
- 优点：明确要求"不得把合成验证说成真实验证"；没有 raw/yahoo_us 文件和面板清单证据时，不得声称有 Yahoo 数据；发布包中不得包含行情缓存、代理设置、个人路径和凭证；抽查首、中、尾三个因子运行 validate.py。

## A175 结论
- 这是一个工程上完整的因子批量生产工具，但它的存在让下游"已验证因子库"的统计意义大打折扣：批量生成、自家门槛、只按名称去重、挑选标准未公开，构成典型的因子挖掘过拟合链条。对 V1.2 的教训是：任何批量生成的指标或候选都必须登记全部试验次数，并做多重检验校正和独立样本外验证（与本项目 §11.9 的规则一致）。generate 脚本未审。
