# A191 skill-signal-portfolio-optimize — Claude 全文审核（2026-11-05）

## P0225 后段（FULL_READ；FILES 1921–1925：portable-loader、docs/default-presets、docs/impact-cost-model、docs/lexicographic-socp-mode、README.en）
- 定位：把一个冻结的截面信号转成相对基准的 long-only 目标权重。风险模型为开放的 Barra 式结构（5 个风格因子加 31 个行业），月频刷新；求解器为 CVXPY + Clarabel，采用两阶段词典序 SOCP（先最大化信号效用，再在保留 99.5% 效用的约束下最小化换手和 L2 正则）；执行层另有 stockdemo 兼容引擎（次日 TWAP、1.4‰ 成本、100 股一手、ST 和涨跌停过滤、停牌 carry-forward）。
- **优点（诚实程度少见）**：
  - 明确写出"信号是样本外的，但**优化器的约束参数是在同一窗口内选的（参数层面属样本内）**，跨时间段的稳定性须另行验证"；
  - 写明"同一期间的单参数扫描不能跨期迁移"，2024 年的 maximin 冠军到 2025–2026 就落后；
  - 承认"参数不通用，四个信号各有各的冠军，没有免费的午餐"；
  - 冲击成本评审材料坦白事后核算的结果：按 √ADV 冲击模型，η=0.5 时**年化冲击成本 3.3–5.2%，与线性成本同量级甚至更大**，而优化器目标函数**没有纳入**；
  - README 说明验证区间"被反复检查过，只能算开发证据，不是封存的 holdout"。
- **问题**：
  1. **"15 个相互独立的评价"并不独立（关键）**：lexicographic 文档据此给出 TE 6% 的 Sharpe 改善 t=+4.25、p=0.0005；而 impact-cost 文档自己写着"现有 4–5 个模型彼此**排名相关 0.84–0.91**"。这 15 个评价来自高度相关的信号族，有效独立样本远少于 15，t 值和 p 值被明显高估。
  2. **hedged 超额 Sharpe 高得不可信（4.55）**：官方 hedged 口径是"(1 + 组合日收益 − 指数日收益).cumprod()"，即**每日无成本地对冲指数**，没有计入股指期货的基差、贴水、保证金和展期成本（A 股的 IF/IC 长期贴水，对冲成本很高），加上参数是在样本内挑的，Sharpe 2.4–4.6 很可能被高估。
  3. **默认配置的版本说法不一致**：README 写实现版本 1.7.0，建议从 `v1.7-signal-preserving-config` 开始；default-presets 推荐 `default_lexicographic_v1_8.yaml`；lexicographic 文档写"v2 锁定默认 = default_te06_turn12_mw040_ind2.yaml"，并写"v1 = te08_turn20"。可是它的"新信号接入流程"第 2 步又让人复制 `te08_turn20` 配置（也就是 v1）。**三份文档指向三个不同的默认配置**。
  4. stockdemo 的默认缺失持仓策略是 carry_forward（按最后有效收盘价估值，且不可交易），文档说是为了"与旧版兼容"。对于已退市的证券，这样会高估净值；严格检查需要显式切换为 error 或 terminal_writeoff。
  5. 每日调仓对 3/4 快信号更好，但成本使每周调仓胜出，说明结论对成本假设高度敏感，而冲击成本又没有进入优化器。
- 中文 README、references 和 SKILL 在 P0226 中，待读。

## P0226（FULL_READ；FILES 1926–1932：README（中文，逐项核对版本和数值，与英文版一致）、backtest-contract、exposure-report、full-universe-enhancement、input-schema 10.5 KB、optimization 10.2 KB、output-contract 8.7 KB）
- 优点（工程纪律好）：
  - **目标在 t 日形成后，只作用于下一交易日的收益**，绝不作用于信号日当天的收益；
  - 优化诊断和回测会计使用同一个 linear_cost_bps，CLI 覆盖时两边同时改，并记入 manifest；
  - 基准由给定的调仓权重模拟，并明确写明"不是官方指数收益"；
  - 持仓缺少收益数据时直接失败，**绝不静默填补**；终止证券只能另行生成派生收益文件，记录每个受影响的代码和日期以及两份文件的哈希，标明是假设而非观测值，保守取 −1（全部减记）；
  - 行业标签按区间数据转成每日标签，端点含边界，重叠区间直接拒绝，默认 `missing-policy error`；
  - PIT 基本面按 `available_date` 物化；
  - Clarabel 的 `optimal_inaccurate` 结果只有在独立复核所有硬约束后才接受；
  - 求解失败时不会悄悄退回等权，等权组合只作为比较对象；
  - feasibility repair 需要显式开启，放宽后的结果与严格可行的结果可以区分。
- 问题：
  1. **方法模式太多**：schema 1 到 10 有多种目标（mean_variance、score_max_te、lexicographic、anchor blend、signal-preserving），每种的约束规则不同（例如 schema 6 拒绝 TE 和换手硬约束）。复现某个结果必须准确记录 schema，配置错用的风险高。
  2. native 回测是收盘到收盘的简单收益，不模拟订单、部分成交和非线性冲击（v1.0 明确不做）；stockdemo 引擎才有 TWAP 和一手 100 股。两种引擎的结果不能直接比较。
  3. optimization 文档说明，换手惩罚 0.00035 对应 7bps 单边成本（L1 范数是单边的 2 倍），但冲击成本仍然没有进入目标函数（见上一段）。

## A191 结论
- 工程上是本批中最成熟的组合优化实现之一：因子形式的 SOCP、硬约束独立复核、fail-closed、证据哈希、PIT 行业和基本面数据。
- 但研究结论有三个缺陷：
  1. "15 个独立评价"实际高度相关；
  2. hedged 超额 Sharpe 没有计入对冲成本，并且参数是在样本内挑的；
  3. 三份文档的默认配置互相矛盾。
- 它自己也承认参数选择是样本内的、跨期不迁移。对 V1.2 可借鉴的是："同一期间的单参数扫描不能跨期迁移，采纳参数改动前，要求多个独立评价同向"，以及"放宽后的结果必须可识别"。SKILL 和脚本将在 P0227 中审读（SKILL）或保持未审（脚本）。

## P0227 前段（FULL_READ；FILES 1933–1938：risk-model 8.3 KB、source-boundary、stockdemo-compat、validation-notes、requirements、SKILL 24.4 KB）
- risk-model：
  - t 日的收益只用前一个对齐交易日的市值和行业数据；
  - 基本面风格（EARNYILD、GROWTH、BTOP、LEVERAGE、LIQUIDTY）只用 `available_date` 不晚于暴露日期的观测；
  - **明确禁止用当前行业快照回填历史**；
  - 特异风险对历史不足的资产用行业中位数插补；
  - 周频和月频刷新模式下，基准成分或持仓缺少覆盖时 fail-closed，绝不静默退回按日构建；
  - 缓存按指纹区分，不完整或过期的缓存 fail-closed。
  - 这几条 PIT 纪律好于 A184（A184 的特异风险没有收缩，本资产有中位数收缩）。
- validation-notes：v1.0 相对 Top200 等权基线，Sharpe 只提高 0.12（1.09 → 1.21），绝对最大回撤 −25.8%；并明确说明"**该区间在 v0.8–v1.0 开发中被反复检查，所有指标都是开发证据，不是封存的样本外结果**"；由于没有经过验证的 PIT 行业历史，行业约束被关闭，"**不用当前行业标签伪造历史**"。
- **新发现**：
  1. **版本号在各文档中不一致**：validation-notes 写当前实现为 1.5.0，README 写 1.7.0，default-presets 和 SKILL 指向 v1.8 分支。
  2. **SKILL 自身前后矛盾**：description 说核心是"保守的等权锚点混合"（schema 6），模式表却把 lexicographic SOCP（schema 5）列为"已验证、通用默认已锁定"；推荐的 preset 文件名又与 lexicographic 文档的"v2 锁定默认"不同。
  3. stockdemo-compat 中出现了**开发者本机 home 目录的绝对路径**（含个人用户名，本记录不转录），属于个人信息泄露。
  4. 好的做法：`prepare_existing_experiment_inputs.py` 使用等权基准时，必须记录 `benchmark_is_market_index: false`，并明确"不要说成指数相对优化"；SKILL 还要求"不要反复查看 OOS 收益来调参"。
