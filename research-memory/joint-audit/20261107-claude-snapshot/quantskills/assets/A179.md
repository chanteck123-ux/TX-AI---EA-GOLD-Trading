# A179 skill-quant-strategy-diagnostics — Claude 全文审核（2026-11-05）

## P0216 中段（FULL_READ；FILES 1812–1816：portable-loader、README.en、README、methodology、SKILL）
- 定位：离线诊断策略是否在变差。比较最近 window 期与紧挨着的前 window 期的累计收益、波动、Sharpe（Rf=0）、胜率、最大回撤、IC、换手和超额收益；出现 1 个信号标为 watch，2 个或以上标为 warning。中英文 README 一致。
- **问题**：
  1. **窗口长度示例矛盾，而且太短**：README 快速开始用 `--window 5`，SKILL 工作流用 `--window 60`。用 5 个日收益计算 Sharpe、最大回撤或 IC 均值，统计上没有意义，只需 10 个数据点就能触发"warning"。
  2. **没有任何显著性检验或置信区间**：阈值（Sharpe 下降 ≥0.5、回撤恶化 ≥5 个百分点、IC 下降 ≥0.02、换手升高 ≥50%）都是固定的启发式门槛，没有考虑窗口长度。60 日 Sharpe 的标准误约为 √(252/60)≈2.05（年化），下降 0.5 完全落在噪声范围内。
  3. 只比较"最近一窗"和"前一窗"两个窗口，没有用更长的历史分布或样本外基准来判断"是否超出历史范围"，而 README 却说能检查"连续回撤是否超过历史范围"。
  4. SKILL 说"真实示例见 examples/data/strategy_daily.csv"，该数据是否真实无法核实（csv 不在本清单内）。
- 优点：数据不足时标为 insufficient_data，不推断衰减；信号不等于原因，需要列出数据断档、成本、执行和状态切换等替代解释；没有成交数据时，不把执行损耗归因于策略；没有 regime 标签时，不声称做了状态分析。

## A179 结论
- 诊断框架的边界划得清楚，但统计方法太弱（两窗口加固定阈值，没有检验），短窗口下误报率很高。对 V1.2 的监控反馈（§13.11）而言，策略健康度判断必须用与样本长度匹配的置信区间或序贯检验，**不能直接套用这套阈值**。scripts 未审。
