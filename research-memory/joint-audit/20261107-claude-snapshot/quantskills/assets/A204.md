# A204 skill-strategy-tearsheet-report — Claude 全文审核（2026-11-05）

## P0243 中段（FULL_READ；FILES 2038–2043：portable-loader、README.en、README、references/metrics-glossary、requirements、SKILL）
- 定位：输入一条净值或收益序列，输出 tearsheet（年化收益和波动、Sharpe、Sortino、Calmar、Omega、Top-N 回撤、滚动指标、月度和年度收益、分布与尾部统计、相对基准指标），格式为 JSON 加自包含 HTML。
- **公式正确**：年化收益用 `(∏(1+r))^(ppy/n) − 1`，期数和年化期数口径一致，避免了 A203 的混用问题；下行偏差用标准的 `sqrt(mean(min(excess,0)^2))`；README 专门提醒 ppy 必须与序列频率一致，月频序列误按 252 年化会使 Sharpe 放大约 √21 ≈ 4.6 倍。
- **问题**：
  1. **基准数据可能静默回退到样本**：没有安装 SDK 时，`--benchmark` 和 `--fund` 会"自动回退"到随包附带的 `examples/sample_data`。质量门槛虽然要求降级时必须声明，但文档没有说明报告是否会标注"基准来自样本"（PLAUSIBLE）。这与 A167 的静默合成回退属同一类风险，相对基准的结论可能是用样本数据算出来的。
  2. **"缺失日期按频率补齐"**：如果补齐的日期按零收益处理，会压低波动、抬高 Sharpe，文档没有说明补齐方法。同一处还写"NAV 先转对数或算术收益"，两者可以任选，但这两种口径算出的指标并不相同。
  3. 基金净值用 `get_fund_daily` 的**收盘价**构造代理，没有考虑分红再投资，会低估收益。场内价格与净值之间的折溢价也被混进结果。
  4. 夏普给出固定解读"大于 1 尚可，大于 2 优秀"，与 V1.2 §11"夏普仅作辅助诊断"不一致；Omega 没有定义阈值。
  5. **与同组织 A203 口径冲突**：无风险利率默认 0.02（A203 为 0）；热力图"绿涨红跌"（A203 为红涨蓝跌）；胜率和盈亏比按期计算（A203 按笔计算）。同一条序列在两个技能中会得到不同的 Sharpe 和胜率。
  6. requirements 只给出下限版本（numpy>=1.21、pandas>=1.5）。
- 优点：Top-N 回撤表包含持续期和恢复时间，未恢复时标为 None；基准与策略先对齐日期再计算；HTML 不依赖任何 CDN。

## A204 结论
- 指标公式是本批中较规范的一份，可作为 V1.2 绩效口径（年化、Sortino、恢复时长）的参照。需要警惕样本回退和缺日补齐带来的偏差。脚本未审。

## 源码批次 S007（2026-11-06，FULL_READ：scripts 下 data_source、metrics、render、tearsheet，examples/run_demo.py，tests/test_regressions.py；样本 nav.csv 与 get_index_daily.json 只看了结构与首行，记为 PARTIAL；未运行）
- **更正文档层结论**：文档层曾写"下行偏差用标准的 `sqrt(mean(min(excess,0)^2))`"，这句只对 glossary 成立。**代码实际是** `downside = excess[excess < 0]; dd = sqrt((downside**2).mean())`，均值只在负收益期上取，分母是负收益期数而不是全部期数 N。下行偏差因此偏大，Sortino 偏低，**代码与 glossary 不一致**。口径与 A203 不同（A203 用负收益的 std），但同样不标准。没有负收益期时返回 None。
- **样本回退是否标注（PLAUSIBLE → 部分成立）**：
  - 自动模式下没有 SDK、但有 `examples/sample_data` 时，`backend="sample"`。此时 `--benchmark 000300.SH` 读取的是 run_demo 用策略收益合成的指数（`0.55×策略收益 + 噪声`），不是真实的沪深 300。
  - 有标注：JSON 的 `backend` 字段和 HTML 顶部的"数据后端 sample"。
  - 没有标注：`status` 仍为 `"ok"`，`degraded` 为空；控制台摘要不显示 backend；`sources.benchmark` 仍写 `get_index_daily`。所以样本回退**不算降级**，读者只看 status 或摘要会误以为基准是真实数据。另外这条合成基准与策略高度相关，Beta 约 0.55、相关性偏高都是构造出来的。
  - `--fund` 在样本模式下因为没有 `get_fund_daily.json` 会返回空，然后以退出码 2 结束，不会伪造数据。
  - `--prefer sdk` 但 SDK 缺失时，异常被捕获并写入 diagnostics，status 变为 degraded，这条路径的处理是正确的。
- **缺失日期补齐（PLAUSIBLE → 实际不补齐）**：代码没有任何按频率补齐的步骤。`nav_to_returns` 先 `dropna()` 再 `pct_change()`，缺失日被直接删除，跨越缺口的多期收益被当作一期计入。期数 n 偏少，年化收益和波动都会失真。`infer_periods_per_year` 只有定义，没有被调用，CLI 固定使用 `--ppy`（默认 252），不检查与序列频率是否一致。文档说的"按频率补齐"并未实现。
- **新发现**：
  1. **回撤峰值日期取错（CONFIRMED，逻辑推演）**：`_peak_date_before` 取 `at_peak.index[-2]`。`prefix` 包含刚进入回撤的那一天，这一天低于 running max，不在 `at_peak` 中，所以真正的峰值是 `at_peak.index[-1]`。代码取的是**上一个创新高日**，导致 `peak_date` 偏早、`drawdown_days` 偏大；最深回撤的"峰值日"在摘要和 HTML 表中都会显示错误。只有序列开头就进入回撤时恰好返回 `prefix.index[0]`。调用处还有一行无效写法 `... if False else _peak_date_before(...)`。没有测试覆盖这一点。
  2. **pandas 版本下限与代码不符**：`resample("ME")` 和 `resample("YE")` 的频率别名要到 pandas 2.2 才支持，requirements 却写 `pandas>=1.5`。在 1.5 到 2.1 的版本上，月度矩阵和年度收益会报"无效频率"（按 pandas 版本变更推断，未运行验证）。
  3. 胜率 `(returns > 0).mean()` 的分母包含零收益期，与 A203"排除零盈亏"的口径相反；两者都没有单独列出零值。
  4. 基准用指数收盘价（价格指数）计算收益，未含分红，超额收益会偏高。基金代理净值用场内收盘价，与文档层第 3 条一致（CONFIRMED）。
  5. `_read_series_csv` 找不到 nav、return 或 ret 列时，静默把第一个数值列当作净值使用。
  6. run_demo 用 `nav.iloc[0] = 1.0` 覆盖首日，丢弃了第一笔合成收益。演示的 backend 标为 `sample(demo合成)`，标注清楚。
  7. 测试只有 4 条，内容为年份分块、基金去重、基准内连接和 CLI 必填参数；Sharpe、Sortino、回撤日期、月度矩阵这些**指标计算全部没有测试**。
- **做得好的地方**：HTML 全部经过 `html.escape`，不依赖 CDN；按年分块取数并去重；基准先内连接再计算；SDK 单个接口失败时进入 diagnostics。
- **结论更新**：撤回文档层"公式较规范、可作 V1.2 参照"的判断。年化公式本身正确，但 Sortino 分母、回撤峰值日期、缺口合并和样本基准标注四处有实质性问题。作为参照只能取它的报告结构，计算代码不可直接采用。
