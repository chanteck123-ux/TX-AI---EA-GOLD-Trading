# A193 某投资人命名的 pairs-trading 技能 — Claude 全文审核（2026-11-05）

## P0228 后段（FULL_READ；FILES 1949–1953：CHANGELOG、examples/01_daily_signal、README、references/methodology、requirements）
- 定位：在 A 股沪深 300 和中证 500 的同行业股票中找协整配对，再做滚动样本外回测，最后由门控决定是否出信号。README 声明与同名投资人及其机构无关（人名在本笔记中不转录）。
- **纪律在本批中属上乘**：
  - 用前复权或后复权价格，未复权价格不进入协整检验；
  - 选对只用形成期（252 日），评估期不参与；
  - 用 BH-FDR 做多重检验校正，同时保留原始 p 值；
  - 半衰期限定在 2–60 日；
  - 用 PCA 和层次聚类去掉共线配对，每只股票最多进入 1 对；
  - 两腿分开记账，换手成本和融券费单独扣；
  - 每日按市值计价（v0.2 修正了此前在平仓日一次性记损益、导致夏普虚高的问题）；
  - CHANGELOG v1.0 删除了"回测后用全样本选对"的 pca_reduce 脚本；
  - 任何 NO_TRADE 状态都隐藏方向；
  - run_id 绑定三种数据指纹，并明确说明它不是数字签名；
  - 只接受 HTTPS，拒绝重定向，令牌只放在进程内存，不写入 SDK 的 user.json。这一点修复了 A158 中凭证落盘的问题。
- **仍有的问题**：
  1. 行业分类取查询当时的结果（无历史时点数据），这一点已披露。股票池只用"数据起点附近"的指数成分，此后滚动重估时不再补入新成分，造成选样口径偏差，且评估期越长偏差越大。
  2. 门控"≥100 笔且夏普 ≥ 0.5"中，交易并不独立：同一配对反复进出、不同配对同行业共振。门控也没有对候选数和参数试验次数做 deflated-Sharpe 之类的校正；FDR 只覆盖配对筛选这一步。
  3. 融券年费 800bp 只是假设，A 股个股实际经常无券可借（已披露）。因此回测中的空腿在可执行性上不成立，"RESEARCH_PASS"的含义有限。
  4. 每 60 日重估时，"关系失效"之后该配对如何处理、是否允许新配对补入，文档没有写清楚。
  5. 示例中的 `SIMONS_TODAY` 环境变量用来固定日期。如果生产中误设，会让信号日期与实际日期不符；文档没有提示。
- 个人信息：README 末尾写有初始维护者的 handle，未转录。

## P0229–P0231（FILE 1954 requirements-lock.txt 分 3 部分：DATA_AUDITED；FILES 1955–1957 SECURITY、SKILL、THIRD_PARTY：FULL_READ）
- 锁定文件做的是数据审计，没有逐行阅读哈希：共 38 个包，全部 `==` 钉定版本，带 1,208 个 `--hash=sha256`；没有 index-url、http 或 git+ 来源。所列版本与 requirements.txt 一致，包含 panda-data==0.0.12、python-dotenv 和 websockets。
- SECURITY 和 THIRD_PARTY 明确写出：panda_data 的许可证、维护主体和源码来源未公开；SDK 默认地址是 HTTP，本项目永久拒绝。这是本批中供应链边界写得最清楚的一例。
- SKILL.md 与 README、methodology 一致：只读 `~/.pandadata.env`，不读项目目录里的 .env；同日、同配置重跑会覆盖同一个目录，文档要求先归档。

## A193 结论
- 研究纪律在本批中处于前列，可作为 V1.2 的参照模板：只在形成期选样、做多重检验校正、标注复权口径、用数据指纹绑定 run_id、门控未通过时隐藏方向、凭证只放进程内存。
- 不足：门控中的交易数并不代表独立样本，FDR 之外没有校正试验次数，空腿在可执行性上不成立，股票池和行业分类都不是历史时点数据。脚本未审。
