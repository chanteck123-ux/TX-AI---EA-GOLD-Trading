# A045 skill-buyback-monitor（全文审核笔记）
- 读取（P0047）：agents/portable-loader.md、README(.en.md, .md)、references/buyback-playbook.md、SKILL.md。
- 内容：A 股回购事件监控：`get_repurchase` 每个事件按进程返回多行（预案 → 决案 → 实施 → 完成/届满/注销），**先去重到事件，再取最新进程**；按 write_off_date 或目的文本把回购分为注销式、激励/员工持股、市值管理，不明确的记"未分类"，**不猜**；强度主看 buy_back_percent（占总股本比例）；价格区间与现价比较。
- 好的做法：
  - **"预案 ≠ 已执行"**：任何金额都必须标注是预案范围（value_floor/ceiling）还是已执行（buy_back_value）；预案阶段 buy_back_percent 为空时标"待披露"，不填补。
  - "注销"只有在有 write_off_date 或明确的注销目的时才认定；一波预案只是意图，不是实际回报。
  - 扫描是时点快照；定时任务幂等；status: draft。
- **独立发现**：没有计划 ID 时，去重规则是"symbol + 回购期限有重叠 + 目的"——这是启发式规则：同一公司在期限重叠期内的两个不同计划可能被合并，同一计划修改期限后又可能被拆开。文档没有要求报告去重的不确定性（例如合并了多少行、按什么键合并）。
- 对黄金 EA：**"预案 ≠ 已执行"与本项目"保存计划不等于已实现、提交订单不等于已成交"是同一原则**（CTrade 返回成功 ≠ 成交）；"按事件去重后取最新状态"对应 RiskExecution 的订单状态机和对账（同一订单多次回报，必须按订单 ID 去重并取最新状态）。
