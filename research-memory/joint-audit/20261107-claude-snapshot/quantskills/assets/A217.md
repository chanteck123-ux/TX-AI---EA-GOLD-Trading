# A217 skill-x-trader-builder — Claude 全文审核（2026-11-05）

## P0251 中段（FULL_READ：FILES 2151–2157，包括 README.en、README、references 下的 data_collection_stable_zh、data_contract、review_rules、skill_output_contract，以及 SKILL）
- 定位：Skill 工厂。把**任意 X/Twitter 公开交易员**的发帖历史加工成该交易员专属的"研究模型 Skill"，流程分九步：初始化、采集、提取、自动复核（7 级标签）、拆分、前向收益评估、模板提炼、报告、生成 Skill。中英文 README 一致。
- **隐私与合规（严重）**：
  1. 这套工具的用途就是**对具体的真实个人做画像**，反推其投资逻辑，再生成"按此人风格分析"的 Skill。README 列出两个已生成的实例，以真实账户或机构命名（本笔记不转录名称）。采集指南中的示例直接使用一个真实的 X handle 和 Substack 地址（不转录）。这与 A189 属于同类问题，只是这里做成了批量、可复用的工厂。
  2. 兜底采集方式是用 `--remote-debugging-port=9222` 打开本地**已登录的浏览器**，再通过 CDP 滚动抓取。这样做借用用户的登录会话，很可能违反平台服务条款；同时开放的调试端口会让同一台机器上的其他进程也能控制浏览器。Claude 不会执行这类操作。
  3. RSS 采集提供 `--allow-insecure` 选项以关闭 TLS 校验。X API token 和 Apify token 可以用命令行参数传入，会留在命令历史里。
- **方法问题**：
  1. **前向收益评估缺少关键约束**：文档没有规定入场价用发帖时刻之后的哪一个价格，也没有说明盘后或周末发帖如何处理，是否扣除基准、是否计入成本也没有写（PLAUSIBLE，与 A189 的问题相同）。
  2. **幸存者偏差**：只能采集到现存的帖子，被作者删掉的错误判断无法收录。"复核质量达标后再生成 Skill"又会让人反复调整规则，直到评估结果好看为止，循环 4 到 9 步之间没有任何试验登记。
  3. 7 级标签靠关键词规则判断，例如出现"10x、called it"就判为回顾帖。容易误判，文档没有给出准确率或人工抽检比例。
- 优点：
  - 帖子不等于经过审计的业绩；
  - 本人观点与引用内容分开；
  - 回顾性的战绩声明不进入前瞻信号；
  - CDP 采集默认视为不完整采集；
  - 生成的 Skill 不打包原始数据。
- 元数据写 `maintainer_type: official`。示例中的人名和账号一律未转录。

## A217 结论
- 对 V1.2 没有用处，而且属于隐私高风险工具：对真实个人画像，并借用登录会话抓取数据。在 GAPS_CN 中登记为"不可采用、不可运行"。脚本未审。
