  2. **滑点默认为 0**：`tick_slippage_amount` 在缺少 ticks 或 tick_size、或者计算出错时返回 0。
  3. **涨跌停检查在没有报价时放行**：`check_limit_lock` 在没有报价（`no_quote`）时不阻断，照常成交。

  5. **保证金率的单位靠猜**：`normalize_margin_rate` 把大于 1 的值一律当作百分数除以 100。例如传入 1.5，本意是 150% 时会被当成 1.5%，本意是 1.5% 时又恰好正确，取决于上游如何表示，**单位没有显式约定**。

## 源码批次 S016（2026-11-07，trader_futures_execution.py 成交与持仓入账，未运行）
- **PARTIAL**：`src/tools/agent_tools/execution/trader_futures_execution.py`，SHA-256 前 16 位 e812ca3485bd26c2。去掉空行和 # 注释行后共 1,558 行，本次读了第 557–1156 行。这一段包括 `_build_transaction`、强平价格与估值、合约码解析、防止混用合约、`apply_transaction_to_portfolio`、滑点、手续费、平今判定和保证金释放。
- **发现（CONFIRMED，读代码得出）**：
  1. **成交价 = 基础价 ± 固定的滑点跳数 × 最小变动价位**，买方向加、卖方向减。缺少 minimum_tick 时滑点为 0。**全部按全量成交**，不考虑盘口深度。
  2. **⚠ 强平定价的回退值名不副实，可能用到未来价格**：`_resolve_forced_risk_price` 在取不到分钟线时，从**当日**报价里依次取 close_price、settle_price、open_price、pre_close……，却把来源标成 `T_MINUS_1_CLOSE_FALLBACK`（意思是"前一日收盘价回退"）。盘中运行或者带 cutoff 回测时，当日收盘价还不应该可见，这里有**前视风险**，而且标签误导审计。
  3. **⚠ 平今判定会被持仓均价合并带偏**：`_is_intraday_close` 用持仓的 `entry_date` 判断是否平今仓。但加仓时（prior_shares > 0），`entry_date` **不会更新**，所以"昨日持仓、今日加仓、今日又平掉"这部分会被当成平昨仓。SC 这类平今费是平昨费 6 倍的品种（catalog 中 40 对 240），手续费会被**少算**。
  4. **⚠ 盘中权益不含浮动盈亏**：每次成交后 `unrealized_pnl` 都被置为 0，`account_equity = cashflow + margin_used`。所以盘中风控（S014 第 4 条）用的权益**不含浮亏**，持仓亏损扩大时，保证金比例和风险等级不会随之变化，要等结算之后才更新。S014 中原来的 PLAUSIBLE 由此升级为 **CONFIRMED**。
  5. 平仓时 entry_price 为 None 的话，已实现盈亏直接记 0，不报错。
  6. **合约码兜底**：建议里没有合约码、又不是平仓时，取当日主力合约；连主力也取不到时，**直接用品种代码**（如 "RB"）作为合约码。
  7. 正面做法：
     - 平仓手数超过可平手数时直接报错；
     - 防止混用合约：已有合约 A 时开仓合约 B 会报错，并要求先换月（换月单和强平单不受限制）；
     - 保证金按平仓比例释放；
     - 强平减仓的手数按"需要释放的保证金 ÷ 每手保证金"向上取整计算。
  8. `_build_transaction` 中的账户级保证金上限检查，只在"策略单 + 开仓 + 要求全市场资金排名"时才执行。其他情况依赖 trader 层的检查（见 S014）。
- **对 V1.2 的反例用例**：
  - 回退价格必须如实标注来源，并且不能晚于 cutoff；
  - 平今和平昨要按每笔开仓逐一归属，不能用持仓均价合并后的日期判断；
  - 风控用的权益必须包含浮动盈亏。

- **新发现（CONFIRMED）**：
  1. **⚠ 先写库、后更新持仓，不是原子操作**：`execute_recommendation` 对每笔交易先调用 `db.save_futures_transaction`，**然后**才调用 `apply_transaction_to_portfolio`。如果更新持仓时抛错（例如平仓手数不足），交易记录已经保存，持仓却没有更新。换月是两条腿依次"保存、应用"，平旧仓保存后、开新仓那一腿如果失败，就会留下**只平不开的半次换月**。两条腿的 `_build_transaction` 都是用换月**之前**的持仓构建的。
  2. **强平扫描与 trader 层的权益口径不一致**：`scan_and_create_intraday_forced_risk_orders` 计算权益时**包含**浮动盈亏（cashflow + 保证金 + 浮盈），trader 层的风险等级则不包含（见 S016 第 4 条）。同一账户在两个风控点上用的是两套权益。强平默认开启：保证金占比 ≥ 85% 触发，减到 70% 为止，先减保证金占用最大的持仓。同一品种、合约、方向已有待执行的强平单时不重复生成。
  3. **对 S015 中"缺数据放行"的补充**：执行引擎对涨跌停检查默认 `enabled=True`。没有报价时虽然不阻断，但会在交易上记一条 `limit_price_unavailable` 警告；交割月无法解析、动态保证金回退为静态值时也会记警告。所以**"放行但留痕"属实**，S015 第 3、4 条据此修正为"不阻断但有警告"。动态保证金默认关闭；开启后如果不允许回退到静态值，就会报错阻断。
  4. 市场规则被阻断时（ExecutionBlocked），建议状态记为 SKIPPED，并写入原因，也写入学习记录（以"不使用未来数据"为前提）。
