## 二、重点四项的独立判断

### [76] skill-factor-decay（commit e049c2b）

1. **绝对值异号**：`SKILL.md:160` 写"若 `|IC(1d)|` 和 `|IC(20d)|` 的符号相反"。绝对值不可能为负，这句话在数学上不成立。**同意 Codex。** 原意应是有符号的 IC(1d) 与 IC(20d) 异号，且各自显著；`|IC|>0.005` 是幅度门槛，不是显著性检验。我原笔记把"方向反转应降级为非参数报告"记为方法，但没有指出这句表述错误，属遗漏。
2. **block bootstrap 的事实归属**：
   - `SKILL.md:113、123、220` 只要求"Bootstrap 置信区间"，没有要求 block。
   - `references/bootstrap.md:24–27` 的参考示例用 `np.random.choice` 逐日独立抽样；第 70 行才建议有自相关时改用 block。第 25 行注释写"保持日间相关性"，实际只保留同一抽样日的跨期限对应，不保留时间上的相邻依赖，注释本身有误导。
   - **Codex 没有提到的补充**：随仓库发布的实现 `scripts/decay_analysis.py:24、80–86` **确实实现了移动块 bootstrap**（`BLOCK_SIZE=5`，按块起点有放回抽样再截断到 n_dates）。所以准确的说法是：主说明要求 Bootstrap；参考示例是独立抽样；随附脚本用的是 5 日块。我原笔记"半衰期必须带 block bootstrap"把实现细节写成了作者的强制要求，**接受收窄**为"作者要求 bootstrap 区间；块重采样是随附脚本的做法，也是我们迁移时的建议"。
3. **新增实现问题**（静态推导，未运行）：
   - 期限最长到 20 日的远期收益互相重叠，长期限的逐日 IC 序列自相关跨度约等于期限长度；5 日块对 10–20 日期限偏短，置信区间可能偏窄。迁移时块长至少应覆盖最长标签期限，或改用按期限分别设定的块长。
   - `decay_analysis.py:89–100` 用"绝对值最大期限的符号"统一符号后拟合，与参考示例"以第 1 个期限为准"不一致；拟合失败（`slope>=0` 或有效点 <2）或半衰期 ≥500 的样本被直接丢弃，区间是"只在成功拟合的样本上"计算的条件区间，会系统性偏离；有效样本 <100 时返回中位数但不给区间。
   - 脚本中没有找到 SKILL.md 所述"方向反转判别"的实现（`grep` 无 reversal 判断），该规则目前只存在于文档。
   - `bootstrap.md:71` 建议剔除 |IC|>0.5 的日期：同意 Codex，不能自动采用，须先确认是数据错误。
4. **修订后结论**：仍为"采纳（方法）"，但写明：反转判别用有符号 IC；区间须考虑标签重叠；作者实现中的块长与失败样本处理不直接沿用。

### [147] skill-numerical-leak-check（commit 0012675）

- `references/result-interpretation.md:5–11` 定义四态：PASS 是"当前口径下未超过容忍度"；WARN 要先区分浮点误差、随机性、缓存、排序不稳定、NaN 处理差异和弱泄露；FAIL 才是"历史输出明确变化"；ERROR 不等于无泄露。
- `scripts/run_numerical_leak_check.py:159–170`：差异 ≤`atol`（默认 1e-8）且无坏点为 PASS；≤`warn_atol`（默认 max(1e-5, 1000×atol)）为 WARN；超过才是 FAIL。
- `references/adapter-contract.md:92–95`：比较口径与生产一致，只比较 checkpoint 及以前；固定 seed；隔离缓存。
- **接受纠正**：我原笔记写"历史部分不一致即泄漏""若历史输出变化即泄漏"，过强。准确表述是：在确定性、相同初始状态、隔离缓存和相同比较区间成立后，超过容忍度的历史变化才构成未来依赖证据；小差异先归入 WARN 排查。
- **关于标签**：同意 Codex。`adapter-contract.md:84` 把"标签生成任务"列为可检查对象，`checkpoint-design.md:19` 提到未来收益标签。标签本来就使用未来值，对它要检查的是"截止时间与可用于训练的时间是否正确登记"，不能机械要求标签前缀不变。迁移时，标签 case 的比较区间应限定为"标签已完全形成"的部分。
- 我原笔记"列为研究端必检项"**改为"建议列入，待项目登记"**，与 SUMMARY 第五节第 8 项一致。

### [216] skill-walk-forward-validator（commit bfa1a16）

- **重叠计数**：`walk_forward.py:164` 只要求 step>0；`:205–206` 测试区间为 `[start+train+embargo, +test_size)`；`:217` 逐折把测试日 IC 追加到同一列表；`:251` 每折前进 `step`；`:268` 对串接后的列表做块 bootstrap；`:291` 的 `n_oos_days` 为串接后有限值个数。**同意 Codex**：当 step<test_size 时同一日期被重复计入，样本数与置信区间都会被高估；默认 step=test_size 不触发。
- **同意 Codex 其他几点**：`:97` ICIR 固定按 √252 年化；`:163` 至少 10 个截面标的；函数接收现成 signal，不在每折重新拟合，所以 train_ic 只是"训练期行上的 IC"，退化率只有在信号确实只用训练期拟合时才有意义。
- **Codex 没有提到的补充**（静态推导，未运行）：
  1. **方向假设与退化率不一致**：门禁 `:271–275` 要求 `mean_test_ic>0`、正 IC 比例 ≥0.6、CI 下限 >0，等于默认因子是正向的；而 `:225–228` 的退化率用绝对值，注释说"正负向因子都适用"。负向因子不预先翻转符号就会必然 FAIL。
  2. **块长与标签期限脱钩**：`_block_bootstrap_ci` 的 `block_size=5`（`:124–145`）固定，不随 `label_horizon` 调整；label_horizon>5 时远期收益重叠，置信区间偏窄。
  3. **多空 Sharpe 的周期口径**：`:219` 每天计算一个 label_horizon 期的多空收益，`:244` 按 `periods_per_year=252` 年化；当 label_horizon>1 时是把重叠的多日收益当日收益年化，Sharpe 被高估。这与 [204] 的"年化期数须与序列频率一致"是同一类问题。
  4. 清洗逻辑 `:211` 只在 `embargo<label_horizon` 时生效，这一点本身没错，但默认 `embargo=5、label_horizon=1` 时 `purged_rows` 恒为 0，报告中的"已清洗"字段容易被误读为做过清洗。
- **修订后结论**：由"采纳（退化率、块 bootstrap CI、多档门禁）"**收窄为**"采纳思想（按信息区间隔离、分折评估、样本内外比值、依赖结构下的区间估计）；作者实现与门禁阈值不采纳为项目标准"。工具的 PASS 不映射为项目验证通过（同意 Codex）。
