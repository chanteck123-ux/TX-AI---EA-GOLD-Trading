- **公式问题（已按文档公式核实）**：
  1. **年化收益口径混用**：`r_ann = (1+r_cum)^(252/T_days)`，其中 `T_days` 是**自然日差**，252 却是交易日数。样本为一个自然年（T=365）时，指数只有 252/365 ≈ 0.69，年化收益被系统性低估。例如累计 +20% 会被年化为约 13.4%，而不是 20%。正确做法是交易日数配 252，或自然日数配 365。
  2. **收益对账是同义反复**：r_t 本身由 NAV 逐日相除得到，`prod(1+r_t) = NAV_e/NAV_s` 在数学上必然成立。"残差 < 1e-6 即通过"只能检查浮点误差，验证不了任何数据或逻辑，与 A158 中"对账实际上同义反复"的问题同类。
  3. **Sortino 分母不标准**：σ_downside 取 `std(r_t | r_t<0)`，即只对负收益求标准差。标准的下行偏差应对全部样本计算 `sqrt(mean(min(r_t,0)^2))`，两者在数值上有明显差异。
  4. **胜率排除零盈亏单**："平仓 = PnL≠0"，零盈亏的交易既不进分子也不进分母。V1.2 §11 要求零盈亏单单独列示，此口径不一致。
  5. **现金法量纲不一致**：重建净值时缺省 `cash_0 = 1 − MV_0`，把持仓市值（绝对金额）和 1.0 放在同一个式子里。除非 MV 已经归一化，否则现金会变成很大的负数（PLAUSIBLE 待脚本核实）。
  6. 单边换手按权重差计算，其中包含价格漂移带来的被动权重变化，并不等于实际交易换手。持仓天数用"自然日 × 5/7"近似。

## 源码批次 S006（2026-11-06，FULL_READ：scripts/performance 下 __init__、base、returns、risk、trades、positions、charts，scripts 下 report、html_report、strategy_report_cli、self_test；assets/echarts.min.js 是约 1 MB 的第三方压缩文件，记为 VENDORED_NOT_REVIEWED；未运行）
- **已核实（CONFIRMED）**：
  1. **年化口径错误**：returns.py 和 risk.py 都用 `(1+cum)^(252 / n_days)`，其中 `n_days = (dates[-1] − dates[0]).days`，即**自然日数**。
  2. **Sortino 分母不标准**：`downside = rets[rets < 0]; dstd = downside.std(ddof=1)`，只对负收益求标准差。
  3. **胜率排除零盈亏单**：`closed = (pnl != 0).sum()`，零盈亏的平仓不进入分母。
  4. **现金法量纲错误**：不传 `initial_cash` 时 `cash0 = 1.0 − mv0`。这时 `equity_t = mv_t + 1 − mv0 + Σcf`，`nav = equity/1`，净值实际上是"1 加绝对盈亏金额"。只要市值没有预先归一化，收益率就失真。self_test 的重建用例中市值约为 1.0，却以每股 10 元买入 200 股（现金流约为 −2,000），重建出的净值会变为负值；但测试只检查首值是否等于 1、模块是否降级，所以**这个缺陷被测试放过**。
- **新发现**：
  5. **同日多笔成交会导致崩溃**：trades.py 中 `bdf = pd.DataFrame({"pnl": pnl.values, "bucket": buckets.values})`，`buckets` 按**去重后的成交日期**生成，`pnl` 按**成交笔数**生成。只要同一天有不止一笔成交，两列长度就不同，pandas 会报"All arrays must be of the same length"。按标的分组时也会遇到同样的问题。self_test 的 14 笔成交恰好都在不同日期，所以没有暴露。
  6. **"本期调仓次数"取的是全历史**：`rebalance_count = trades["date"].nunique()` 统计的是全部历史的成交日数，没有限定在报告窗口内，与"本期"的说法不符。

## Codex 复核后更正（2026-11-07）
- S006 第 5 条"同日多笔成交就崩溃"收窄为：**只有 date 值完全相同的多笔成交才会触发长度不一致**。base.py 用 `pd.to_datetime` 处理日期时保留了时间部分，同一天但日内时间戳不同的成交，`unique()` 不会减少行数，因此不会崩溃。无成交，或 FIFO 无法配平而提前返回时，也不会走到这一行。以上是静态推断，未用 pandas 复现。
