# A170 skill-post-market-screener — Claude 全文审核（2026-11-05）

## P0209 后段（FULL_READ；FILES 1742–1743：portable-loader、OPERATION_MANUAL 25.7 KB）
- 定位：A 股盘后全市场选股，8 个 K 线形态检测器加资金流过滤，按行业做 Z-score 中性化后评分，再由 LLM（DeepSeek，走 Anthropic 兼容接口）逐股生成分析，最后输出 Markdown 和 JSON 日报。提供 MCP server。
- **安全问题**：
  1. **Pandadata 的 base_url 是 `http://`（明文 HTTP）**，用户名（"86+手机号"格式）和密码可能以明文在网络上传输。
  2. config.json 方式 B 把密码以明文写在文件里。
  3. portable-loader 的 MCP 配置示例把 `ANTHROPIC_AUTH_TOKEN`、`DEFAULT_USERNAME`、`DEFAULT_PASSWORD` 写进 mcp.json 的 env（示例中是占位符，不是真实值）。这会引导用户把密钥写进配置文件。
- **数据真实性问题（关键）**：
  1. 同花顺的数据没有超大单和大单拆分，系统就**用"净额×0.5"代替超大单和大单**。过滤条件 `super_large_positive`（超大单 > 0）因此只是"净额 > 0"的翻版，完全依赖代理值。JSON 示例中 super_large_inflow 32850 正好等于 main_inflow 65700 的一半，证实了这一点。然而 `data_provenance.flow.is_real=true`、`all_real=true`，**把代理值标成了真实数据**，溯源表存在误导。
  2. LLM 约 15% 返回空文本，自动用模板补成一句话摘要；LLM 生成的叙述直接进入报告，有编造风险，报告中没有区分模板和模型输出。
  3. 手册说"No mock/dry-run mode"，目录中却有 `core/mock_data.py`。
- **方法问题**：
  1. **权重在样本内校准**：analyze_weights 用缓存的 1000 只股票、233,894 条记录计算 5 日 Spearman IC，据此调整检测器权重（例如放量突破从 4 改为 3），再直接写回 config 用于生产，没有样本外检验。判断阈值（IC>0.02 为优秀、命中率>50%）没有扣除成本。
  2. 缓存超过 30 天自动清理，而回测校准需要至少 60 天缓存，两者冲突。全市场标的来自当前的 trade_list，存在幸存者偏差。
  3. **可交易性被忽略**：示例中排名第 1 的股票当日涨幅 19.99%（创业板涨停），收盘涨停的股票次日往往无法按收盘价买入，评分体系没有排除涨停股。
  4. 行业中性化用 max(0, z)，小行业的 σ 不稳定；quality_bonus 的阈值（市值 50 亿、成交额 2 亿）是主观设定。
  5. 配置中模型名为 `claude-sonnet-4-6`，实际被环境变量覆盖为 deepseek-v4-pro，配置与实际运行的模型不一致。
  6. 资金流数据通过 akshare 抓取东方财富和同花顺，三条路径自动切换（包括东方财富直连分页抓取），网站服务条款和合规性没有讨论。
- 测试声称有 154 个，未验证。

## P0210（FULL_READ；FILES 1744–1750：README.en、README、pandadata-map、pattern-formulas、report-template、validate-rules、requirements）
- 中英文 README 基本一致。触发时间三处不同：英文版写 cron 15:45，中文 mermaid 图写 15:30，计划任务写 15:37。资金流数据在收盘后十几分钟内未必已最终定稿。
- **回测结果与权重自相矛盾（关键）**：README 写"启明星 IC(5d)=+0.003 最优，MACD 金叉 IC=+0.016 唯一显著正向"。+0.003 小于 +0.016，"最优"的说法本身就矛盾；而且手册把 IC>0.02 定为"优秀"，**没有任何检测器达到**。生产配置中启明星的权重为 3（最高档），MACD 金叉为 1（最低档），权重与自家 IC 结论**相反**。IC 0.003 基本等于零，整套选股**没有展示出预测能力**。
- **文档之间不一致**：
  1. pattern-formulas 中放量突破的权重是 4、RSI 是 2，最大分 17；manual 和 README 已改为 3 和 1。JSON 示例的 pattern_score_raw=11，三个形态按新权重是 3+3+3=9，按旧权重是 4+3+3=10，两种都对不上。
  2. 文档称检测器"返回连续强度值"，公式却全是 0/1 条件判断。
  3. validate-rules 要求的字段名是 raw_pattern_score、industry_neutralized_score、final_score，JSON 示例用的是 pattern_score_raw 和 score，按这套规则校验示例本身就会失败。
  4. pandadata-map 把 AKShare/东方财富列为资金流主路径，并提到在 mock 模式下"使用模拟资金流数据"；其他文档却说主路径是同花顺，并且"No mock mode"。
  5. RSI 用简单平均，不是 Wilder 平滑；布林带的 std 没有说明用总体还是样本口径；启明星的跳空条件被放宽成"day −1 low < day −2 low"。
- 校验规则 C2 要求报告**必须**出现"值得关注""可跟踪"等措辞，等于强制每份报告都给出倾向性判断，与"仅供研究"的定位冲突。C1 禁止"买入""目标价"等词，有积极作用。
- 依赖：requirements 列了 mcp，但没有列 requests 和 urllib3（manual 中有）；panda_data 版本 ≥0.0.9（A158 要求 0.0.12）。get_stock_industry 和 get_stock_rt_daily 写明"权限不足"。

## A170 结论
- 这是一个带 MCP 和 LLM 的 A 股盘后选股器。主要问题：
  1. **自己的回测显示信号几乎没有预测力**（IC 在 0.003 到 0.016 之间），权重还与 IC 结论相反；
  2. 超大单数据是"净额×0.5"的代理值，**却被标记为真实数据**；
  3. 明文 HTTP 传输凭证，密钥会被写进 MCP 配置文件；
  4. 文档之间多处矛盾（权重、字段名、mock 模式、主数据路径）；
  5. 没有考虑涨停股的可交易性，权重只在样本内校准。
- 对 V1.2 唯一可借鉴的是"数据来源标注"这个想法，但它也反面说明了：标注本身必须如实，代理值不能标成真实值。脚本未审，154 个测试未验证。
