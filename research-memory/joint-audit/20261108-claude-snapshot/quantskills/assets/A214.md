# A214 skill-us-sec-edgar-harvester — Claude 全文审核（2026-11-05）

## P0249 尾段与 P0250 前段（FULL_READ：FILES 2128–2134，包括 portable-loader、README.en、README（中文版只核对了要点，与英文版一致）、references 下的 edgar-sources、methodology、source_boundary，以及 SKILL）
- 定位：只做信息采集。从 SEC EDGAR 的公开端点（submissions API、全文搜索、ticker 与 CIK 映射表、Archives）抓取 8-K、Form 4、13D/13G、13F、S-1，按 accession 去重，处理 /A 修订版的替代链，生成带来源的时间线和数据集。
- **优点（本批数据纪律最好的之一）**：
  - **每行必须带 accession 编号和 source_url**，没有 accession 的行不收录；
  - 区分申报日（acceptance）和事件或报告期日，时间线必须注明按哪一种日期排序；
  - 修订版保留整条替代链，原始行不删除；
  - Form 4 交易代码按原文记录，期权授予、扣税股不会被并成"买入"；Table I 与 Table II 分开；
  - 一个实体有多个 CIK 时不合并；
  - 遇到 403 或 429 时退避，并报告部分覆盖，不静默丢数据；
  - 单个文档解析失败时标记 `parse_incomplete`，其余照常处理；
  - **User-Agent 使用通用的描述性名称，不编造个人邮箱**；
  - 明确写出 13F 有 45 天滞后、只含多头和美股。
  这些原则与 V1.2 的证据和来源规则高度一致。
- **问题**：
  1. **13D 申报时限可能已过时**（按 Claude 的知识，未联网核实）：文档写 13D 为 10 日触发。据 Claude 所知，SEC 于 2023 年修订规则，自 2024 年起首次 13D 申报时限缩短为 5 个工作日。需要按 SEC 原文复核，本笔记只标为待核。
  2. edgar-sources 第 4 节把 browse-edgar 的 `output=atom` 列表写成"Filing index (JSON)"，实际是 Atom/XML（括号里已注明），标签有误。
  3. Form 4 和 13D/G 中有自然人的姓名和持股信息。这些虽是公开申报，文档仍没有提到个人数据最小化（例如研究中是否需要保留内部人的姓名）。
  4. 文档中多次说明 cursor-rule 和 portable-loader 由工作区同步生成，属维护信息。validate_report.py 只检查报告的格式和字段，不检查数据是否正确。
- 个人信息：维护者 handle 未转录。示例中出现的公司名称属于公开上市公司，与个人无关。
