# A157 skill-pandaai-workflow-generator — Claude 全文审核（2026-11-04）

## P0164（FULL_READ；FILES 1653–1659：portable-loader、README.en、README、disclaimer_template、qbti_bridge、sandbox_diagnostics、sandbox_restrictions）
定位：把 LLM 生成的策略或因子代码注入四个 PandaAI 工作流模板（simple_backtest、complex_stock_selection、multi_factor_analysis、multi_agent_trading），输出可导入的 JSON；另提供 skill-qbti 问卷桥接。

**优点**：
1. 参数定位符匹配到零个节点时报错退出，防止拼错后静默生成默认参数文件。
2. 多 CodeControl 模板拒绝不带定位的 `--code-file`。
3. 沙箱诊断方法论：
   - 先跑只读探针，再写策略；
   - 探针不下单、不 raise，用 hasattr 而非 dir；
   - 设对照标的，区分"方法不可用"和"标的无数据"；
   - 用短区间。
   可借鉴为 EA 在新券商/新品种上的"先探测平台能力"步骤（对应 MT5 实际 GOLD 规格、保证金核验）。
4. 事实表带验证日期，要求追加不覆盖。
5. qbti_bridge 明确写明：五个打分不是经 IC 检验的 Alpha；止损百分比是 generator 自定默认值；行业按名称关键词近似匹配。

**缺陷与风险**：
1. **"经验证、能够完美跑通"、"连线完美"**：属于营销式**未核实**声明，模板文件（JSON）不在本轮文档清单中。
2. **qbti 打分取算术平均、未做归一化**：
   - 各分量量纲不同：20 日收益、负偏离度、负标准差、增速标准差；
   - 直接平均会被量纲最大的分量主导；
   - 与 A155 pitfalls"先 RANK 再加权"的要求相反。
3. **quality_stable 存在 PIT 风险**：在 `initialize` 中一次性预取全区间 revenue/net_profit，再计算增速标准差。若 handle_data 没有按当时可得日期截断，就是未来函数（代码未读，**疑点待核**）。"前 1 年后 4 年"的写法用于规避平台 5 年区间限制，是绕过平台约束的技巧。
4. 行业过滤和 ST 剔除都按名称关键词判断，文档已承认会误判。用于研究时会引入不可控的选择偏差。
5. **ETF 结论外推过度**：证据只来自单一账号（2026-07-08）。行动准则却要求"只要用户提 ETF 就先告知不支持"，并写"不再需要额外扫描确认"，把单账号、单日期的事实固化为通用规则，有过期风险。名称关键词"300"作为 ETF 扫描依据也很弱。
6. sandbox_restrictions 的"禁止 import 模块"列表混入了 dir/eval/globals 等函数名。原文照抄自报错弹窗，文档自己承认未逐项复测。
7. 调仓频率映射（weekly→5 等）是近似值，文中已注明。

**对 V1.2 的适用性**：A 股/期货平台装配工具，不适用于 MT5 EA。只有"先探测平台能力、设对照组、事实表留日期"这一方法可参考。


## P0165（FULL_READ；FILE 1660 SKILL.md）
1. **防泄漏建议本身有缺陷**：SKILL 写"Shift signals where necessary (`factors['close'].shift(1)`) to prevent look-ahead"。但 A155 的返回契约规定 factors 是 `[symbol, date]` 多级索引 Series，不按 symbol 分组直接 `shift(1)`，会把上一只股票的最后一个值移入下一只股票的第一行（跨标的污染）。正确做法是 `groupby(level='symbol').shift(1)`（本条属推断，前提是平台 Series 结构与 A155 描述一致，未运行验证）。
2. 第 1 步把单账号的 ETF 结论写成"closed, not tentative… do not re-run the diagnostic probes again"，与 P0164 第 5 条相同，存在过期与外推风险。
3. 第 2a 步"探测后更新事实表，下一次同域跳过探测"：事实会随平台版本和账号变化，跳过探测缺少有效期约束。
4. 第 5 步建议导入前先交给 workflow-audit 审计。装配与审计分离，做法得当。
5. "Write clean, robust, error-free Python code"属于对模型的要求，不是验证手段。
6. 元数据为 `status: draft`、`validation_level: listed`，与 README 的"经验证、完美跑通"口径不一。

## A157 结论
- 工具性质：模板装配器。最有价值的是"先探测再写"的沙箱诊断法和定位符零匹配即报错。
- 主要问题：
  - shift(1) 在多级索引上的跨标的污染风险；
  - qbti 打分未归一化直接平均；
  - quality_stable 预取可能存在 PIT 风险；
  - 单账号事实被固化为通用规则；
  - README 营销口径与 draft 状态不一致。
- 不适用于 MT5 EA；未运行。
