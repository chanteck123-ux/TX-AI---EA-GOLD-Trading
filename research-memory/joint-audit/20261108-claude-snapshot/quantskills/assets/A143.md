# A143 skill-model-hpo-evidence-driven（因子模型超参数搜索：evidence-driven LLM + grid）— 文本审核

## P0147 部分（FILE 1512 agents/portable-loader 全文）
- 入口：`scripts/run_hpo_search.py --input <json>`；模型可选 lgbm、mlp 或已注册模型；方法可选 evidence_driven 或 grid；LLM 决策通过 `codex_external` 写入 decision JSON。
- 两种模式：
  - `legacy_v1`：逐 trial 使用不同 seed，以 rankic_ir 评估，状态为 status=evaluated；
  - `research_v2`：使用共同 seed 并做多 seed 确认，状态为 status=selected_not_tested，参数冻结后再用独立的 holdout 命令（需显式 `--confirm-holdout-access`）。
- 初步评价：research_v2 把"选出"与"测试"分开，方向正确；legacy_v1 是默认模式，是否把选参与评估混在同一数据上，待后续文件核对。
- 待续：P0148。

## P0148 补读（FILE 1513 extension_templates/README、1514 README.en、1515 README、1516 references/codex_external_workflow、1517 extension_api、1518 input_schema、1519 output_contract 全文）

要点：
- 两种 profile：
  - legacy_v1（**默认**）：目标为 rankic_ir；trial seed = seed + trial_index×997；不做 PIT 严格检查；**搜索运行中自动评估固定测试期**。
  - research_v2：目标为 robust_rankic（按块均值减去标准误惩罚）；共同 seed；Top-K 用 3 个 seed 确认（mean − 0.5·std）；严格 PIT 要求 available_date、label_start/end 和 universe；搜索数据在 valid_end 处截断；holdout 通过独立命令开封。
- 外部决策：LLM 只能写 decision JSON，由 Python 做 schema 和边界校验；final selector 只能在 allowed 列表内选择已有的中心 trial，并受 max_score_drop 限制。
- 扩展：外部模块必须同时设置 allow_external、plugin_roots 和 modules 才会被导入，manifest 记录模块文件的 SHA-256；运行时不扫描目录、不 eval 源字符串。

发现：
1. **默认 profile 不安全**：legacy_v1 每次搜索都会自动给出测试期结果，用户反复改配置重跑，就等于在测试集上间接调参。README 说"Holdout 指标只用于最终报告，不反馈给搜索过程"，这只在单次运行内成立。为兼容旧结果而默认 legacy_v1，应当反过来默认 research_v2。
2. **research_v2 的 holdout 不是一次性的**：独立命令每次写入 `holdout_evaluations/<timestamp>/`，并在 append-only 日志中记录访问，但**没有阻止再次运行**（对比 A142 在拟合前独占 claim、失败也消耗一次的机制）。只是"可审计"，不是"不可复用"。
3. legacy_v1 每个 trial 的 seed 不同，trial 之间的分数差混入了随机种子噪声，按 rankic_ir 选最优时会挑中"幸运 seed"。research_v2 用共同 seed 加多 seed 确认来纠正，做法正确。
4. **多重试验没有校正**：没有记录有效试验数，也没有 DSR 或 PBO 类校正；LLM 可以 expand/shift 搜索空间，使试验空间不断扩大，选择偏差随之增长。
5. "evidence_driven"在文档中明确"不是概率性 TPE"，但仍接受旧别名 `adaptive_tpe`，命名容易误导。
6. 时间单位混用：purge 用 embargo_days（自然日还是交易日没有说明），walk-forward 用交易日计数，另有 time.trade_lag_days；口径需要统一。
7. 设计优点：
   - 外部决策需要经过 schema 和边界校验；
   - LLM 只能从已有 trial 中选，不能编造参数；
   - 外部代码必须显式授权并记录哈希；
   - feature pipeline 在 transform 中拿不到验证集或测试集的 y。

待续：P0149（SKILL.md、validation_notes、source_boundary 等）。

## P0149 补读（FILE 1520 references/source_boundary、1521 validation_notes、1522 requirements、1523 SKILL.md 全文）

补充：
- source_boundary 明确说明："legacy_v1 自动评估测试期**不是封存 holdout 流程**"；"本地审计控制无法阻止用户复制数据或重跑命令，仍需组织层面的测试集治理"。这印证了发现 1、2，作者如实承认。
- LLM 只拿到结构化的 trial 证据，看不到原始因子矩阵或标签；越界输出回退为规则决策。
- requirements 只设下限，torch 为必需依赖（README 却说 LGBM 可以不装 torch），两处不一致。

**A143 结论**：文本全部覆盖（共 12 份全文）。research_v2 的设计（共同 seed、多 seed 确认、PIT 严格模式、封存后开封 holdout、外部决策需校验）正确；但**默认的 legacy_v1 会在每次运行时暴露测试期**，holdout 也不是一次性的，而且没有多重试验校正。对本项目的启示："参数单独变化也要登记为试验"，测试期必须独占且只用一次。**未实现**。
