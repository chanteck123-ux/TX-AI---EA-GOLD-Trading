# A033 skill-b12-intraday-position-manager（全文审核笔记）——与 RiskExecution 相关
- 读取（P0035）：INSTALL.md、README(.en.md, .md)、references/api_guide.md、requirements.txt（SKILL.md 见后续包）。
- 内容：日内多品种（A 股/ETF、股指期货、商品期货、港股）的五级规则：
  - 到时间强平 → 浮亏 ≥1% 全平 → 浮亏 ≥0.5% 砍半 → 浮盈 >1% 加仓 50% → 持有。
  - 区分 T+1 锁仓（sellable_qty 与 locked_qty 分开）；加仓前校验现金或保证金，**不足就整单 hold，不做部分降级**。
  - v3 输出新增结构化字段：market、sellable、cash_req、flags、capped_by_max_qty；可选 max_qty 上限。
- **值得借鉴**：
  - ①v3 **拒绝 NaN/inf/bool**，直接抛 ValueError——比 A32"静默 hold"的做法正确，坏数据要显式失败。
  - ②**结构化 flags 取代 reason 字符串前缀**，并给出弃用期——对应我们拒单和对账原因码的设计（只解析结构化字段，不解析人类可读文本）。
  - ③T+1 锁仓：强平时 target = locked_qty，不尝试卖出不可卖的部分，并标 t1_blocked。
  - ④资金不足时整单拒绝，而不是悄悄缩量（与 A009 的正确做法一致，也和项目"固定表不被静默缩量"的原则一致）。
  - ⑤交易时段校验默认开启（time 不在交易时段内就报错），回测时可显式关闭。
- **独立发现（未运行）**：
  - ①**自动加仓 50%**：浮盈 >1% 就加仓——一个"仓位管理/风控"模块自己**扩大风险**。这与项目原则"风控不自动扩大已授权风险"冲突；加仓应该属于策略意图（Core 的 TradeIntent），再经过 RiskExecution 审批。
  - ②**flags 优先级掩盖信息**：max_qty 和现金同时不足时，只报 capped_by_max_qty，不报 cash_insufficient——第二个约束被隐藏。诊断用的标志应该把所有命中的约束都列出来。
  - ③**未识别品种 → hold**（只加 unknown_market 标志）：同 A32，对持仓来说等于没有保护；而且批量处理中任何一条 ValueError 都会让整批中止（异常表里包括空列表、时段越界等），一条坏数据就让所有仓位失去管理。
  - ④**商品期货时段不含夜盘**：夜盘时间调用会因时段校验报错——夜盘持仓得不到管理（是否带 session_check=False 运行取决于调用方）。
  - ⑤止损阈值依赖调用方传入的 pnl_pct，模块本身不核算（不知道 pnl 的基准是含费还是不含费）。
  - ⑥版本标注不一致：README 写 SKILL v2.1，api_guide 写 v3 breaking changes。
- 对 RiskExecution 的候选测试用例（只记录，不改 v1.0 接口）：
  - ①批量中一条坏数据**不能**让其他仓位失去保护——应按单条隔离失败；
  - ②所有命中的约束都要写入原因码；
  - ③风控模块不产生加仓意图；
  - ④交易时段校验必须覆盖 GOLD 的实际交易时段与休市窗口（包括每日休市、周末），不在时段内时进入"待处理"状态，而不是丢弃。
- 续读（P0036）：SKILL.md（18 KB，全文）。补充：
  - 交易时段集中配置在 `_TRADING_SESSIONS`，修改一处即可；作者特别提醒：**`force_close_time` 必须落在允许的时段窗口内，否则强平"永远不会触发"**（时段校验会先拒绝调用）——这是一条很有价值的教训：保护性触发条件与输入门控之间的冲突，会让保护**静默失效**。
  - 集合竞价时段拒绝调用；港股半日市没有识别。
  - **文档残留**："可被 Alpha 调用"一节仍要求调用方提供 `yesterday_qty / today_qty`，而 v2 已改为 sellable_qty/locked_qty。
  - 手续费按固定费率估算，不含印花税等。
- **A33 逐资产结论**：输入校验和结构化输出优于 A32，但风控模块内含自动加仓，批量处理会因单条错误整体失败，夜盘不管理。**未做静态实现核查，未运行**。
- 对 RiskExecution 的补充候选测试：**所有保护性触发时间（例如周五收盘前减仓、休市前处理）都必须有测试，证明它们落在允许执行的窗口内**，否则保护会静默失效。

## 源码批次 S022（2026-11-07，只读，未运行）

- `scripts/test.py` 仍为 UNREAD，归入第 3 层。
1. **CONFIRMED：批量运行时，任何一条记录不在交易时段，整批都会停下。**
   - `batch_manage` 在开启 session_check 时，会对每条记录执行 `_check_trading_session`，有一条不在时段内就抛出 ValueError，整批停止。
   - 商品期货的交易时段只配了日盘（09:00–10:15、10:30–11:30、13:30–15:00），**夜盘时调用一定报错**。
2. **CONFIRMED：规则不记状态，会反复触发。**
   - 每次调用只看传进来的 pnl_pct：只要浮亏 ≥ 0.5% 就把仓位砍半，只要浮盈 > 1% 就加仓 50%。
   - 系统没有记录"这次是否已经执行过"。如果按分钟轮询，就会连续砍半，或者连续加仓、金字塔式放大。
   - 加仓后均价改变，pnl_pct 的计算基准由调用方决定，代码里没有说明。
3. **CONFIRMED：不传 max_qty 时，加仓没有上限。** 只检查 available_cash 是否够付保证金加手续费，没有账户层面的保证金比例或敞口上限。
4. **CONFIRMED：无法识别的品种一律 hold，浮亏也不平仓。** 比如示例中的 "ABCD"，浮亏 1.2% 时仍然 hold，只打上 `unknown_market` 标记，出场方向等于放行。另外，港股的最小交易单位查不到时默认取 100，属于默认值兜底。
5. 只支持多头：卖出都按平多处理，没有空单的表示方式。商品期货强平时间是 14:45，不处理夜盘持仓。
6. 做得对的地方：
   - T+1 锁仓的处理正确，强平时 target 设为 locked，并标记 t1_blocked；
   - 全平和强平直接平到 0，不受最小单位取整影响；
   - 输入校验拒绝 NaN、inf 和 bool；
   - 输出带结构化的 flags。
- **对 V1.2 的反例用例**：
  - 加仓和减仓规则必须有状态，比如同一个触发条件只执行一次，并且有冷却期；
  - 批量处理中一条记录出错，不能让其他持仓的保护失效，必须逐条隔离；
  - 无法识别的品种在出场方向上要报警升级，不能静默 hold；
  - 保护规则必须覆盖所有交易时段，包括夜盘。
