## P0236 尾段与 P0237（FULL_READ；FILE 1996 portable-loader；FILES 1997–1999 三份 docs/superpowers/plans）
- 定位：美股存储芯片相关股票的研究报告，先算两层评分，再生成 HTML 报告。
- **工程与安全设计值得借鉴**：
  - 每次分析前先过行业快照门禁：五个模块要么本轮刷新成功，要么由用户明确授权使用旧快照（cached-authorized），沉默不算授权；
  - run manifest 绑定 ticker、refresh_id，且只能使用一次；
  - 官方域名按点号边界做后缀匹配，能挡住 `nvidia.com.attacker.example` 这类伪装域名，重定向后的 final_url 也会重新校验；
  - 快照用临时文件加 `os.replace` 原子替换；
  - 事实和估算分开，估算必须带输入、公式、假设、局限和区间；
  - 凭证只在本机可见窗口隐藏输入，不进聊天、命令行或日志；
  - 先通过门禁再要凭证；
  - 计划遵循 TDD（先写失败测试）。
  这套"刷新门禁加显式授权降级"可直接对照 V1.2 的 NR08 新闻日历和数据新鲜度处理。
- **评分方法问题（计划 1998 原文）**：
  1. 最终信号的九项系数合计 0.88，另有不设上限的"财务质量修正"直接加减，最后 clamp 到 10–95。文档自己承认系数不是归一化权重。**HBM、下游、技术节点三项同时进入内层的存储周期分和外层最终信号**，属于重复计分，文档也承认"同时出现"。
  2. 历史样本诊断用的是"与正式研究信号不同的简化评分"。这意味着正式信号**没有任何历史验证**，IC 和分层结果只针对另一个模型。
  3. 各模块的加减分档位（±20、±25、±12、0–7）没有任何依据或整定说明。
- 计划 1999 称某海外存储厂的 ADR 于 2026-07-10 在 Nasdaq 上市，因此只允许使用该日之后的历史，禁止拼接原股价格。这是**来源中的说法，Claude 未核实**。不拼接、历史不足时返回空值并说明原因、不用 52 周字段替代，这些做法都正确。
- 计划要求"用 PowerShell -ExecutionPolicy Bypass 运行"，会绕过执行策略，Claude 不执行。

## P0238–P0239 前段（FULL_READ；FILES 2000–2002 三份 specs、2003 README.en、2004 README、2005 requirements、2006 SKILL）
- specs 与 plans 一致：允许域名清单、四个时间字段（published/as_of/accessed/verified）不得互相替代；按 as_of 选择最新来源，而不是按响应先后；镜像来源冲突时判定该模块失败，不自动选边；旧数据授权只对当前一次分析有效。README 中英文一致。
- **新发现**：
  1. **门禁不对称**：一手来源门禁只覆盖 GPU/HBM 的五个模块。权重最大的 DRAM/NAND 合约价（±25）、库存、下游、CapEx 和技术节点仍从静态 `industry_data.json` 读取，陈旧时**只给提示，不阻断分析**，而且允许用第三方或付费资料作为来源。HBM 门禁很严格，最主要的周期输入却没有门禁。
  2. **分数区间前后矛盾**：README 和 spec 给出四档（65–95、50–64、35–49、10–34，配合 clamp 10–95）；SKILL.md 给出五档（70–100 较强、55–69、45–54、30–44、0–29 较弱）。clamp 到 10–95 时，"0–29"和"95–100"两段永远不会出现。同一分数按两份文档会得到不同解释。
  3. requirements 只有下限（`panda_data>=0.0.12`、`pandas>=2.0`、`plotly>=5.0`），没有锁定版本或哈希。
  4. SKILL 和 README 中带有开发者本机路径（`D:\PandaAi_skills\...`，不含人名），以及 `-ExecutionPolicy Bypass` 启动方式。
- 其他：SKILL 要求首轮回复不得附带市场观点和评分，回测必须披露"简化评分与实际评分的差异"，这些边界写得清楚。
