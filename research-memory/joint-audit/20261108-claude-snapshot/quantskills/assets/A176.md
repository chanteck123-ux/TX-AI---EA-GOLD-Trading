## P0214 后段（FULL_READ；FILES 1780–1786：portable-loader、CLAUDE.md、README.en、README、governance-and-monitoring、portfolio-construction、risk-models）
- 定位：组合构建与风险治理，覆盖 mandate 转换、风险预算、约束分层、换手与成本、求解器诊断、风险模型与压力测试、治理与监控。与 A172 和 A177 是同一作者的三件套（写作风格一致）。中英文 README 一致。
- **可直接迁移到 V1.2 RiskExecution（高价值）**：
  1. **缺失或过期的风险输入一律阻断（fail closed）**；某项控制不可用时，阻断或进入文档化的降风险模式。
  2. **交易量按实际持仓计算，不按上期目标计算**，并计入挂单、已成交、公司行为、现金和合约乘数，这对 MT5 的挂单和部分成交场景很关键。
  3. 独立风控尽可能走**独立的计算路径**；单一成功指标不能授权交易；放行前必须同时通过数据新鲜度、模型有效性、mandate、风险、流动性和操作检查。
  4. **Kill switch 只能通过经过认证并留有记录的审批来解除**，并要指定安全状态（撤单、持有、减仓、对冲或平仓）。
  5. 每项限额必须写明阈值（硬限、预警、容差）、计量方式、责任人、动作、覆盖权限（含期限和补偿控制）和不可篡改的证据；**不能靠改变计算窗口或舍入来掩盖超限**。
  6. 每一步尽可能幂等，"重试不得重复下单或重复计算成交"。
  7. 目标波动率不能防跳空和模型误差，缩放之后还要再施加杠杆、保证金、流动性和跳空损失上限。这与 V1.2 DR01 动态风险的设计一致。
- 风险模型部分：MRC、RC 的定义正确，并要求对账到总波动；协方差要做对称性、PSD、条件数和新鲜度检查；**不得在不标注的情况下用单位阵替换无效矩阵**；压力测试分历史、假设、实施三层。
- 缺口：
  - (a) 偏向机构股票组合，没有覆盖单品种 CFD 的保证金、Stop Out、swap 和周末跳空；
  - (b) 限额的"责任人"一项在单人加 AI 的项目里需要改成"Codex/Claude/用户"的职责映射；
  - (c) scripts 未审。
