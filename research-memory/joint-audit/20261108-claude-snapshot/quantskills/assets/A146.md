# A146 skill-northbound-margin-monitor（北向资金 + 两融全景监控，含 MCP server）— 文本审核

## P0150 部分（FILE 1541 agents/portable-loader 全文）
- 除 CLI 外还提供 MCP server（run_panorama_monitor、get_latest_report、check_trading_day）。
- 示例 MCP 配置把 `ANTHROPIC_AUTH_TOKEN`（占位值 sk-xxx）、第三方兼容网关的 base URL、模型名，以及 `DEFAULT_USERNAME`/`DEFAULT_PASSWORD`（占位值）写进 MCP JSON 的 env 字段。示例中都是占位符，但这种写法**引导用户把真实凭证以明文写入配置文件**，存在安全隐患。
- 声称"全部真实数据（Pandadata + AKShare + LLM API），没有 mock 或 dry-run 模式"，意味着测试也必须调用外部服务并消耗配额。

## P0151 补读（FILE 1542 OPERATION_MANUAL、1543 README.en、1544 README、1545 references/advanced-features 全文）

要点：
- 共 25 个检测器（北向 7、融资 7、期货 3、量价 2、微观 7），另有 4 种共振/背离模式和半衰期衰减（2^(−N/half_life)）。
- 综合分：加权和 × (1 + 共振修正) → 映射到 0–100，分 A+ 到 F− 九档；另有四因子风险星级和风险惩罚。
- 多级降级链；声称 540 个测试（**未运行核实**）。

发现：
1. **权重文档不一致，且"重校准"没有依据**：OPERATION_MANUAL 写北向/融资/期货/量价/微观 = 35/35/17/8/5；README（中英文）写 18/38/20/8/16，并注明"2026-07 由 0.35 重校准、由 0.05 重校准"，却**没有给出重校准的方法、数据区间或样本外检验**，很可能是事后按历史表现调参。
2. **"北向"维度实际是指数动量的代理**：作者承认 net_buy_amount 自 2024-08 起为 NaN，market_value 自 2026-04 起为 0，个股持仓数据停在 2024 年。系统改用"CSI300 指数变动"和 FlowAccumulator 作为北向的代理，于是北向信号与量价维度（指数动量）**同源重复计分**；北向维度名不副实，但仍占 18–35% 的权重。（作者如实披露了数据缺失，问题在于降级后没有重新评估权重和含义。）
3. **静默换源**：Pandadata 不可用时，融资个股数据自动降级到东方财富；北向数据有 4 级降级链。报告虽然标注了数据源，但跨源拼接时口径不同（单位、时点），文档没有说明如何统一。
4. **运行时点早于数据可得时点**：cron 示例为 15:30，而数据时延表写明"融资个股 T 日 20:00 后可用，北向和融资宏观 18:00 后可用"。按示例运行会取到前一日数据或空数据，文档"故障排查 2"也承认存在这种情况；与 A136 选在 18:30 运行相比，时点不一致。
5. **IC 回测不满足 PIT**：回测读取 output/ 下的历史 JSON 报告，但历史报告可以用 `--date` 结合当前 API 重新生成（会拿到修订后的数据）。申万行业"离线备份永不过期"，意味着历史分析可能使用了后来的行业分类。
6. **含有交易建议性表述**：共振表的"操作参考"列写着"顺势做多 / 减仓观望 / 高度警惕"，与校验器"禁止投资建议表述"的规则自相矛盾。
7. 风险惩罚"把极端评分拉向中性"，评分档位和惩罚阈值（38% / 28%）都是人为设定，没有校准依据。
8. MCP 的 SSE 模式（远程调用）没有提到鉴权；README 中出现作者本机的 D 盘路径。
9. 依赖要求 numpy<2.0，有老化风险。

待续：P0152（data-sources、report-template、SKILL.md 等）。

## P0152 补读（FILE 1546 references/data-sources、1547 references/report-template、1548 requirements 全文）

补充：
- 各检测器的数据源分配表显示：北向 7 个检测器中有 5 个依赖 "📈CSI300 代理 / 📊市值差"（市值差自 2026-04 起为 0），**只有"市场流向"一项是真实的北向数据**。这印证了发现 2：北向维度大部分是指数代理。
- 微观检测器使用硬阈值：主力净流入 ±50 亿、龙虎榜净买入占比 55% 且金额 5 亿、新高占比 65% 等，均为手设，没有校准依据。

发现（续）：
10. **模板与 LLM prompt 的权重已经过时**：报告模板第 7 节和 LLM prompt 仍写"北向 35%、融资 35%、期货 17%、量价 8%、微观 5%"，与 README 当前的 18/38/20/8/16 不一致。LLM 拿到的是错误的权重说明，生成的研判会误导读者。
11. **规则变更与自动阈值校准**：data-sources 称"2026-07-06 起主板 ST 涨跌幅限制由 ±5% 改为 ±10%"——这超出 Claude 的已知范围，**未核实**。随后建议运行 `calibrate_zt_thresholds.py` "自动阈值校准"，即用新数据在样本内重新拟合阈值，没有说明验证区间。
12. 融资买入比的分母"总成交额不可用，使用启发式估算"，但"融资买入比 10–15%"这类绝对阈值依赖分母口径，启发式分母会使阈值失去意义。
13. 规则 fallback 的叙述（例如"涨跌停比极端时反转概率增加"）没有统计依据。

**A146 结论**：文本全部覆盖（共 9 份全文）。工程层面的降级、溯源标注和缓存做得比较完整，作者也如实披露了北向数据缺失；但北向维度大部分已退化为指数代理且与量价维度重复，权重在多份文档之间互相矛盾且"重校准"没有依据，运行时点早于数据可得时点，回测不满足 PIT，还包含操作建议性表述。综合评分**不能作为择时依据**。与 EA 无关。
