独立发现：
1. **数据源优先级风险**：SKILL 规定"用户指定 → tests/ 合成面板 → .env 真实 Parquet，读到即停"。若 tests 下已生成合成 CSV 而用户未显式指定输入，就会先读合成数据，可能把合成结果当成真实监控报告。source_boundary 禁止"把随机样本当正式结论"，但流程本身没有防止这种情况。
2. **原始价格字段的结构性误报**：默认检查 close/high/low/open/volume/amount 的原始水平值。脚本把基准期与监控期所有标的、所有日期合并计算 PSI/KS/均值偏移；价格与成交额本身非平稳，有趋势就会被判为"漂移"。应先对收益、截面标准化或排名后的值做漂移检查。
3. **标签期限跨越基准/监控边界**：`return_20 = close(t+20)/close(t)−1`，按行移位（与 decay 脚本同类：停牌缺行会拉长实际期限，以 close(t) 为起点）。基准期末 20 天的标签落在监控期内，基准 IC 含监控期价格信息；最后 20 天无标签，末尾窗口 ic_days 偏少。
4. **IC 处理优于 walk_forward**：150 行单独检查 baseline 与 window IC 的符号翻转，所以绝对值保留率不会漏掉正负翻转。这一点资料实现是对的。
5. 默认切分点为日期中位数，`freq` 分窗；监控窗为月时，20 日重叠标签使窗内 IC 高度自相关，文档未提示。
6. 排序规则"date 降序"只是展示约定；派生收益使用升序副本（90 行 `sort_index(level=[1,0])`），静态核对无方向错误。
