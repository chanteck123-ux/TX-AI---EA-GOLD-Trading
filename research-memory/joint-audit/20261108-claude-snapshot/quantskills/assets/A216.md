# A216 skill-walk-forward-validator — Claude 全文审核（2026-11-05）

## P0250 尾段与 P0251 前段（FULL_READ：FILES 2145–2148、2150，包括 README.en、README、references/methodology、references/source_boundary、SKILL；FILES 2141–2144 四个运行时适配器和 FILE 2149 requirements 为 HASH_REUSE）
- 定位：对截面信号做 purged/embargo 的滚动前推样本外验证。流程是按 label_horizon 剔除训练集中标签与测试期重叠的行，再加 embargo 间隔，然后计算 Rank IC 和 Pearson IC、ICIR、多空 Sharpe、Q5−Q1、训练到测试的退化率，用移动区块 bootstrap 求 CI95，最后由多门禁给出 PASS、WEAK_PASS 或 FAIL。引用了 López de Prado 第 7 章。中英文 README 一致。
- **方法问题**：
  1. **信号矩阵事先算好，"训练窗"里其实没有拟合任何东西**：输入是一个已经算好的 signal[T×N]。各折之间不重新估计参数，所以"训练窗"只是样本内 IC 的计算区间，purge 和 embargo 只能防止**标签重叠**造成的泄漏，**防不住研究者在看过全样本后才设计出信号**这种更常见的前视。"训练到测试的退化率"在没有逐折拟合的情况下，只反映不同时期 IC 的差异，不能说明过拟合程度。文档在 Boundaries 里要求"调用方保证信号可得"，但没有点明这一局限。
  2. **门禁阈值没有公开**：PASS 和 WEAK_PASS 的具体阈值，以及 bootstrap 的区块长度，在 SKILL、README 和 methodology 中都没有写出，只能看脚本（未审）。门禁一旦不透明，PASS 就无法复核，与 A175 的"自定义 pass"同属一类问题。
  3. 多空 Sharpe 不含成本（已披露）；没有对多个候选信号做多重检验校正。
- 优点：强调 label_horizon 必须等于远期收益的期数；工具不绑定数据供应商，不联网；演示数据为合成且确定；限制写得清楚。

## A216 结论
- purge 加 embargo 的思路适用于 V1.2 M5 标签、持仓重叠样本的样本外设计。但 V1.2 必须做到"逐折重新拟合，或冻结参数后再做样本外"，门禁阈值也必须事先登记。脚本未审。
