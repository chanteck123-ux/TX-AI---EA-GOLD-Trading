## P0200（FULL_READ；FILES 1676–1682：portable-loader、README.en、README、common_formulas、data_sources、requirements、SKILL）
- 定位：论文复现流程（arXiv 检索 → PyMuPDF 提取 → pandas 回测 → 图表 → 指标对照），内置 tsmom、csmom、risk_parity、trend_vol 四个模板，默认标的 rb、if、au（中国期货）。中英文 README 逐段对照，内容一致。
- **公式和实现问题（common_formulas.md）**：
  1. **Risk Parity 公式错误**：`w ∝ Σ⁻¹·σ` 不是风险贡献相等（ERC），它是最大分散化组合的形式；再把负权重截为 0、归一化之后，更谈不上风险平价。文档却注明 "risk contribution equalized"。
  2. **ARP 标签可疑**：`w ∝ Σ⁻¹·1` 是最小方差组合的形式；"Agnostic Risk Parity" 一般指对相关矩阵做 C^{-1/2} 旋转，两者不同（我依据的是对该方法的一般认识，原论文未读，属 PLAUSIBLE）。
  3. **CSMOM 在默认 3 个标的下失效**：top 10% 的条件是 `ranks <= 0.3`，没有任何标的满足，所以没有多头；bottom 的条件是 `ranks > 2.7`，只有第 3 名满足。默认参数会得到一个只有单边空头的组合。
  4. **波动率目标化有前视风险**：用 `rolling(20).std()` 在当日直接缩放当日仓位，没有 shift。虽然另一节要求 weights.shift(1)，但两段代码没有关联起来；杠杆上限为 3 倍。
  5. **期货手数公式错误（高风险）**：`target_lots = capital*weight / (price*multiplier*margin_rate)` 算出的是让**保证金**等于目标金额的手数，名义敞口等于目标的 1/margin_rate 倍（保证金率 8–14% 时为 7–12.5 倍）。若 weight 的含义是名义权重，杠杆会被放大约 10 倍。这一点直接关系到本项目的 RiskExecution 原则：仓位要按止损风险或名义敞口计算，不能按保证金反推。
  6. 合约规格表的乘数和跳动价位大致正确（AU 为 1000 g/手、0.02；CU 为 5、10；IF 为 300、0.2），但保证金率是静态近似值，交易所和期货公司会调整，不能当作权威。
  7. Sharpe 默认 Rf=0；TSMOM 用 `close[-252]`（实际是 251 日收益）；look-ahead 小节先说"t 时信号只用 t-1 数据"，示例却是"t 收盘出信号、t+1 收盘成交"，两种口径并存，但都偏保守。
- **数据问题（data_sources.md）**：akshare 的 `rb0`、`AU0` 和 yfinance 的 `GC=F` 都是**未调整的连续合约拼接**，换月跳空会产生虚假收益，TSMOM 等信号会被污染。文档完全没有提到换月或复权处理。默认成本 1bp，未计滑点。
- **工程问题**：输出路径硬编码为 Linux 的 `/home/coder/project/...`，在 Windows 上不可用；README 和 SKILL 都说可以用 yfinance，requirements 却没有列出；`search_arxiv.py --download` 会联网下载 PDF（不受信任的下载）；SKILL 中引用的 `scripts/` 和 `templates/` 未审（属 .py，或不在清单中）。
- 优点：要求如实解释与论文的差异，不得强行拟合；记录数据来源、日期范围和最新日期；图表文字使用 ASCII。
- 结论：流程框架可参考，但内置公式中**风险平价错误、手数公式会把杠杆放大约 10 倍、连续合约未复权**三项会直接导致复现结论错误。不建议直接使用其模板结果。对本项目的启示：仓位计算必须以风险或名义敞口为口径，并有单元测试；连续合约必须做换月处理。
