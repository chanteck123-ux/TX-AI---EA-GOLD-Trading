- 内容：从每日 ≥3 连板候选中选 top-3。10 个子因子 z 加权后经 sigmoid 映射为绝对分数 score；T 日收盘后出信号，T+1 开盘买入，T+2 全日 VWAP 卖出；T+1 一字板或开盘涨停标为 unfillable；策略层用 60 日 RankIC > 0.02 门控（`rolling(60).mean().shift(1)`，已滞后一期）。
- 好的做法：
  - unfillable 单独计数（31% 的候选根本买不到）。
  - 概念成分按 in_date ≤ signal_date 过滤。
  - 作者坦白：候选池次日整体均值为负；激进权重校准在 OOS 上亏 90%。
  - sigmoid 绝对评分，避免"矮子里挑高个"。
- **独立发现（文档之间相互矛盾，属于静态核对，未运行）**：
  - ①**buy 阈值不一致**：README 写 score ≥ 80，开发版 SKILL.md 写 ≥ 70。
  - ②**权重不一致**：README 列出 10 项（0.18/0.18/0.13/0.09/−0.13/−0.09/0.05/0.05/+0.10/−0.10）；开发版 SKILL.md 公式只有 8 项（0.20/0.20/0.15/0.10/−0.15/−0.10/0.05/0.05）。
  - ③**IS/OOS 的 IC 数字三处各不相同**：README 摘要 IS≈0.008 / OOS≈0.107；README"已知发现"表 IS=0.054 / OOS=0.179；backtest_report.md 中 IS IC=0.0073、RankIC=−0.001，OOS IC=0.1069、RankIC=0.0455。
  - ④**交付报告自相矛盾**：backtest_report.md 中全样本 buy 多头毛收益 ARR −99.75%、MDD −99.71%；IS 段 −99.96%；**五层分层收益全部是 NaN**。但 README 的验收表把"输出分层"标为 ✅——验收声明与产物不符。
  - ⑤**OOS 已被污染**：IC gate 和情绪过滤是根据"ablation 显示显著改善 OOS"选出的，Layer 2 状态机也是"经回测证明有害"后删除的——设计决策用了同一段数据，最近 6 个月已不能算样本外。OOS 只有 40 个回测日、53 笔 buy。
  - ⑥**成本口径不一致**：验收要求写"标准 0.30% + 压力 0.50%"，策略层实际用 0.10%/0.15%；README 称实盘需 ≤0.15%。对连板股而言，0.10% 的双边成本未计入冲击，偏乐观。
  - ⑦**卖出口径不一致**：设计表写"封板顺延卖出，找首个未封板日 close"，而 data_guide 中 forward_return 固定为 T+2 VWAP；T+2 若封死跌停，VWAP 无法成交。
  - ⑧概念成分只按 in_date 过滤，没有处理剔除日期（out_date），历史成分会混入后来才剔除的成员——是另一种 PIT 偏差。
  - ⑨`validation_level` 三处不同：根目录 listed、开发版 community、README 未标。
- **A26 逐资产结论**：作者对局限很坦率，但交付物内部不一致，验收声明与报告不符，OOS 已被设计决策污染。**不作为方法参考**，只作为反例。未做静态实现核查，未运行。
- 对黄金 EA（反例教训）：
  - ①验收表中每个 ✅ 都必须能对应到产物里的实际数值（NaN 不能算通过）——对应七状态区分。
  - ②**用来选择过滤器或门控的数据段，就不再是 OOS**——对应 §13.9 冻结后才验证的规则。
  - ③多份文档的参数（阈值、权重）必须来自同一个机器可读的源，否则必然漂移——对应我们"单一权威文件"的做法。
