# A166 skill-portfolio-liquidity-stress-test — Claude 全文审核（2026-11-05）

## P0207 中段（FULL_READ；FILES 1717–1720、1722、1724、1725；1721 output-contract.md 和 1723 requirements.txt 为 HASH_REUSE，与 corporate-action-adjustment-auditor 的同名文件哈希相同，已在该资产中审过）
- 定位：确定性的流动性压力测试。压力 ADV = adv×volume_shock；日容量 = 压力 ADV × 参与率；期限容量 = min(持仓, 日容量×期限)；赎回按持仓市值比例分配，再受各标的期限容量约束；成本 = 半个完整买卖价差 + η·σ·sqrt(出售额/(压力ADV×期限))。
- **问题**：
  1. **波动率口径未定义（关键）**：输入要求 `volatility` 为"非负的小数波动率"，但没有说明是日波动率还是年化波动率。平方根冲击模型通常使用**日**波动率，如果误传年化值，冲击成本会放大约 √252≈15.9 倍。
  2. 赎回严格按比例分配，某个标的容量不足造成的缺口不会转移到流动性好的标的上，所以缺口和成本反映的是"按比例出售"这一特定策略，不是最优清算，需要在报告中说明。
  3. "清算天数"的公式在 methodology 中没有给出（只有容量公式）；η=0.5 是未经校准的默认值（文档已承认"不是校准的执行预测"）。
  4. 只在 ADV 上施加压力，不同时提高波动率和点差，而核心原则第 1 条要求"压力期同时提高波动率/点差"。脚本参数中没有对应的压力乘数，原则与实现不一致。
- 优点：输入守卫严格（symbol 唯一、数值有限、CLI 参数互斥）；明确区分"最大变现容量成本"与"小额赎回成本"；代理点差必须标为 proxy 并做敏感性分析；pass 只表示已执行的检查通过，证据不足时标为 insufficient-evidence；`runnable` 被注明为社区自评，不是官方验证。中英文 README 一致（英文版较简短）。
- 对 V1.2：GOLD 流动性好，但"参与率上限、平方根冲击、波动率口径必须写明"的原则可用于 RiskExecution 的滑点和冲击压力测试。脚本未审。
