# A211 skill-transaction-cost-analysis — Claude 全文审核（2026-11-05）

## P0248 尾段与 P0249 前段（FULL_READ：FILES 2108–2114，包括 portable-loader、examples/sample_report、README.en、README、references/methodology、requirements、SKILL）
- 定位：用分钟线重建区间 VWAP 和 TWAP，按 Perold 执行差额（IS）框架把成交成本拆成择时、冲击、点差、费用、滑点五项，单位为 bps。中英文 README 一致。样例数字已验算：0.54 + 0.13 + 11.63 + 4.90 + 4.35 = 21.55 bps，与报告吻合。
- **核心概念错误**：
  1. **五项相加有重复计算**：滑点定义为 `dir·(P−B)/B`，即成交价相对 VWAP 基准的残差。**这个实测残差已经包含了真实的半个点差和冲击**。在此之上再加模型估计的冲击 `k·σ·√(Q/ADV)` 和用分钟高低幅代理的点差，就把同一笔成本算了两次。标准的 IS 只有 `(P−A) = (B−A) 择时 + (P−B) 执行`，冲击和点差是对执行部分的**解释**，不能另外相加。
  2. **"主要成本是点差"是代理方法造成的**：样例中点差 11.63 bps 占总成本的一半以上，而文档自己承认"分钟高低幅包含区间内的价格漂移，通常**高估**点差"。结论的主因恰恰是那个被承认高估的代理值。
  3. **"五项之和等于总成本，对账闭合"是同义反复**：总成本本来就定义为五项之和，这个检查没有任何信息量。
- **其他问题**：
  - VWAP 基准包含本方自己的成交，参与率高时基准被自身成交污染，滑点因此被低估；
  - 到达价默认用"首笔成交前一根分钟线的收盘价"作代理，不是真实的决策时刻；
  - SKILL 写"无凭证时回退合成分钟线"，README 写"回退内置样本"，两份文档说法不一致，样本回退的风险与 A204 相同；
  - requirements 只有下限版本。
- 优点：方向约定统一为"对本方不利为正"；印花税写明自 2023-08-28 起卖出单边 5 bps，口径正确；港美股可用日线自带的 bid、ask 和 vwap。

## A211 结论
- 对 V1.2 的启示：MT5 成本核验要分开记录"实测滑点（成交价相对请求价或到达价）"和"点差与佣金"；**不能再把模型估计的冲击叠加到实测滑点上**。XAUUSD 零售规模的冲击可以忽略。脚本未审。

## 源码批次 S004（2026-11-06，FULL_READ：scripts 下 tca_decompose、benchmarks、data_source、tca_report、formatters，examples/run_demo，tests/test_benchmark_regression；未运行）
- **重复计算（CONFIRMED）**：`decompose_fill` 中 `total_bps = timing + impact + spread + fees + slippage`，其中 `slippage = dir·(price − bench)/bench` 是**实测**残差，`impact` 是模型估计的 `k·σ_day·√(qty/ADV)`，`spread` 是分钟高低幅的一半，三者直接相加。
- **对文档层结论的修正**：无 SDK 时回退到样本数据，这一点会写进报告的 `backend` 字段并显示在报告头部（"后端 sample"），**不是静默的**。SKILL 中"合成分钟线"的说法与代码不符，代码实际读取的是 `examples/sample_data/*.json`。
- **新发现**：
  1. **区间无数据时静默取最近一根 bar**：`MinuteBars.slice` 在区间为空时返回"离成交时刻最近的一根"，可能是另一个交易日，而且**不记 degraded**（因为 seg 非空）。
  2. **波动率静默回退且口径偏高**：样本不足时 `realized_vol` 直接返回 0.30，不记 degraded；分钟收益跨隔夜和午休连续计算，夜间跳空被当作分钟波动，σ 偏高。
  3. **ADV 包含本方成交**：`_minute_window` 只拉取成交当天的分钟线，`pad_minutes` 参数没有使用。ADV 用这些天的分钟量估计，包含本方自己的成交；分钟数不足时再外推，取两种估计中的较大者。
  4. **VWAP 基准含成交后价格**：VWAP 基准区间是成交时刻 ±15 分钟，包含成交之后的价格（这在区间 VWAP 中是常见做法，但会与择时项混淆）。到达价取每笔成交前一根 bar 的 close，代码并没有像文档写的那样取"首笔"。
  5. 冲击计算中算出了 `sigma_bar`，但没有使用，改用日尺度 σ；系数 k 默认 0.1，没有校准依据。
  6. **测试覆盖很窄**：测试只验证基准选择和买卖方向的正负号；`impact_coef=0` 且 `commission=0`，冲击、点差和"五项不重复"都没有测试。
- **结论更新**：A211 的总成本数字因重复计算而偏高，"主要成本来源"由被高估的点差代理决定，不能用于 V1.2 的 MT5 成本核验。可借鉴的只有方向约定（统一"对本方不利为正"）和 degraded 字段的设计。
