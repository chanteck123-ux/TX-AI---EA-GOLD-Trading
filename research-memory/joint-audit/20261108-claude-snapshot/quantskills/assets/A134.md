# A134 skill-macro-futures-scenario-analysis（宏观事件 → 期货三情景，社区项目，GPL-3.0-only）— 文本审核

范围：P0138 FILE 1399–1406 全文（portable-loader、CLAUDE.md、README.en、README、references/futures_contract、methodology、pandadata_contract、SKILL.md）。scripts/ 与 tests/ 不在计划内，**未读**。

要点：
- 链条：事件事实与发布时间 → actual / consensus / previous 与 surprise → 利率、汇率、增长、风险偏好 → 品种供需（库存、基差、期限结构）→ 价格、成交量、持仓确认 → 基准 / 偏强 / 偏弱三情景，每个情景都要有确认、失效、替代解释和置信度。
- PIT 规则：
  - as_of 是硬截止；
  - actual 只有在 pub_date ≤ as_of 时才可使用；
  - report_period ≠ 发布时间；
  - 主力合约按历史日期逐日解析，不能用今天的主力，不能自行拼接月份；
  - 结算价与收盘价不能混写。
- 每次调用都保留状态 envelope（ok / empty / error / unsupported）；禁止静默换源、插值，禁止统计胜率。

发现：
1. **PIT 精度只到日，事件发布却在日内**：
   - as_of 和 pub_date 都按 YYYYMMDD 比较；
   - 美国 CPI、非农在北京时间 20:30 / 21:30 前后发布，而国内期货日盘在 15:00 收盘，夜盘 21:00 开始且归入下一交易日；
   - 以"发布当日"为 as_of 时，actual 可以被当日日线（发布前已收盘）使用，等于把事件结果与事件前的收盘价混在一起；
   - 正确做法是用**带时区的时间戳**对齐到 bar 的开收盘时刻。文档写了"北京时间发布时间"字段，但比较规则只写到日期。（静态推导，未读代码。）
2. **夏令时**：美国数据的北京时间发布时刻随美国夏令时变化（如 CPI 在夏令时约 20:30，冬令时约 21:30），文档没有提到 DST。
3. **surprise 没有标准化**：`surprise = actual − consensus` 是原始差值；不同事件、不同时期不可比，也无法判断"大幅超预期"。没有按历史 surprise 标准差归一化，"大小"只能靠主观判断。
4. **consensus 来源与时点未定义**：预期值取哪一刻的快照（发布前一周还是发布前一刻）、来自哪个机构，文档没有说明；consensus 若事后被更新，也会前视。
5. 字段命名混乱：`revision = previous_value（仅作前值背景，不当作修订值）`——名为 revision 却不是修订值。
6. 置信度（高/中/低）没有校准方法；文档禁止写概率和胜率，置信度因此只是主观标签。
7. 机制示例（CPI 超预期 → 实际利率和美元上行 → 黄金承压）是常识模板，文档也注明"仅机制模板"。
8. 运行依赖特定的 MCP 工具名（mcp__pandadata__call_pandadata）和 python3.11；默认事件代码 USA.004 = 美国 CPI，**未核实**。
9. 数据层与降级纪律完整，"SDK 中有方法 ≠ 账号可用"、以 --probe-only 实测为准，做法良好。
