# A171 skill-qbti — Claude 全文审核（2026-11-05）

## P0211 后段（FULL_READ；FILES 1752–1756：portable-loader、README.en、README、disclaimer_template、profile_schema）
- 定位：面向非专业用户的"投资人格"问卷。五组问题（亏损反应、参与度、策略口味、选股范围、时间周期）的答案落到封闭枚举上，由固定映射表 `preference_mapping.yaml` 确定性地转成因子方向、单票仓位上限（5–15%）、调仓频率和持有期，再交给因子库和 skill-backtest。中英文 README 及免责声明逐段对照，内容一致。
- 优点：
  - 采用"问法可自由发挥，枚举固定"的契约；
  - 映射是确定性的（纯标准库脚本，不联网、不用 LLM）；
  - 拒答使用默认值，并必须记入 `defaults_used` 后念给用户；
  - 调整只能往更保守的方向；
  - user_confirmed=false 时不生成 brief；
  - 免责声明必须原样出现在两个位置。
- **问题**：
  1. **"只翻译、不推荐"是措辞上的规避**：通过心理问卷评估风险承受力，再映射成仓位上限、止损纪律和因子方向，实质上就是**适当性评估加个性化参数建议**，在很多司法辖区属于受监管的投顾活动。免责声明不能改变它的实质。strategy_brief 中的字段名就叫 `recommended_next_skills`，自己就用了"推荐"一词。
  2. 用"养柯基还是多肉""追热剧"之类的比喻包装风险问题，会弱化用户对风险的认真程度；"亏损反应"只有一道题，就决定了 risk_tolerance 和 max_position_pct，**单题定档**的测量信度很低。
  3. `discount_buy_more`（下跌就加仓）被映射为激进档，但"越跌越买"这种行为模式本身就是风险信号，规则表的处理方式值得商榷（preference_mapping.yaml 不在本清单内，具体映射未审）。
  4. 单票上限 5–15% 只限制个股，没有组合级回撤预算或杠杆约束；回测交给其他技能，本技能不验证结果。
- question_bank.md 和 SKILL.md 在 P0212 中，待读。

## A171 结论
- 产品设计上有不少严谨之处（枚举契约、确定性映射、只往保守方向调整、默认值必须披露、免责声明两次原样展示）。核心风险在于用措辞规避来处理**个性化适当性**问题："翻译不是推荐"并不能改变把问卷结果映射成仓位和止损参数的实质。
- 与 V1.2 无直接关系，但"用户偏好只能把风险往保守方向调，绝不能加大授权风险"的原则，与本项目"固定表不自动扩大已授权风险"的规则一致。
