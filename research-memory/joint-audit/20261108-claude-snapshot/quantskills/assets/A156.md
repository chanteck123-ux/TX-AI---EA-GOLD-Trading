# A156 skill-pandaai-workflow-audit — Claude 全文审核（2026-11-04）

## P0163（FULL_READ；FILES 1646–1651：portable-loader、README.en、README、audit_rules、disclaimer_template、pandaai_workflow_format）
定位：对 PandaAI 导出的工作流 JSON 做静态"代码审查"。范围包括图完整性、代码语法、负向 shift、同 bar 信号与成交、硬编码标的池、可调参数数量、回测窗口、零成本、隐式外部数据、未设随机种子、缺少运行结果。

**优点（方法论质量高）**：
1. **静态结论与经验结论严格分开**。静态审查可以断言：负 shift 泄露、图断链、可调项多、硬编码池、缺少证据。静态审查不得断言：过拟合概率、未来收益、高夏普能否扛住多重检验、跨未知环境的稳定性。
2. **证据不足不等于通过**：`insufficient-evidence / unassessable / static-only`，并明确"不表示通过"。
3. **evidence 类发现不计入 static_risk**；对每个导出都成立的格式固有事实（如未知试验次数）记为 info，不算缺陷。
4. 每条发现必须包含四项：可证伪的缺陷陈述、证据、影响、优化方案。禁止"可能过拟合，请注意"这类空话。
5. `credible-under-tested-conditions` 不得简称为 credible 或 safe。
6. 历史工作流版本只给出试验次数的下界。
7. 前端导出的 `output_db_id` 为 null，`task_id` 为占位"error"。因此前端导出通常只能达到 static-only，这是诚实的格式限制说明。
8. 不执行工作流内嵌代码；DSR/PBO 交给 skill-backtest-overfit，不重复伪造统计量。

**缺陷与疑点**：
1. "疑似同 bar 信号与成交"的检测是启发式，审计脚本未读（清单不含 .py），检测能力**未核实**。
2. 免责声明要求"原样展示、不得改写"，属于模板约束，不涉及研究质量。
3. portable-loader 要求运行 `audit_workflow.py`；按本审核边界未运行。

**对 V1.2 的可借鉴点**：
- 判定语义可映射到 EA 研究状态的分离：insufficient-evidence ≠ pass，与"未执行不得写通过"一致。
- static_risk 与 evidence 分开计分，可对应 SCORE_TARGETS_UNSET / N/A 的处理。
- 发现四要素格式可用于 Critic 复审记录。
