# A037 skill-backtest-assumption-check（全文审核笔记）
- 读取（P0039）：agents/portable-loader.md、README.en.md（其余文件见后续包）。
- 内容：回测假设审计器，九个审计轴：执行时点与前视、成本、涨跌停与停牌、幸存者偏差、参数自由度与多重检验、数据对齐与复权、换手与容量、基准与超额收益、报告透明度。每项给出 PASS/WARN/FAIL/INFO 和 BLOCKER/MAJOR/MINOR/INFO 严重度。
- 好的做法：**每个缺陷都必须有证据（代码行或检测器输出），没有证据就不下结论**；输入缺失时该轴降级为 INFO（证据不足，建议补充材料），**不猜测**；只审计，不改写代码，也不为结论背书。
- 对本次审核的意义：A36 的参考实现正好可以作为这个审计器的测试对象——第 1 轴（执行时点）应判为 BLOCKER。
- 续读（P0040）：README.md、references/{audit-axes, evidence-collection, fix-library, report-format, severity-model, source_boundary}.md、scripts/requirements.txt、SKILL.md。
- **方法价值高（可直接作为本项目审核模板）**：
  - 九个审计轴，每轴写明"判定什么 / 证据来源 / PASS-WARN-FAIL-INFO 标准 / 修复 / 复检动作"。
  - **严重度模型**：BLOCKER = 系统性机制错误（前视、零成本、当前成分回填、基准错配）；MAJOR = 改变量级或排序；MINOR = 透明度不足；INFO = 证据不足。总体可信度：≥1 个 BLOCKER 即"不可采信"。"不要把所有缺陷都标成重大"；"严重度要结合换手判断"。
  - 每个缺陷必须有 5 个要素（缺陷、证据、严重度、影响、修复），证据必须精确到"文件:行"或探测器输出的数值。
  - grep 命中只是线索，必须读上下文确认或排除。
  - 每项修复都附带复检动作（例如重跑前缀回放，确认 close→close 与 T+1 开盘两条曲线不再重合）。
- **独立发现（文档层面）**：
  - ①**以错误的基线为基准**：判定基线"对齐生态 skill-backtest 标准协议"，但 A36 的参考实现本身违反了这个协议（以 T 日收盘入场）。审计器依据的是协议文字，不应把 A36 的代码当作正确实现。
  - ②轴 6 的修复建议"统一前复权口径"：前复权价格的历史**水平值**会随之后的分红而改变，用价格水平（而不是收益率）构造的信号会吸收未来的公司行为信息；对涨跌停判断也不能使用复权价（见 A21）。正确的说法应该是：收益用复权，价格水平和涨跌停用未复权，或使用 PIT 复权因子。
  - ③元数据中 repository 指向个人仓库（`wangofcong/...`），与组织仓库名称不一致，来源归属需要核对。
  - ④探测器和自检脚本在 scripts/ 中（.py 不在本次文本清单内），**未做静态实现核查，未运行**。
- **A37 逐资产结论**：本批资料中最可直接借鉴的审计方法之一。
- 对黄金 EA：建议把九轴审计（改写为 XAUUSD 版本：执行时点与延迟、点差/佣金/隔夜费、交易时段与休市、合约规格历史、参数自由度、数据质量（tick 覆盖）、容量与滑点、基准、透明度）作为 Critic 复审的结构化模板——**候选，需登记后才生效**。
