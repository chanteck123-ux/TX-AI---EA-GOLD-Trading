独立发现（静态阅读）：
1. **取整方向会突破风险预算**：`contract_count = round(exposure_notional / contract_notional)` 四舍五入。对冲场景可以接受；但用于"CTA 风格仓位 sizing"（风险预算）时，向上取整会使实际风险超过预算。风险上限约束应向下取整（floor），并报告剩余敞口。SKILL 虽要求"说明取整误差"，但公式本身没有区分两种用途。
2. **公式不完整或符号不明**：
   - `roll_pnl = next_contract_price − front_contract_price` 只是价差，没有乘以张数和乘数，也没有区分多空方向（多头在 contango 下支付、空头收取）；
   - `basis_pnl = futures_return − spot_return` 没有说明对冲方向（空期货时符号相反）；
   - `trade_ok = margin_safe + liquidity_ok + …` 用加号表示逻辑与，属于记号不严谨。
3. **"验证"只是格式检查**：check_test_cases.py 与 A083 完全相同，只检查用例标题数和标记字符串，不验证任何计算（同 A083 发现 1）。
