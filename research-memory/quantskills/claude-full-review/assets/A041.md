# A041 skill-block-trade-radar（全文审核笔记）
- 读取（P0042）：agents/portable-loader.md、README(.en.md, .md)（SKILL.md、playbook 见后续包）。
- 内容：A 股大宗交易折溢价雷达。折溢价率 = 成交价 / 同日收盘价 − 1（不是接口字段，由本技能计算）；"机构专用"在买方视为接盘、在卖方视为出货，属于匿名席位，不指名；`buyer == seller` 视为对倒或过券，单列并从方向净额中剔除；先按 symbol + date 聚合，再排榜。
- 好的做法：
  - 每个折溢价都写明计算基准（get_stock_daily 的同日收盘价），收盘价缺失时标记"待补"并剔除，**不估算**；
  - 扫描结果是某个时点的快照，必须标注时间；
  - 定时任务幂等（同名报告覆盖重写），非交易日跳过；
  - 有 validate_report.py 校验报告结构。
- **独立发现**：`buyer == seller`（同一营业部）不一定是对倒——同一营业部下的不同客户也可以是买卖双方。规则把这类成交全部剔除出方向净额，会把真实的营业部内部撮合一并排除。作者已经用"对倒式提示"的措辞表达不确定性，但聚合时仍直接剔除。
- 对黄金 EA：领域不相关。可借鉴：①派生指标必须写明计算基准，基准缺失就标记待补，不估算；②定时任务幂等。
- 续读（P0043）：references/block-trade-playbook.md、SKILL.md。
- 补充：
  - 折溢价分档（≤−5%、−5%~−1%、±1%、>+1%）明确标注为"约定"，可调整；
  - 当日收盘价缺失时**绝不静默用前一日收盘价替代**，并说明剔除了多少笔；
  - 成交日期不是交易日时要注明，而不是静默删除；
  - "不要过度解读单笔"——先聚合，看是否重复出现，再谈模式；
  - 方向只是"倾向"，不代表身份。
  - status: draft，validation_level: runnable。
- **A41 逐资产结论**：规则清晰、边界意识强。validate_report.py 不在清单内，**未做静态实现核查，未运行**。对黄金 EA 的价值仅限于方法层面（派生指标标注基准、缺失值不静默替代）。
