# A019 skill-a-share-pit-fundamental-vintage-builder（全文审核笔记）
- 读取（P0021）：agents/portable-loader.md、README(.md, .en.md)、references/{data-contract, factor-definitions, research-boundaries}.md。
- 内容：从财报版本时间线重建时点（PIT）面板，只回答一个问题：某个历史调仓日使用的财报，当时是否已披露且可交易？
- **方法（高质量）**：
  - `eligible(T) = {v | disclosure ≤ T 且 available ≤ T}`；`available` = 披露日之后的首个交易日（严格大于，T+1）；`PIT(symbol, quarter, T)` 取符合条件的最新版本。
  - 每行保留数据血缘：quarter、disclosure_date、available_date、as_of_date、vintage_type。
  - 同一证券、财报期、披露日存在无法区分的版本时 **fail closed**，要求补版本标识。
  - NaN 保持缺失，不填 0。
  - 单季值 = 当期累计 − 上一季累计；TTM 必须是连续 4 季，否则为 NaN、不做推断；按 (symbol, as_of_date) 分组，防止后来的修订泄漏进早先的快照。
  - 静态审计检查 `is_latest=True`、负数 shift、缺失快照；作者明确说明"静态检查只是证据，不能证明无泄漏"。
- **作者实测的 SDK 注意事项**：`get_trade_cal` 实际返回 nature_date/is_trade；若在 fields 参数中请求文档写的 date/is_trading_day，会返回空表——文档与实际行为不一致。另外，单次请求最多 20 个季度。
- 自述局限：不处理幸存者偏差、公司行为、退市收益、成本和流动性；没有日内发布时间戳，因此无法建模当日可交易。
- 对黄金 EA：没有财报，但**严格 T+1 的可得性公式与数据血缘字段**可直接借鉴到 NR08 新闻/经济日历：每个事件记录 发布时间 / 首次可用时间 / as_of / 版本（初值或修正值）；经济数据的修正值不得回填进历史信号（vintage 问题）。这是候选设计要求，**尚未登记、未实现**。
- 续读（P0022）：SKILL.md。补充：
  - 审计要求每个 as_of_date 分区中每个 (symbol, quarter) 只有一个版本，且每个调仓日都有快照。
  - `is_latest=True` 和负数 shift 判为**确定性错误**；`bfill` 和向前的 `merge_asof` 只判为警告，需要结合语境复核。
  - 审计结论分三档：可信 / 存在风险 / **无法确认**；只提供面板时，只能检查数据时点，不能证明整个策略无泄漏。
  - 文档记录的 `get_stock_disclosure_date` 在 SDK 中不存在。
  - validation_level: listed（低于 runnable）。
  - ⚠ 登录脚本示例为 `powershell -ExecutionPolicy Bypass -File ...`，并把凭据**保存到 Windows 当前用户环境变量**（明文持久化）。这是资料内容，本次不执行；如果项目要借鉴，凭据存储方式需另行评估，不能照搬。
