## P0101 部分（FILE 986–988 全文：agents/portable-loader.md、README.en.md、README.md）

要点：
- 一轮式因子池进化：评估 seed 因子（RankIC/RankICIR）→ 取前 50% 为强池 → 对全部因子生成 mutation，对强池与低相关伙伴做 crossover → 由当前 LLM 填写候选 → 统一评估排序 → 推荐下一轮。
- 可反复调用以逐轮进化。
- 设计灵感来自 CogAlpha（arXiv 2511.18850，资料引用，未外部核实），声明并非完整复现。
- 内置 vendor 的 Alpha101/Alpha191 运行时，保留原许可。

初步发现（文档静态阅读，未运行）：
1. **重复调用的累积选择偏差**：每轮都在同一数据上用 RankIC/RankICIR 选强池和推荐因子，再作为下一轮 seed。多轮之后，推荐因子相对该数据段高度过拟合。README 只在边界中写"仍需样本外验证"，没有在流程中内置留出段（需核对 input_schema 与 evolution_rules 是否有评估区间切分，待后续 pack）。
2. "相关性只作诊断，不作推荐的硬过滤"与 A084、A075 把 |ρ|≥0.85 设为硬门槛的做法不一致。推荐列表可能包含高度同质的候选（同 A082 的等价变体问题）。
3. 第三方 vendor 代码许可分开保留，记录较规范。

## P0102 补读（FILE 989–992 全文：references/evolution_rules、input_schema、output_contract、SKILL.md）

独立发现（续，静态阅读，未运行）：
4. **确认无时间切分**：input_schema 只有一个 `market_data_csv_path`。seed 评估、强池选择、候选评估与 top-k 推荐都在同一份数据上完成，没有 train/valid/test 或区间字段。推荐的 `next_round_custom_seed_factors.json` 进入下一轮后继续在同一数据上选择（确认发现 1）。
5. **方向在样本内事后决定**：`use_abs_metrics` 默认为 true，按 |RankIC|、|RankICIR| 打分；随后按 RankICIR 的符号给出 `recommended_sign`（±1），下一轮"考虑翻转"。方向选择与评估使用同一数据，相当于双倍搜索（同 A082 flip-sign）。
6. **排序口径不一致**：
   - SKILL 第 3 步：强池按"RankICIR 主、RankIC 次"排序；
   - 第 4 步与 evolution_rules：候选按"RankIC 主、RankICIR 次"排序。
7. **相关性过滤自相矛盾**：SKILL 与 evolution_rules 说 maxCorr"只作诊断、不参与推荐过滤"；input_schema 却有 `recommendation_use_abs_corr`，说明是"是否按绝对相关性应用推荐**去重阈值**"，暗示存在去重过滤。哪一个是实际行为需看脚本（未核查）。
8. **LLM 生成代码被直接执行**：候选因子以 Python `code` 字符串提交，由"内置轻量执行器"运行（自定义 seed 也一样）。文档没有说明沙箱、导入白名单或禁止 I/O 的强制机制（A081 handoff 只有文字约束）。这是任意代码执行风险。
9. 数值口径：
   - `min_cross_section_samples` 默认 3，截面 IC 噪声极大；
   - 缺少 vwap 与 amount 时，底层库以 `close×volume` 代替 amount，推导出的 vwap = amount/volume ≡ close，vwap 类因子会无提示地退化（同 A072）。
10. 诚实度：SKILL `status: draft`；evolution_rules 明列"未实现完整多轮 loop、adaptive feedback、quality checker 等"。
