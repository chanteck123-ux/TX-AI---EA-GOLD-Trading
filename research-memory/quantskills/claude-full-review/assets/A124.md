要点：
- 对标准化日内 OHLCV 做确定性检查：
  - 时间戳乱序与重复；
  - 组内缺口（间隔 > 1.5 × expected_seconds）；
  - OHLC 不变量；
  - 非正价格、负成交量；
  - 交易日错配。
- 分组键为 symbol + trading_date + session，不跨午休、跨日或跨夜盘比较。
- 夜盘需显式标注；同组内时区感知必须一致，混用则判为证据不足。
- 缺口只作待核查标记。

独立发现（静态核查确认，**未运行**）：
1. **按时间戳字符串排序与去重**（227 行附近 `sorted(... key=timestamp 字符串)`，`seen` 集合同样存字符串）：
   - 若同组内都带时区但偏移不同（如 +08:00 与 +00:00），字符串顺序并不等于真实时间顺序；
   - 同一时刻用不同偏移表示时，不会被识别为重复；
   - 混用检查只看"是否带时区"，不看偏移是否一致；
   - 结果可能是缺口与乱序的误报或漏报。
2. **缺失数值被静默替换为 0**（49–54 行 `number()` 默认返回 0.0）：
   - 价格缺失 → 0 → 报为 `non_positive_price`，标签不准确，但至少被标出；
   - **成交量缺失 → 0 → 视为合法**，不会报出；
   - 应单独报告 `missing_value`。
3. **只检查组内缺口，不检查时段边界**：
   - 某时段缺失开头或结尾若干根 K 线，不会被发现；
   - 整个时段或整天缺失也不会被发现，因为没有分组就不会产生发现；
   - 文档承认 `get_trade_cal` 不提供盘中时段，但没有用 future_detail 的 trading_hours 或交易所时段规则检查首尾。
4. **没有检查停滞或重复 K 线**：例如连续多根 OHLC 完全相同且成交量为 0，或报价冻结。这类问题对外汇、黄金、CFD 数据最为常见，属于缺口之外最重要的质量问题。
5. **没有检查 K 线时间戳的标注口径**（开始时间还是结束时间），而这是跨数据源对齐时最常见的偏移来源。
6. 设计上的优点：不修改原始数据，缺口不直接定性为错误，夜盘需显式标注，参数非法时输出 insufficient-evidence，而不是伪造"通过"。

与黄金 EA 的关系：**直接相关（数据质量）**。本项目 LEAN 与 MT5 的 M5/Tick 数据核验可以借鉴以下检查清单：
- 按真实时间（UTC 或券商服务器时间）而不是字符串排序和去重；
- 缺失值单独报告，不填 0；
- 对照 FxPro 服务器时间的 GOLD 交易时段，检查时段首尾与整段缺失；
- 检查停滞报价与 0 tick-volume 的连续 K 线；
- 明确 K 线时间戳是开盘时间还是收盘时间（MT5 为开盘时间），并与 LEAN 的 bar 结束时间约定对齐；
- 周末与日内休市（服务器时间每日约 1 小时）列为预期缺口。

以上是**检查设计建议**，不代表已在本项目实现或运行。
