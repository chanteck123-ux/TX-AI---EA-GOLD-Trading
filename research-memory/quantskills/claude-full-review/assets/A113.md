## P0121 部分（FILE 1241 portable-loader、1242 README.en、1243 README 全文）

中英文 README 逐段对照，内容等价。

要点：
- 港股、美股目标价与评级在 5 个回看期（周、1/3/6/12 月）的修订轨迹矩阵；
- 规则化状态机："持续上修"、"共振"、"高分歧待核验"等，状态不改变排名；
- 离线单文件 HTML，无 CDN；
- 核心股票池只包含确认在市的普通股；
- 缺失值不填补；
- 现价按标的逐个回退，最多 14 个自然日。

限制写得较诚实：
- 只有聚合一致预期；
- 没有业务日期；
- 不做 FX 归一化；
- 不考虑公司行动。

独立发现：
1. **拆股或合股会造成伪修订**：
   - 修订 = 当前目标价均值 / 回看期目标价均值 − 1；
   - 若回看期内发生拆股（例如 1 拆 10），历史目标价未复权时会出现约 −90% 的"下修"，并进入下修榜；
   - 文档把公司行动列为范围外，分红与拆股事件"仅作解释、不改变排名"，因此这类伪信号**不会被剔除**；
   - 至少应把窗口内有拆股/合股的标的从修订榜排除或标注（需看源码，未核查）。
2. **现价最多回退 14 个自然日**：用于"价格偏离"时，可能用两周前的价格与当前目标价比较。报告会披露回退，但排名中没有按回退天数降权或排除。
3. **评级均值方向**：PandaData 评级均值越低越积极，"评级变化 = 历史 − 当前"，为正表示改善。这种方向约定容易被误读，文档已说明。
4. `--revision-threshold` 称为"绝对变化阈值"，但修订是比率，实际上指 |比率| ≥ 0.01。用词不够精确。
5. 登录：11 位手机号自动加 86；有 GUI 登录窗口；只把短期 token 传回主进程。凭证处理比同套件的其他资产谨慎。
6. 与 A112 的关系：A113 承认一致预期没有业务日期，可以用来更正 A112 的"数据日"要求（见 A112 发现 2）。

与黄金 EA 的关系：无。

## P0122 补读（FILE 1244 methodology、1245 pandadata-api-map、1246 requirements、1247 SKILL.md 全文）

补充要点：
- 公式完整：
  - tp_revision_h = 当前/历史 − 1；
  - 方向阈值 ±1%，**严格**大于阈值才算方向；
  - 分类按全精度判断，不看显示时的四舍五入。
- 校验只标记，不修改源值：
  - low ≤ mean ≤ high；
  - included ≤ estimates；
  - 评级桶之和对比总数（不一致只作警告）；
  - 评级均值在 1–5 之间。
- 币种：只有在目标价币种 = 市场标准报价币种（HKD/USD）时，才进入价格偏离榜。
- 覆盖变化"显著"：|Δ| ≥ 2 且 |Δ%| ≥ 20%，只作提示。
- 时点：明确写出聚合一致预期**没有** date、as_of、updated_at；后缀是"提供方定义的比较字段，不是推导出的日历日期"——这与 A112 的发现 1、2 互相印证。
- 资格漏斗是链式 mask，最终计数必须等于榜单池的大小。

独立发现：
1. **"上修加速"与"上修减速"的定义比较的是嵌套窗口的累计变化，不是速率**（文本推导）：
   - 加速：周变化 − 1 月变化 > 阈值，且两者都为正。周累计变化大于月累计变化，意味着 TP(1周前) < TP(1月前)，即第 2–4 周目标价是**下降**的，最近一周才回升——这更接近"V 形回升"，而不是加速；
   - 减速：1 月变化 − 周变化 > 阈值。若一个月内匀速上修（月 +4%，周 ≈ +1%），也会被判为"减速"。
   
   合理的比较应是周变化对比月变化 ÷ (约 4.3 周)，或者比较不重叠区间（最近一周对比前三周）。**状态标签可能误导**；但状态不改变排名，影响限于解读。
2. **拆股/公司行动的伪修订已确认**：methodology 中"The method ignores corporate actions"，SKILL 中的公司行动也被排除在范围外。拆股事件只是上下文，不改变排名。P0121 的发现 1 成立，属于文档内可确认的设计缺口（源码未核查）。
3. "持续上修（短期三个窗口至少两个正向）"没有写明是哪三个窗口（推测为周、1 月、3 月）。"趋势反转待核验"中的"任一较长窗口"则包含 12 月，覆盖范围很宽。
4. 高分歧阈值使用当期有效样本的 P75，是相对阈值，每期总会有约 25% 的标的被标记，不代表分歧的绝对水平。
5. 认证设计：凭证保留在进程内存，不生成 user.json，本地回环只转发 token，失败时双字段都要重新输入。在套件中属于最谨慎的一类。SKILL 要求 Codex 遇到非 TTY 时加 `--desktop-login-window`——这是给代理的操作指令，本审查**未执行**。
