# A034 skill-b6-limitup-pool（全文审核笔记）
- 读取（P0036）：agents/portable-loader.md、README(.en.md, .md)、SKILL.md、开发产物/references/api_guide.md（开发版 SKILL.md 等见后续包）。
- 内容：A 股涨停池的盘后维护：连板状态机（停牌不算断板）、炸板与回封（优先分钟线，缺失时降级为日线代理并在 `seal_metric_source` 中标注）、题材分组（概念成分按 in_date PIT 过滤）、特殊形态、情绪指标（分层晋级率、炸板率、昨日涨停今日表现）。
- 好的做法：
  - 每行标注**计算来源**（minute 或 daily_proxy），代理值的时间字段留空而不是编造；作者明确要求"日线代理不得表述为分钟级事实"。
  - 分钟线连续失败 3 次以上时整体降级，主流程不中断；错误码有对照表。
  - 烂板判定附注了一个误判陷阱：全天稳封的股票 final_seal ≈ 15:00，必须先炸开过才算"尾盘回封"。
  - 作者公开已知问题：同一交易日重跑后会残留旧行（issue #2）——**幂等性缺陷**。
- **独立发现（文档层面，未运行）**：
  - ①**与"同源"声明不一致**：文档称涨停判定"口径同 alpha-A3，保持同源以避免漂移"，但这里用 `close ≥ eff_limit_up × 0.9999`，A26 的 data_guide 用的是 `× 0.999`——**已经漂移**。
  - ②**ST 涨跌幅与 A21 冲突**：这里的兜底规则把主板 ST 写成 5%（没有日期区分）；A21 称自 2026-07-06 起主板 ST 改为 ±10%，并要求按 bar 日期取规则。两者至少有一个过时（是否真的发生了这项改革，**本次未独立核实**）。好在 B6 剔除了 ST，并优先使用接口提供的 limit_up，所以实际影响有限。
  - ③**取整方式**：兜底价用 `round(pre_close × (1 + rate), 2)`。如果在 Python 中实现，内置 round 采用银行家舍入，而交易所用 ROUND_HALF_UP（见 A21），两者在 .005 边界上会不一致（源码不在清单内，未核实）。
  - ④**分钟级"封板"的定义是近似**：`sealed(t) = minute.high ≥ 涨停价`——一分钟的最高价触及涨停不代表这一分钟都封住，炸板次数只能按分钟粒度估计，分钟内的开板和回封看不到。所以即使是 minute 来源，也只是近似值。
  - ⑤概念成分只按 in_date 过滤，没有处理剔除日期（同 A26 ⑧）。
  - ⑥README.en 写"pre-close maintenance tool"，中文版写"盘后"，说法不一致。
- 对黄金 EA：
  - ①**每个指标都标注计算来源和精度**（例如 tick、M1 或 M5 近似），代理值不能冒充高精度事实——对应我们 History Quality ≠ 真实 tick 覆盖的规则；
  - ②**重跑必须幂等**（同一 run_id 或日期重算时先删后写，或采用版本化写入）——对应 Codex 的 MT5 测试队列和我们的状态持久化；
  - ③声称"同源"的口径必须用代码共享或常量单一来源，不能靠复制文档。
- 续读（P0037）：开发产物/SKILL.md、生产产物/SKILL.md。补充：
  - 生产包中的 database.parquet **声明了来源**：真实 PandaData 复盘样例，覆盖 2026-06-18 至 06-24，data_version 已标注，可以用 backfill 重建，"不是测试桩或合成数据"——这种来源声明值得借鉴（对应我们"随包报告必须注明来源和运行"的要求）。
  - **独立发现**："必须先 `test.py` 全绿；真实数据因流量超限或权限不足会自动跳过（不判失败）"——**跳过 ≠ 通过**。全绿时真实数据冒烟测试可能根本没有执行，报告应把 skipped 与 passed 分开列出（对应七状态中的"未执行"）。
  - 生产文件用追加合并，结合 README 中的已知问题（重跑残留旧行），追加模式本身就是幂等性问题的来源。
