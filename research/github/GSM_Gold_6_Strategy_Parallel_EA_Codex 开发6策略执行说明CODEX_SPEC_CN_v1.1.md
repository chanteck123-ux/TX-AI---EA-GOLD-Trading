### 2.2 扫描与调度

“同时”是六策略持续启用并在各自数据更新时得到调度，不要求 MQL5 创建六条线程。每次事件处理应覆盖所有需要更新的引擎；不得 `if S1成立 else if S2成立`，不得第一单发出后直接跳过其余五个引擎。

## 3. 可实现的六策略首轮研究定义

本节用于补齐用户给出的策略名称，并不是已验证的交易优势。若仓库已有用户确认的同名 SOP，先做来源映射，再明确采用 SOP 版还是研究定义版；每个 run 固定一个 `rule_version`，禁止混用。

### 3.1 通用数据和入场规则

- 默认指标均用已收盘数据。禁止通过未收盘高周期的最终 OHLC 或后来确认的 pivot 回写过去信号。
- `ATR14`、EMA、ADX、布林带采用 MT5 标准定义；使用哪个周期、哪个 buffer 和 shift 必须写清。
- 结构价格基于该品种图表报价；执行 BUY 用 Ask、SELL 用 Bid，平仓估值 BUY 用 Bid、SELL 用 Ask，不能混成相同价格。
- `ATR14_prev` 表示信号 K 线之前已完成的 ATR，避免用当根大 K 线反向调整其门槛。
- 初始研究版默认在确认后的下一次可交易 Tick 市价申请入场。若原 SOP 明确要求 Limit/Stop，则保留该策略的挂单路径；不从其他非农 EA 引入“全部只能挂单”。
- 新鲜度：M5 触发的市价候选，默认仅在下一根 M5 内有效；M15 确认仅在下一根 M15 内有效；H4 确认仅在下一根 H4 内有效。超过有效期须重新取得新触发，不能延迟数小时照旧开。
- 最大追价偏离首轮为触发周期 `0.25×ATR14_prev`；仅限制执行位置，作为独立研究参数记录。无 Tick/报价不合法时不发送。
- 初始结构缓冲首轮为 `max(2×tick_size, 0.20×ATR14(结构周期))`；SOP 已有固定缓冲时以 SOP 为准。保护价不合法时放弃或按规定重算风险，不能偷偷缩短止损。
- 本节统一采用有初始 SL/TP 的单次独立 Setup；禁止马丁、网格、因浮亏补仓。S4 第二仓必须有新 Setup ID，不能复制第一仓或连续 Tick 刷单。
- 每个 Setup 只在其结构、方向、确认时间与有效期内有效。独立 Setup 的唯一标识至少含策略、品种、方向、结构 ID 和触发 K 线时间。

### 3.2 S1：H1 趋势＋M15 回踩＋M5 触发

BUY 首轮规则：

1. 最近收盘 H1：`EMA20 > EMA50`、`Close > EMA20`，且 H1 EMA20 高于三根 H1 前的值。SELL 完全镜像。
2. 新收盘 M15 与 EMA20 附近 `±0.25×ATR14_prev(M15)` 区间发生重叠，且 BUY 收盘重新站在 EMA20 上方；记录该根回踩 K 的高低和确认时刻。
3. 回踩候选最多等待 3 根后续 M15；期间若 H1 方向失效或价格跌破计划结构 SL，候选失效。
4. 仅在回踩确认之后，新收盘 M5 出现阳线且收盘高于前一根 M5 高点，建立 BUY 触发；SELL 用阴线收盘跌破前一根低点。
5. BUY 初始 SL 取回踩 M15 与触发 M5 两者最低价以下加结构缓冲；SELL 镜像。初始 TP 为 2R。

S1 的 H1、M15、M5 条件是本策略自己的要求，不引入其他 EA 的“任意 2/3 共振”替换它。一个回踩候选最多完成一张独立仓位，平仓后等待新的回踩对象。

### 3.3 S2：Supply/Demand First Touch

H4 与 H1 独立检测区域，M15 负责回触确认，不强制 H4/H1 同方向。

首轮区域程序定义：

1. Base 为离开 K 前连续 1～3 根已收盘 K；每根实体/全幅 ≤0.50，Base 总高低幅度 ≤0.80×离开前 ATR14。零波幅 K 线拒绝参与。
2. 上行离开 K：阳线实体 ≥1.0×离开前 ATR14，收盘高于 Base 最高价至少 0.30×ATR，形成 Demand；下行镜像形成 Supply。
3. 同一离开 K 有多个 Base 长度满足时，首轮固定取最短者；区域边界固定为整个 Base 的最低/最高价。区域 ID 含形成周期、Base 起止和离开 K 时间。
4. 只有离开 K 收盘确认后区域才存在。价格须先位于区域外，才能记录之后的首次回触；过往形成后的触碰必须计入历史，不能因为 EA 刚启动而都认作 fresh。
5. 首轮区域最长有效期为形成周期 60 根 K。对 Demand，形成周期收盘跌破远端加缓冲即失效；Supply 镜像。首次回触期间如果价格直接穿越计划 SL，候选立即失效。
6. Tick 触区用图表 Bid 轨迹判定是否进入/穿过区域；BUY 实际 Ask 仍须落在可接受执行范围。跳空直接越过远端，不伪造一次可成交的区域内触碰。
7. 第一轮触碰开始后，最多等 3 根新收盘 M15：Demand 要求阳线且收盘高于区域中点；Supply 要求阴线且收盘低于中点。只接受收盘时间晚于首次回触开始的确认。
8. 初始 SL 在区域远端之外加形成周期缓冲；TP 首轮为 2R。

First Touch 是一次持续的市场回触事件，不是一个 Tick，也不是每根 K 重新计数。首次事件结束、超时、结构失效或成功成交后均不能再次当新鲜区。可执行的明确拒单重试只能发生在同一未失效事件内；超时未知先对账，不重发。

若历史长度或状态缺失，无法确认区域自形成以来是否已触碰，标 `FRESHNESS_UNKNOWN` 并只拒绝该区域的新单；不能把所有区重置为 fresh。缺失数据恢复后重新核对，其他引擎不因此停止。

多个区域可独立保存状态；实际槽位有限时，优先最早有效触发，平时展示最近合法区域；等距/等时固定按形成时间和周期处理并记录，不做信号方向投票。重新选区不清除被替换区域的触碰历史。

### 3.4 S3：突破后回踩

1. 在每个 M15 突破检测时刻，固定取当时已收盘的最近 20 根 H1 高点最大值为上沿、低点最小值为下沿。不得把未来 H1 数据纳入窗口。
2. BUY：新收盘 M15 收于上沿以上至少 `0.15×ATR14_prev(M15)`，且上一根 M15 未收在同一上沿之上，登记一次突破事件。SELL 镜像。
3. 必须等待突破确认之后的 M15 回踩：价格区间与突破位 `±0.25×突破时ATR` 重叠，BUY 收盘守住突破位上方；SELL 镜像。突破 K 本身不兼任回踩 K。
4. 最多等待 8 根 M15 完成回踩及触发。BUY 若 M15 收盘低于突破位减 `0.50×突破时ATR`，失效；SELL 镜像。
5. 回踩确认后，新收盘 M5 阳线突破前一根 M5 高点才 BUY；SELL 镜像。
6. BUY 的 SL 在回踩低点以下加 M15 缓冲；TP 首轮为 2R。突破位和 ATR 在事件内冻结，不随滚动窗口追着价格移动。

同一突破事件只允许一个成功 Setup；重新回到区间后，出现新的有效突破事件才可再次入场。S1 同向或反向持仓均不影响 S3。

### 3.5 S4：伦敦/纽约动能 Scalping

1. 首轮交易窗口定义为伦敦当地 08:00–11:00，或纽约当地 08:00–11:00，使用半开区间。两个窗口重叠时合并，不重复计算信号。
2. 必须实现英国/美国历史夏令时与经纪商服务器时间到 UTC 的日期映射；测试器不能用“当前电脑时差”推断历史。日期映射缺失时只阻止 S4 新单并记录，其他五策略继续。
3. M15 最近收盘 `EMA9 > EMA20` 且 EMA9 高于三根 M15 前为 BUY 动能背景；SELL 镜像。
4. 新收盘 M5 阳线实体 ≥0.60×ATR14_prev(M5)，全幅 ≤2.50×该 ATR，收盘位于该 K 全幅顶部 25%，且收盘高于此前 5 根 M5 的最高价。SELL 镜像。
5. BUY 初始 SL 在动能 K 低点以下加 M5 缓冲；SELL 镜像；初始 TP 首轮为 1.5R。
6. 最多两个活动槽位；第二单必须出自之后的新触发 K / 新 Setup，且独立通过单笔及组合风险。允许时间重叠，不因第一单在管理中而停止扫描。

时间窗口和动能阈值是研究默认；不代表最佳时段。不开启额外全账户交易时段限制。若采用旧 Scalping SOP 版本，必须保持旧固定 SL/TP 及退出禁令，并明确报告它与本 S4 动能研究版的差别。

### 3.6 S5：布林带横盘反转

1. M15 使用 Bollinger Bands：周期 20、偏差 2、收盘价；ADX14 主线 <20，并且 `abs(EMA20[1]-EMA20[4]) ≤0.25×ATR14(M15)[1]`，作为本策略自己的横盘条件。
2. BUY：新收盘 M15 的 Low 触及/穿过此前已知的下轨，且 Close 收回该下轨之上；SELL 用上轨镜像。判定边界使用信号 K 之前那一根 M15 的布林轨值，固定记录。
3. 候选最多等 3 根 M5；BUY 要求新收盘 M5 阳线且 Close 高于前一根 M5 高点，SELL 镜像；M15 横盘条件失效则取消本候选。
4. BUY 的 SL 在 M15 触轨 K 与 M5 触发 K 最低点以下加 M15 缓冲；SELL 镜像。
5. TP 取信号确认时冻结的 M15 布林中轨；若 TP 位于错误方向或预期距离无法覆盖已知往返成本及执行缓冲，拒绝并记录 `TARGET_SPACE_INSUFFICIENT`。不强制使用趋势策略的 2R TP。
6. 同一次触轨只允许一个成功 Setup；需先出现至少一根未触该侧轨道的收盘 M15，再发生新触轨，才能建立同方向新事件。

S5 的 ADX/横盘限制只作用于 S5，不能拿来关停 S1 或 S6；S6 有趋势仓不代表 S5 必须停止反转交易。

### 3.7 S6：D1/H4趋势＋M/W结构，M15/M5寻找入场

用户新增的是 S6 的顺势结构入场能力，不是第七个策略。Magic继续6601，备注继续`GSM_SWING`，最多一个活动槽位。W指双底结构，M指双顶结构；不能仅凭两根相似K线就称完整形态，也不能把“W必涨、M必跌”写成保证。

#### 3.7.1 周期分工与两条入场路径

| 层次 | 具体职责 |
|---|---|
| D1 | 最近三根已收盘K的实体高低框架、前方目标空间和结构背景；不要求D1与H4额外投票 |
| H4 | 决定S6趋势方向、主要支撑阻力、Swing初始保护与持仓管理依据 |
| M15 | 主要M/W结构识别、颈线与结构确认 |
| M5 | 精细执行触发；也可独立识别较小完整M/W结构，不要求M15同时再出现同形态 |

H4 BUY条件沿用v1.0：最近收盘EMA20>EMA50、Close>EMA20、EMA20高于三根H4前；SELL完全镜像。H4无明确方向时，本策略继续扫描与记录，但不新开趋势仓。

`S6EntryMode=H4_PULLBACK_OR_MW`为首轮默认：

- 路径A `H4_PULLBACK`：保留原H4回踩入场。H4 K与EMA20±0.25×ATR14_prev(H4)重叠，BUY阳线收在EMA20上方；SELL镜像。每根合格H4回踩只产生一个Setup。
- 路径B `TREND_MW`：H4上涨只接受W底做多；H4下跌只接受M顶做空。M15或M5出现一套完整结构并通过M5执行条件即可申请，不要求路径A的H4回踩K同时成立。
- A、B是两条可选机会路径（OR），不是叠加硬条件（AND）。同一时刻竞争S6唯一槽位，不能各开一仓。研究对照可设`H4_ONLY`和`MW_ONLY`，六个策略引擎仍全开。
- 首轮`EnableM15MW=true`、`EnableM5MW=true`，属于本次程序化落实的研究默认；先分别统计两个来源，再评估一起启用的结果，不以两个周期同时出现形态作为必要条件。

M/W是H4趋势中的较小周期回踩结束或反弹结束的候选证据。逆H4的M/W只记录，不用它反向开仓、关闭已有S6仓或操作其他策略。

#### 3.7.2 可编码的M/W定义

M15和M5各自维护独立结构检测器。下列数值均为待验证研究起点：

1. 每个周期最多回看120根已收盘K；局部pivot用左右各2根已收盘K的严格极值，局部平台等高/等低不确认。两个相隔的底/顶允许在容差内近似相等。
2. W的时间顺序为`低点L1 → 中间反弹 → 低点L2`；颈线N固定为L1与L2之间（不含两端K）的最高价。M镜像为`高点H1 → 中间回落 → 高点H2`，N为两顶之间最低价。
3. 两个底或两个顶相隔至少5根、最多40根该形态周期K。两极值价差绝对值≤0.35×ATR14；W的`N-max(L1,L2)`、M的`min(H1,H2)-N`均至少0.50×ATR14。
4. 形态几何使用第二个底/顶形成之前已收盘的ATR14，构造候选后冻结；不得用后来行情扩大容差，让不合格结构变合格。
5. 第二个底/顶的右侧两根收盘后，才允许完整形态进入`MW_CANDIDATE`；同时保存极值发生时刻、pivot确认时刻和`available_at`。不得在第二个极值发生当时回填已确认信号。
6. W要求形态周期收盘上破`N+0.10×冻结ATR`，M要求下破`N-0.10×冻结ATR`，且前一根收盘尚未越过该阈值。突破K收盘时刻必须≥形态available_at；若更早已突破，不倒填交易，等待新的合法突破或候选到期。
7. 完整形态最多等待第二极值确认后的12根该周期K完成颈线突破；突破后最多等待6根M5完成执行触发。到期记录`MW_EXPIRED`；不能持仓结束后重用很久以前的形态。

M15/M5图形缩放相似不等于独立机会，跨周期重复识别按3.7.5去重。形态阈值不得根据最终盈亏动态重画。

#### 3.7.3 M5执行：确认或回测颈线

首轮`MWEntryStyle=CONFIRM_OR_RETEST`；两种时机是OR，不要求两个动作连续都出现：

- **确认入场：**颈线突破确认之后的新收盘M5，BUY为阳线、收在N上方且高于前一根M5高点；SELL为阴线、收在N下方且低于前一根M5低点。
- **回测入场：**颈线突破确认之后的新收盘M5，与N±0.25×冻结形态ATR区域重叠，BUY阳线收回N上方；SELL阴线收回N下方。回测K不能兼任颈线突破K。
- 对M5来源形态，也必须等突破确认之后的新M5；不能用同一根K既确认第二极值、突破颈线又重复作为后续触发。
- 条件成立后的下一可交易Tick申请入场，采用第3.1节M5新鲜度及追价限制，重读H4方向和风险。未完成的M5形态、未收盘突破或未就绪数据都不能下单。

M/W的程序实现要检查`CopyRates/CopyBuffer`返回数量和数组方向，明确shift=0为当前未完成K；先按时间对齐，再使用当时已收盘的数据。[官方CopyRates说明](https://www.mql5.com/en/docs/series/copyrates)

#### 3.7.4 结构失效、初始SL/TP与管理

- 候选期间H4方向失效/反向，或价格穿越计划结构SL，即失效。颈线突破之后，W若新收盘M5跌回N−0.25×冻结ATR以下，M若涨回N+0.25×冻结ATR以上，记`MW_BREAKOUT_FAILED`并取消候选，先判失效再判进场。
- H4结构pivot沿用左右各2根已收盘H4确认；缺合法H4支撑/阻力时记`NO_CONFIRMED_STRUCTURE`，不能只为增加交易改成无保护小止损。
- 路径A的初始SL保持原定义：BUY在H4回踩K低点及最近已确认H4支撑pivot较低者下方加H4缓冲；SELL镜像。
- 路径B默认仍用Swing结构保护：W的BUY SL在`min(L1,L2,最近已确认H4支撑pivot)`以下加H4缓冲；M的SELL SL在`max(H1,H2,最近已确认H4阻力pivot)`以上加H4缓冲。M15/M5用于改善入场时机，不自动把Swing止损缩成短线几美元。
- 两条路径的TP和最低空间要求保持至少2R：前方D1框架边缘或已确认H4结构更近时，目标放在该结构之前一个缓冲位置，再检查2R；不足则等待或放弃，不缩SL凑盈亏比。
- 手数继续按实际入场到SL的距离及成本倒推。出现完整M/W不提高风险比例、持仓上限或“置信度手数”；资金不足仍输出`MIN_LOT_OVER_RISK`。
- 持仓管理的结构/ATR周期保持H4，保本按初始R和成本判断。M5逆向小形态不是强制退出信号；最长持仓、周末和新闻处理沿用SOP或另注册实验。

两路径共享S6的盈亏/连亏记录。为避免新增M5触发无意改变原冷却时长，本版显式设`S6CooldownTimeframe=H4`，仍按第4.2节3根K研究默认计算，不把它自动变成3根M5。

#### 3.7.5 身份、去重与统计

- `pattern_id`包含品种、方向、形态周期、两个极值时间和颈线来源；`setup_id`另含S6入口路径与实际M5触发时间，但一个pattern只允许一次成功交易。平仓/重启不清除已用标记。
- 首轮跨周期去重：同方向M15/M5候选的第二极值落在同一根M15时间区间，且颈线价差≤0.25×当时已知的M15 ATR14，归入同一`setup_family_id`。判定只用当时已知数据；先形成的family持久化，后到的匹配候选并入，不另开仓。
- 同时有效时优先最早可执行触发；完全同一时刻默认M15结构优先，保留被合并来源。A/B同时有效也只申请一个S6仓，并记录两个证据来源；不通过两个不同setup_id绕过槽位或重复开仓。
- M15没有完整形态不否决一个独立合格M5形态；跨周期合并条件不成立时各自保留候选，仍共用一个槽位和风险预算。
- 导出`entry_path, pattern_type, pattern_tf, pattern_id, setup_family_id, extremum1_time/price, extremum2_time/price, pivot_confirm_time, neckline, frozen_atr, available_at, breakout_time, trigger_time, entry_style, merged_sources`。
- S6报告分`H4_PULLBACK / M15_W / M15_M / M5_W / M5_M`，另分确认入场和回测入场；比较新增路径净利润、独立机会、风险拦截、入场MAE、假突破和组合DD。

若旧Swing SOP是D1/H4/M30，迁移到本次D1/H4背景＋M15/M5结构入场，必须在来源映射中记录。S6新路径是用户已授权的候选扩展，不改写旧Swing历史成绩，也不把旧M30触发隐藏在新路径中。

## 4. 策略隔离、状态机与订单执行

### 4.1 每个策略必须独立保存

`strategy_id / magic / indicator_handles / bar_clocks / structures / candidates / setup_ids / request_ids / position_records / pending_orders / risk_config / management_config / loss_streak / cooldown_until / day_trade_count / day_pnl / funnel / reason_codes`。

允许复用只读行情缓存和无副作用数学函数；禁止共享可写信号方向、区域消耗标记、保本标记、连亏或 cooldown。指标缓存必须以品种、周期、参数完整键控，不能让某策略改参数后影响其他引擎。

### 4.2 两层状态，避免持仓后不再扫描

用户给出的状态链应落实为每个 Setup / 持仓槽位的生命周期，而不是每个策略唯一的互斥枚举：

`IDLE → CANDIDATE → ARMED → RESERVED → ORDER_SENT → POSITION_OPEN → MANAGING → CLOSED → COOLDOWN`。

另有 `INVALIDATED / EXPIRED / REJECTED / REQUEST_UNKNOWN / RECOVERING` 分支。候选过期或失效直接归档；明确拒单可在有效期内按规则重试；未知请求保持占用并对账。

策略容器同时维护扫描状态、候选集合和活动槽位。S4 可以一槽处于 MANAGING，另一槽处于 ARMED，扫描器继续运行。其他策略槽位满时记录新机会但不超限下单。

冷却规则首轮：每个已完成 Setup 的触发 K 不再使用；技术重试最短间隔 2 秒、最多 2 次明确拒单重试。连续亏损达到 3 笔，首轮仅本策略新单冷却 3 根其触发周期 K；之后恢复，其他五个引擎不变。上述冷却为研究默认，需单独报告拦截影响。

连亏只在完整交易结束时更新：净亏损增加，净盈利清零，净保本保持原值但不增加；部分平仓不提前算胜负。冷却只由新完成的亏损事件触发，不能因计数仍≥3而每个Tick延长截止时间。冷却到期可重新接受新Setup；若随后又完成亏损，再按事件触发新的冷却。

每日交易次数默认不设人为上限，`MaxDailyTrades=0` 表示无限制但仍统计；不能让一次亏损或一次技术错误把全部策略锁一天。

### 4.3 所有订单操作明确归属

操作前枚举并验证 `symbol + magic + 当前 position ticket`。调用 `PositionModify(ticket, sl, tp)`、`PositionClose(ticket)`、`PositionClosePartial(ticket, volume)`，不得通过 symbol 重载操作多仓；挂单用 order ticket 及 `ORDER_MAGIC` 校验。

订单备注是审计信息，不是唯一授权依据。经纪商可能截断/更改 comment，不得因为备注变化而遗弃已确认属于本策略的仓位；也不能仅凭备注相同接管陌生订单。

持久归属键采用 `POSITION_IDENTIFIER`，实时操作使用当前 ticket。两者不能混淆；ticket 可能因服务器处理变化，须刷新映射。部分平仓、手动平仓或 Guardian 平仓的 deal 即使 Magic 不同，也应通过 `DEAL_POSITION_ID` 回溯原策略，不能丢失盈亏。

禁止跨策略 `CloseBy`，禁止用 S3 的 SELL 去对冲平掉 S1 的 BUY。BUY 和 SELL 各自独立 SL/TP、佣金、隔夜费与统计。

[官方持仓属性](https://www.mql5.com/en/docs/constants/tradingconstants/positionproperties)、[ticket 修改接口](https://www.mql5.com/en/docs/standardlibrary/tradeclasses/ctrade/ctradepositionmodify)、[分批平仓接口](https://www.mql5.com/en/docs/standardlibrary/tradeclasses/ctrade/ctradepositionclosepartial)。

### 4.4 下单与账户额度串行预留

首轮采用单一执行网关，行情/策略层只产生候选：

1. 收集六策略的有效候选，按有效触发时间排序；同一时刻用持久化轮换的平局优先权公平仲裁。所有策略均扫描，轮换仅用于有限额度的请求顺序。
2. 对每个候选重新读取最新报价、账户敞口、槽位和信号有效性。
3. 计算 SL、TP、合法手数和预期风险；使用 `OrderCheck` 核对请求及预计账户状态。
4. 发送前原子预留风险、保证金和槽位，再允许下一个候选检查额度。
5. 发送请求，保存完整 retcode、request_id、setup_id、订单/成交引用。`OrderSend=true` 不代表已经成交。
6. 明确失败才释放对应预留。超时/断线/状态未知，保持预留并暂停同一 Setup 重发；从服务器订单、持仓和成交历史确定结果。
7. 成交后把预留转换成真实仓位风险，不能双重计入；部分成交时分别记录已成交和余量，余量未撤销前不能释放全部额度。
8. 初始市价候选过期不能直接再发；若要重试必须再次满足当前策略条件和追价限制。

成交后还须按实际价、实际量和成本重算初始风险。若超过本请求冻结预算，记录 `ENTRY_RISK_OVERRUN`，优先合法减小本Setup的成交量；最低量仍超限或无法合法减量时关闭本Setup，并按真实执行结果对账。不得扩大SL、放宽预算，或先关闭其他策略给它腾位置。跳空可能在补救执行前已造成超额损失，因此预检查不是最大损失保证。

请求前读取该品种允许的订单类型、成交填充模式、订单有效期、Stops/Freeze规则；不能硬编码不受支持的FOK/IOC策略。初始保护SL必须随请求或按可验证的受控建仓流程生效，不能默认先无SL裸仓等待下一轮Tick补保护。

优先使用同步发送简化第一版，但依然处理交易回报异步到达。`OnTradeTransaction` 内只做轻量事件登记；不要阻塞、无限循环或假设事件顺序固定。后续由统一对账过程更新最终状态。[OrderSend](https://www.mql5.com/en/docs/trading/ordersend)、[OrderCheck](https://www.mql5.com/en/docs/trading/ordercheck)、[交易回报](https://www.mql5.com/en/docs/event_handlers/ontradetransaction)。

### 4.5 重启、重复实例和未知状态

- 持久化每个 Setup 的初始入场、初始 SL、初始 R、初始成交量、累计已减量、保本状态、已用区、请求及风险预留。
- 终端/EA 重启后先从服务器和成交历史重建，再恢复扫描与管理；不能清空 First Touch、日亏损熔断或把旧信号当新信号。
- 重启时间落在日内时，从该风险日已持久化净值快照及账务重建日损；无法恢复则标 `DAY_BASELINE_UNKNOWN` 并暂停新增风险，不能把当前净值当作当天开盘净值抹掉旧亏损。
- 状态文件缺失且无法重建初始 R 时，保留原服务器 SL/TP，记录 `INITIAL_R_UNKNOWN`，停用该仓依赖 R 的额外管理；继续必要安全管理，不能用当前移动后的 SL 伪造初始 R。
- 重启后发现同一账户有旧版/陌生 Magic 仓位，不接管，但其账户风险计入 Guardian；无法估计风险时阻止新单并明确原因。
- 同一候选在多 Tick、多个回报、重启重放下，只能产生一次实际订单效果。不得将持久化中的 `ORDER_SENT` 直接视为已成交或已失败。

## 5. 资金管理：先定止损，再计算手数

### 5.1 三种可选手数模式

| 模式 | 规则 |
|---|---|
| `AUTO_RISK`（默认） | 根据净值、风险比例、真实 SL、成本和组合剩余额度计算手数 |
| `FIXED_LOT` | 用户设手数，仍经过同样风险验算；超额则拒绝，不能绕过风险引擎 |
| `AUTO_RISK_CAPPED` | 自动手数同时受用户手数上限约束，最终向下对齐 |

不提供按亏损倍增、保证胜率加仓或未经风险检查的固定仓位模式。手数增长只能来自净值及允许风险变化，不能因刚亏损而补大单。

### 5.2 计算流程与单位

风险资本使用 `min(Balance, Equity)`，不把尚未实现的浮盈直接作为新增仓位扩张依据；净值为零/负数或字段不可靠时拒绝。该选择是保守研究默认，可另做明确对照。

`单笔预算 = 风险资本 × strategy_risk_percent / 100`

`合法手数需满足：初始SL价差损失 + 佣金/适用费用 + 预计持仓成本 + 不利滑点预留 ≤ 单笔预算`

先用经纪商允许的参考手数调用 `OrderCalcProfit(direction, symbol, reference_volume, entry, SL)`，再按预算搜索合法手数。读取 volume min/max/step、tick size/value、contract size、报价币种及账户换算；不硬编码“一手100盎司”。价格以 tick size 对齐，手数向下对齐 volume step，最后以实际合法值重新验算。[损益计算](https://www.mql5.com/en/docs/trading/ordercalcprofit)、[品种规格](https://www.mql5.com/en/docs/constants/environment_state/marketinfoconstants)。

真实 Ask/Bid 价差已体现在相应执行估计中，不重复加一次 spread。佣金和预留成本单列；估计未知不能默认为 0 并宣称成本已覆盖。允许明确设置 `COST_MODEL_UNCALIBRATED` 研究预设，但正式晋级前必须校准。

`MIN_LOT_OVER_RISK`：最低合法手数已超预算时跳过，显示本 Setup 所需最低净值；不向上取整，不偷偷把单笔上限提高到5%，不移动结构SL迁就资金。

例：仅作单位说明，若 USD500、每手100盎司、SL相距USD10，则0.05手约亏USD50（10%），0.02手约USD20（4%），0.01手约USD10（2%），均未计额外成本。账户大小本身不能证明某手数是“轻仓”。

### 5.3 首轮研究配置

| 参数 | 默认研究值 | 边界/解释 |
|---|---:|---|
| 每个策略每个新 Setup 风险 | 0.5% | S4 两单各算；本候选不允许超过旧项目单笔1%上界 |
| 组合新建仓风险预算 | 2.0% | 可另测3.0%，不能超过旧项目3%上界 |
| 当前净值至所有SL回落预算 | 3.0% | 包括浮盈回吐；达到后暂停新单，不因一般超限强制收紧他人SL |
| 保证金占净值上限 | 25% | 按请求后预计账户状态；与券商实际强平模式一起检查 |
| 无成本资料的滑点研究预留 | 2个tick | 仅未校准占位情景，正式测试按实际执行分布冻结；不能说2个tick足够覆盖尾部 |
| 账户日净值损失暂停线 | 3.0% | 达到后只暂停新增风险；对应的挂单限制见第7节 |
| 账户峰值净值紧急回撤 | 10.0% | 触发紧急处置并锁定；不是保证最终损失≤10% |
| S1/S2/S3/S4/S5/S6槽位 | 1/1/1/2/1/1 | 总槽位上界7；风险不足时不要求开满 |
| 每日交易数上限 | 0 | 不人为限制，但每笔须有独立Setup |

点差研究预设：新单同时满足 `Ask-Bid ≤ 0.50黄金报价美元` 且不超过本策略预计价格止损距离的15%。这是未校准示例，需要以 FxPro 的实际 Bid/Ask 历史核实；两个门槛分别报告拦截比例，不宣称通用最优值。不影响已有仓位正常保护。

所有百分比输入含义固定，例如输入0.5表示0.5%，不是50%。`USD价格距离 / MT5 points / account currency金额 / R倍数`必须分别命名并显示换算。

## 6. 保本、移动止损和分批止盈

### 6.1 固定初始 R 与费用保本

记录成交后的初始 `R_price=abs(actual_entry-initial_SL)` 和初始风险金额 `R_money`；部分成交按同一 Setup 加权汇总，初始建仓完成后冻结。之后移动 SL、改变剩余手数、保本都不能重新定义初始 R。

BUY 的当前盈利距离按 Bid−入场价，SELL 按入场价−Ask。保本触发首轮研究值1.0R；候选对照0.8R、1.2R只在训练段登记后测试。成本后保本价应覆盖适用佣金、退出成本与已产生swap，并保留执行缓冲；按剩余仓位实际成本归集，分批已实现盈利不能当作剩余仓位自身保本。

报价尚未允许合法保本SL时等待，不把SL放到非法位置。保本是计划退出水平，跳空/滑点可能产生亏损，不记录“保证零风险”。

### 6.2 单一持仓管理器合并保护请求

每个持仓只有其所属引擎的管理器提交最终修改。先处理已触发的强制退出，再处理尚未执行的分批动作，收到确认后刷新仓位，最后合并保本与追踪建议；每一轮最多提交一项未决修改。

- BUY 只允许提高 SL，SELL 只允许降低 SL；不能为扩大获利空间放松保护。
- BUY 在有效候选SL中选最高者，SELL选最低者；但需满足 Bid/Ask方向、tick size、Stops Level、Freeze Level及最小修改步长。
- 修改失败不能先把本地 `BE_DONE / PARTIAL_DONE` 标成成功；必须按服务器实际结果确认。
- 追踪首轮在1.5R后启动，采用已收盘策略管理周期的 ATR14、距离2.0ATR；只在该周期新K或足够价格改善时评估。另一候选为已确认结构之后加缓冲的追踪，两者分开测试。
- S1/S2/S3 的管理周期首轮 M15，S4 M5，S6 H4；S6新增M15/M5入场不自动改变其Swing追踪周期。S5 首轮只用原固定目标，额外管理关闭，避免还没到中轨就被追踪逻辑反复干预。
- 旧 SOP 锁定固定退出的引擎，不允许上述可选保护函数触达；用显式能力标记 `allow_optional_exit_management=false` 做约束。

### 6.3 分批止盈

独立研究候选：达到1R时平初始建仓量的50%，仅一次；其他比例另注册实验。合法平仓量和剩余量都要符合最小量/步长，且不能把“平一半”退化成全部平仓。

例如最小量/步长均为0.01，0.01手不能平0.005；记录 `PARTIAL_CLOSE_NOT_POSSIBLE`，继续原完整仓位管理。0.03手的一半也不能随意四舍五入，按向下合法量执行并披露实际比例。实际少量成交及重启后按累计已减量确定余量，不重复分批。

分批只是退出方式，不计为新的入场机会；不能为启用分批而先开大仓或把一单拆成多单。分批降低回撤或改善收益均须测试，不能预设必然有效。

### 6.4 实验版本

| ID | 退出模式 | 六策略启用要求 |
|---|---|---|
| X0 | 各策略初始/锁定的SL/TP规则，不加额外保护 | 六个全开，是退出对照 |
| X1 | 在允许修改的单个引擎加入成本后保本 | 其余五个保持X0；六个仍扫描 |
| X2 | 在允许修改的单个引擎加入ATR或结构追踪之一 | 其余五个保持X0 |
| X3 | 在已有证据的管理候选上测试分批 | 必须比较不分批版本 |

按引擎逐项找证据，随后对已冻结的各引擎退出组合重跑六策略。不能一次把所有保本、追踪、分批和风险参数全改后声称知道改善原因。最终交付全部引擎默认启用，不自动按历史盈亏关闭任何策略。

## 7. Portfolio Risk Guardian：账户级保护

### 7.1 两种风险同时跟踪

初始预算风险：对每仓计算剩余量从初始入场至当前有效SL的非负损失，加适用剩余成本；盈利侧SL也不能减去其他仓风险。新增订单按入场至初始SL计；挂单/在途请求按其承诺风险计。

当前净值风险：每仓用同一估值口径求 `max(0, 当前可实现浮动盈亏 − 在SL预计盈亏) + 额外退出压力成本`，反映从现在净值回落到SL的空间。不得只用“入场到SL已为正”把所有浮盈仓当风险零。

两种指标分别与第5节对应阈值比较，不把它们相加重复计算同一仓风险。组合按仓位逐项累计，不因BUY/SELL手数相等就净额抵消。还要记录 gross long/short手数、方向初始风险、总保证金占用和每策略预算占用。

账户级读风险含手动单与其他EA敞口。没有SL、费用未知或无法归属而不能可靠估计的外部风险，默认暂停本EA新单并显示原因，不擅自补SL或平外部仓。普通拒绝新单不能取消别的策略已存在的挂单。

`OrderCalcMargin` 可作单请求估算，但不会自动把全部现存仓单按本设计汇总；需结合账户实际保证金、预留和 `OrderCheck` 预计结果，不凭杠杆大小放行。[官方保证金估算](https://www.mql5.com/en/docs/trading/ordercalcmargin)

### 7.2 保护级别与动作

| 条件 | 新请求 | 已有仓位/挂单 |
|---|---|---|
| 组合预算/槽位满 | 拒绝新增风险，保留有效信号日志 | 所属策略照常管理；不因此平其他策略 |
| 保证金不足、异常点差、交易权限关闭 | 暂停新入场 | 不停止可执行的正常保护；失败明确记录 |
| 断线、陈旧报价、数据未同步 | 不发送依赖异常数据的新交易 | 服务器已有SL继续有效；连接恢复后对账，不假装离线平仓成功 |
| 单策略连亏/冷却 | 仅阻止该策略新单 | 其他策略继续；该策略既有仓仍管理 |
| 账户日损达到暂停线 | 全六策略暂停新的风险提交，锁至下一风险日 | 不因普通日损线强平；挂单承诺按7.3处理 |
| 账户净值紧急回撤达到10%候选线 | 锁定所有六策略新单 | Guardian取消六策略受管挂单、逐ticket平受管仓位并确认，包含所有六策略 |
| 确认存在无初始保护SL的本EA仓位 | 立即停止新增风险，尝试恢复原合法SL | 无法恢复则以独立紧急事件平该受管仓；持续失败上报并重试 |

紧急处置的“所有仓位”在此明确为本EA六个Magic在受管品种名下的所有仓位；不是某个引擎只管自己。手动单、其他EA、其他品种不默认接管，其风险仍计入账户保护。若以后明确要求账户所有交易一并紧急平仓，应另设显式范围配置并在面板展示，不能隐式扩大。

紧急流程优先取消受管挂单，再按可执行性处理受管仓位；全过程继续对账，期间触发的新成交也加入处置。断线/休市/拒绝可能令平仓失败，保留锁和可恢复重试，不能宣称达到某回撤线就保证绝不超额。紧急锁重启保留，需明确人工复位；普通新交易日不解除紧急锁。

### 7.3 “暂停新单”与服务器挂单触发分开

第3节默认研究版在确认后市价申请，因此日损暂停能阻止后续新入场申请。若某SOP使用服务器挂单，已提交挂单属于已预留承诺，暂停新增提交并不能阻止它稍后触发。

必须显示 `PAUSE_NEW_SUBMISSIONS_EXISTING_COMMITMENTS_ACTIVE`，不可声称已彻底停止一切新持仓。普通暂停线不跨策略撤单；所有受管挂单只按各自到期/失效或明确全局紧急条件撤销。要实现“日损达到线后绝不允许挂单再触发”，需要显式将该阈值升级为全局紧急撤单条件；默认不偷偷改变用户只在紧急时跨策略撤单的要求。

### 7.4 日损、峰值和现金流

- 首轮风险日用UTC 00:00，配置和日志同时显示服务器时间、UTC时间及用户显示时间；时区变更不得重置亏损纪律。
- 设日初净值为 E0、当日外部净注资为 C（入金正、出金负），日损比例为 `max(0, E0 + C − Equity_now) / E0`，E0不合法时不计算伪值。
- 账户峰值与回撤按外部入出金调整的净值路径维护。入金不直接清空连续回撤，出金不错误触发交易亏损熔断。
- 如果测试中没有外部资金流，也须明确记录该假设；日初净值、峰值、当日锁与紧急锁必须持久化。
- 新闻过滤若原SOP/项目已要求则保留；历史测试要有当时可获得的事件日历及时区，不能联网取得未来结果作为过去过滤。缺数据如实标记，不自动把新闻过滤关掉以增加交易。

## 9. 指标定义：净利润、交易次数与回撤

### 9.1 完整交易与资金对账

以完整持仓生命周期为基本交易单位；多次部分平仓全部合并后再算该笔胜负、平均盈亏和连亏。若经纪商将同一建仓请求拆成多个持仓，还需按Setup另报去重数量。分别报告 `MT5 Trades / Deals / Complete Positions / Unique Setups / Independent Entries`。

净收益包含 `DEAL_PROFIT + DEAL_COMMISSION + DEAL_SWAP + DEAL_FEE` 中实际适用字段，逐deal入账一次。无法归属的账务费用放到 `UNALLOCATED_ACCOUNT_COST` 并解释，不能丢掉或按比例虚构归属。分批、手动平仓和紧急平仓都追溯原持仓策略。[官方成交字段](https://www.mql5.com/en/docs/constants/tradingconstants/dealproperties)

`六策略已实现贡献 + 外部交易已实现变化 + 未分配账务费用 + 外部现金流`应与账户余额变化对账；相同字段不得重复扣费。利润、均值和对账容差按账户货币精度预先定义。

### 9.2 每策略必须有两类结果

1. **单独运行报告：**该策略独立run，用同一USD500、账户规格、风险配置和日期得到原生MT5统计，保留其他五策略关闭仅为诊断的配置证据。
2. **六策略组合内贡献：**来自六个全开同一次run的实际成交、浮盈亏和预算占用，受到组合风险竞争影响。

两者不能混用。组合内每策略的累计已实现加未实现净贡献形成一条贡献曲线，以它计算 `ContributionDD_USD`；若需要百分比，明确除以组合初始资金，标 `ContributionDD_pct_of_combined_initial`，不能冒充独立账户原生DD。不得把六条曲线各加USD500后相加成USD3000的虚构账户。

`TesterStatistics()`返回整个run统计，不会按Magic自动提供六份原生Recovery/PF。分策略原生指标来自六个单独run；组合内指标由审计账本重建并标明口径。

### 9.3 主报告字段

| 维度 | 必报内容 |
|---|---|
| 收益 | Net Profit、账户货币、初始资金、日期、Return%、Gross Profit/Loss、成本明细 |
| PF和胜率 | 原生PF与完整交易净额PF、盈利/亏损/保本数、胜率、平均盈利/亏损、实际平均盈亏比 |
| 期望 | 原生Expected Payoff、净收益/完整交易数、每单成本、成本压力后期望及不确定性 |
| 回撤 | 最大净值DD金额、其对应%、全程最大相对净值DD%、余额DD辅助、最长恢复时间 |
| Recovery | 原生MT5 Recovery及额外Equity Recovery，分母为0等情况明确状态 |
| 活跃度 | 每月独立进场数、有交易日占比、无交易天数、机会漏斗、被风险挡住的合格Setup |
| 持仓 | 最大同时持仓数、long/short总量和风险、峰值保证金、最低Margin Level、Stop Out事件 |
| 归因 | S1～S6、BUY/SELL、月份、趋势/震荡/高波动、成本和退出类型 |
| 尾部风险 | 最大单亏、最长连亏及金额、实际超计划损失、跳空/滑点、亏损聚集 |

平均净期望 = 盈利比例×平均净盈利 − 亏损比例×平均净亏损绝对值。保本单独统计；有保本单时不能强行把败率写成1−胜率。理论TP/SL比与实际平均盈亏比、R倍数收益分别报告。

原生 `STAT_RECOVERY_FACTOR = STAT_PROFIT / STAT_BALANCE_DD`。额外 `EquityRecovery = 同区间净收益 / 最大净值回撤金额`。最大相对净值回撤门槛使用 `STAT_EQUITY_DDREL_PERCENT`，不是最大金额回撤对应百分比。无交易/无亏损/分母0使用 `UNDEFINED / INSUFFICIENT_DATA` 和平台原值，不用999假装通过。[官方统计定义](https://www.mql5.com/en/docs/constants/environment_state/statistics)

胜率没有统一合格区间。PF>2.5或3不是“90%过拟合”；记录审查标记，核查样本、参数试验次数、未来信息、成本与利润集中，按证据判断。

### 9.4 净值与相关性不能靠成交表猜

EA运行中逐Tick更新账户及策略贡献的极值、MAE/MFE和DD；图表可下采样，但保留真实极值及发生时间，注明采样方法。只用平仓后余额无法证明盘中浮亏回撤很小。

策略相关性基于相同时间格、含未实现盈亏变化的日收益/贡献变化序列；没有新成交但有持仓也不能把该日变化写0。同时报告亏损重叠、方向集中和保证金重叠。不要只算成交序号之间相关性，也不要把低相关等同于未来风险一定降低。

新增交易的净收益需单独汇总；同时重新跑完整组合，核查新增订单是否挤占其他策略更好的机会。仅看原有赢家掩盖新增亏损，或通过多次部分平仓增加Trades，均不得认定频率优化成功。

## 10. 回测协议与正式验收

### 10.1 测试环境与证据

- 首先做FxPro XAUUSD，实际品种后缀、合约、币种、杠杆以终端为准；不自动换券商、换合约或增资制造通过。
- 以USD500为主要小资金可行性案例；其他资金档只作明确独立实验，不能替代USD500结果。
- 用户已知Real Tick起点是2024年3月。先核查实际覆盖与缺口，再冻结可用起止；不声称已拥有2020年数据。
- 旧计划记载2026-05-01至2026-08-26及旧Scalping验证段已被分析，当前不能再次标为全新未见样本外；先核对数据使用登记。
- 正式结果采用 `Every tick based on real ticks`，检查缺失Tick导致的生成回退。OHLC可用于开发排错，不作为最终短线成绩。[官方Tick机制](https://www.metatrader5.com/en/terminal/help/algotrading/tick_generation)
- 训练、滚动验证和最终保留样本的边界、预热与跨边界持仓策略预先固定。训练时只能使用当时已知数据；最终保留段用来验证冻结版本，看到结果后修改则该段转为已参与研究。
- MT5原生Random Delay为秒级：90%为0–8秒、10%为9–18秒。实测固定延迟、10/25/50毫秒情景和原生随机模式分开；Delay不能完整模拟挂单触发滑点。[官方执行设置](https://www.metatrader5.com/en/terminal/help/algotrading/testing)
- 成本情景首轮包含实际成本、点差+25%、点差+50%、更不利执行滑点。1.5倍/2倍总成本可作额外敏感性分析，明确模型。无法由原生测试器表达的情景标研究模拟；若影响成交路径，应重跑，不能只从最终利润减钱。
- 每次记录参数搜索次数和失败结果，禁止对同一OOS反复调到PASS。没有足够未用验证数据则标 `OOS_PENDING`。

两个版本用同一账户资本、风险上限、成本、时区、日期及数据源；应同时给出每笔R收益对照，区分信号/退出改进与动态手数路径变化。组合结果必须真实重跑，不能用六份solo利润相加。

### 10.3 工程验收与盈利验收分开

**ENGINEERING_PASS**：六引擎真实实现、默认全开、隔离/风险/恢复关键场景通过，实际MetaEditor编译0 errors/0 warnings，有可复查日志。不能由Python语法检查代替MQL5编译。

**RESEARCH_PASS**：在上述基础上有相同风险的真实测试证据；本规格采用以下明确门槛，继承旧计划约束并为低回撤目标收紧自动晋级区间：

| 项目 | 正式处理 |
|---|---|
| 净利润与净期望 | 主测试、冻结的合理不利成本场景及最终OOS均需为正；样本与置信不确定性另报 |
| PF | 样本外≥1.3作为本轮候选初筛目标；不是通用金融定律，不设高PF上限 |
| 最大相对净值DD | ≤10%为研发目标；自动晋级须≤15%；>15%不自动晋级，>30%继承旧硬拒绝 |
| 完整交易数 | 六个solo线及六策略Combined主区间各>100；不从重叠报告/部分平仓凑数。组合内每策略数量另报，不伪装成solo样本 |
| Recovery | 六个solo及Combined原生MT5 Recovery>3，另报净值Recovery；无定义或低样本不自动晋级 |
| 安全与完整性 | 无串单、重复开单、净额合并、绕过风险、故意无SL、未来数据、Stop Out或隐藏成本 |
| 三项目标 | 相对B0同时列净利变化、独立进场变化、DD变化；只有净利与有效进场增加且DD不增，才可标“三项目标同时改善” |
| 证据不足 | `RESEARCH_FURTHER / LOW_SAMPLE_SIZE / CAPITAL_CONSTRAINT / OOS_PENDING`，不能降门槛或强制开单 |

单策略不赚钱或样本不足时继续研究与披露，不自动将其关闭后宣称“六策略全开PASS”。个别指标之间有取舍时明确列出，不能把高净利抵消工程安全失败。用户当前要求六策略全开，因此最终晋级对象必须是可复现的六策略组合。

恢复因子和>100笔在这里属于沿用的项目门槛，不是保证统计可靠或未来赚钱。极端压力情景的接受标准要预先登记，可专门评估失败方式；不能要求任何灾难情景都盈利，也不能隐藏结果。

## 12. 建议代码结构与交付内容

### 12.1 模块边界

建议工程入口：`MQL5/Experts/GSM_Gold_6_Strategy_Parallel_EA.mq5`。辅助文件放在独立的 `MQL5/Include/GSM6/`，不要覆盖旧版同名include。

| 模块 | 责任 |
|---|---|
| `StrategyRegistry` / `StrategyBase` | 六策略注册、独立参数状态、扫描接口、Setup创建 |
| `S1_Trend`～`S6_Swing` | 第3节各自真实信号与失效规则，不直接调用交易API |
| `MarketData` / `Indicators` / `SessionClock` | 已知时刻数据、缓存、指标就绪、时区及夏令时 |
| `SetupState` / `PositionBook` | Setup与持仓多槽生命周期、归属、初始R、历史映射 |
| `RiskSizer` | 全部手数模式的同一风险/成本计算、价格/手数合法化 |
| `PortfolioGuardian` / `RiskReservation` | 总风险、保证金、日损/紧急锁和请求预留 |
| `ExecutionGateway` | 唯一交易API入口、ticket校验、retcode、重试及对账 |
| `PositionManager` | 所属仓位保本、追踪、分批合并；锁定SOP能力检查 |
| `Persistence` / `Audit` / `DashboardCN` | 恢复、schema日志、统计对账、中文显示 |

核心事件职责：

- `OnInit`：参数/账户/实例检查，创建六引擎，建立数据与恢复状态，启动timer；历史预热不足只标就绪状态，不假开仓。
- `OnTick`：刷新数据、对账、优先风险和保护、调度六策略扫描、处理有效候选；全局普通暂停只影响新增请求阶段。
- `OnTimer`：连接/状态心跳、缺失数据重试、轻量持久化和未知请求对账；没有新报价不能凭旧价交易。
- `OnTradeTransaction`：登记交易事件、归属与待对账标志，不能做长时间报告计算。
- `OnDeinit`：持久化状态、释放句柄/租约；移除EA不自动平仓或撤单，既有服务器保护保留。
- `OnTester` / 测试结束：导出真实统计、极值与自定义结果；不得为获得高排名把无交易/无亏损的未定义值变成极大分。

接口可以采用结构化 `StrategySignal, SetupRecord, RiskDecision, ReservationRecord, PositionRecord, ManagementIntent`；字段覆盖前文。下单网关再次校验策略归属与全局锁，不能信任上层过期检查结果。
