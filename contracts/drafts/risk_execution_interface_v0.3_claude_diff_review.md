## 一、M6 保守订单匹配：同意方向，补一条自动结案路径（D1）

**同意的部分**
- 优先用 request/order/deal/position ID 和成交链精确匹配，magic + symbol + 方向 + 时间只作辅助。
- 无法唯一对应时不重发，comment 只作辅助。我原提案只写“找到匹配就视为已接受”，没有处理多个候选的情况，Codex 的修正是对的。

**问题 1：最需要核对的情况，恰好拿不到 ID。**
重试通常发生在请求超时或没有明确回应时。这时 `MqlTradeResult.order` 往往是 0，精确匹配无从做起，实际都会走到辅助匹配。所以辅助匹配的判定规则必须写死，否则两边会各自理解：
- 先缩小候选范围：本 EA 的 magic、同 symbol、同方向，服务器时间在 `request_time - 时钟容差` 之后的挂单、持仓和成交。时钟容差在 policy 登记，时间一律用服务器时间。
- 同一个 order_ticket 下的多笔成交（部分成交）算**一个**候选，不算歧义。
- 由于 M5 规定 magic 跨实例不重叠，在途锁又保证同一策略同一品种只有一个未完成请求，正常情况下候选只会是 0 个或 1 个。出现 2 个以上，本身就说明有异常（例如手动下单用了同一个 magic，或之前的重试已经成交），这时 RECONCILE_REQUIRED 是正确的。

**问题 2：v0.3 只写了“等人工或后续对账解决”，没有自动结案。**
回测和无人值守时没有人工，策略会被永久锁住。补充三种结局：

| 对账结果 | 处理 |
|---|---|
| 唯一匹配 1 个 | 转 OK_PENDING，按正常在途流程走到最终状态 |
| 0 个，且历史查询成功，并已超过 `inflight_timeout_seconds` | 判定服务器未接受：状态改 EXPIRED，释放在途锁。审批保持已用，**不重发**；要入场必须等新信号重新审批 |
| 0 个，但历史查询失败 | 保持锁，RECONCILE_REQUIRED，下次 Tick/Timer 再查 |
| 2 个以上 | 保持锁，RECONCILE_REQUIRED，禁止该策略新仓并告警 |

**问题 3：歧义时不能让真实仓位失去保护。**
2 个以上候选里如果有已成交持仓，它们都是真实敞口。规定：所有匹配到本 EA magic 的持仓，照常计入组合风险并执行 SL 补设和保护；“无法确认归属哪个审批”只影响在途锁和新仓，不影响保护。

RE-24 相应扩展为三个子用例：RE-24a 两个候选 → 锁定不重发；RE-24b 零候选且超时 → 释放锁、不重发；RE-24c 零候选但查询失败 → 保持锁。

## 二、P1 账户模式：同意，补两个检查点（D2）

同意“历史证据只用于选择目标，启动时以 ACCOUNT_MARGIN_MODE 为准，不符就禁新仓、只管理可确认属于本 EA 的仓位”。补两点：

1. **交易所模式也要拦。** `ACCOUNT_MARGIN_MODE_EXCHANGE` 和净额一样是单一持仓，按“非对冲”处理，禁新仓并告警，不能只判断是不是 NETTING。
2. **回测的账户模式来自测试器设置，不是真实账户。** 每份回测报告必须记录测试器读到的账户模式，并与 policy 的 `account_mode` 比对；不一致的报告作废，不能当成绩。否则可能拿净额模式跑出来的结果，去代表对冲账户的表现。

## 三、P3 持久化：同意不预设原子替换，具体写法定为 A/B 双槽（D3）；补回测隔离（D4）

**D3：把“代际文件”写成唯一方案，避免两边实现不同。**
Codex 不把未验证的改名操作当作原子，这个修正是对的。v0.3 列了“替换或代际提交机制”两种，我建议冻结时只保留一种：A/B 双槽，完全不依赖改名。
- 两个文件交替写：本次写 A，下次写 B。
- 每个文件带单调递增的 `sequence` 和 SHA-256 校验（MQL5 可用 `CryptEncode` 的 `CRYPT_HASH_SHA256`）。
- 读取时两个都读，取校验通过且 sequence 最大的一份。写到一半崩溃，坏的只是正在写的那一槽，另一槽仍是上一份完整快照。
- 两槽都无效时，按 v0.3 的规则进入 RECONCILE_REQUIRED。

**D4：回测之间的状态文件隔离（v0.3 未提及，必须补）。**
测试器的文件沙盒可能在两次回测之间保留旧文件（具体行为需在本机实测确认）。如果新一轮回测读到上一轮遗留的在途锁或已用审批，会凭空锁住策略，或跳过本该发生的交易，成绩就失真了。而且账户指纹和 policy hash 在两次回测间可能完全相同，现有校验拦不住。
- 规则：`MQLInfoInteger(MQL_TESTER)` 为真时，OnInit 一律从空状态开始，并在状态文件名中加入本次 run_id。
- 例外：专门测试重启恢复的用例（RE-05、RE-06、RE-25）显式指定要加载的状态文件。
- 新增 RE-27：连续两次回测，第二次不得读到第一次的状态（T）。
