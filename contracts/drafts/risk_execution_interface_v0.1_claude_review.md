## 一、对 v0.1 的审查意见（需修改）

### R1. 防止重复下单：缺少“在途订单”状态
`SubmitEntry` 返回成功不等于已成交。订单发出到持仓出现之间，下一个 Tick 可能再次满足信号，导致重复开仓。
- 执行模块维护每个 `strategy_id + symbol` 的在途锁：`PENDING_SUBMIT → SENT → FILLED / PARTIAL / REJECTED / EXPIRED`。
- 在途期间，同一策略同一品种的 `EvaluateEntry` 直接返回 `REJECT_IN_FLIGHT`。
- 在途锁超时后不能自动解锁，必须先对账，确认服务器上没有对应订单或持仓。

### R2. 新 K 线判定被前面的门控影响
`IsNewBar()` 放在点差和新闻门控之后。如果新 K 线开盘时点差过大，会在同一根 K 线内稍后才入场，价格已偏离信号。
- 信号必须基于已收盘 K 线计算。
- 增加 `max_entry_delay`（秒或 Tick 数，事前登记）：超过就放弃本根 K 线的信号，不延迟追单。
- 新 K 线检测的状态更新不能被前面的 return 吞掉或重复触发，Core 要明确记录“本根 K 线是否已评估过”。

### R3. 成交后必须按实际成交重算风险
审批时用的是预期入场价。实际成交价、滑点和部分成交都会改变真实风险。
- 成交后用实际均价和实际成交量重算风险，写入持仓记录。
- 实际风险超过审批上限的允许误差（事前登记，例如 10%）时，执行事前登记的处理：减仓到上限内，或标记异常并禁止该策略新开仓，不能静默接受。

### R4. 净额账户与对冲账户必须分开定义
- 启动时读取 `ACCOUNT_MARGIN_MODE`，写入日志。
- 对冲账户：每个持仓用 `magic`（策略）+ `position ticket` 识别。
- 净额账户：同一品种只有一个持仓，多个策略无法各自拥有止损。v1 规则：净额账户下同一品种只允许一个策略持仓，第二个策略的 `EvaluateEntry` 返回 `REJECT_NETTING_CONFLICT`。不在 v1 实现虚拟持仓。
- 平仓意图在净额账户中可能变成反向开仓，执行前必须核对实际持仓方向与数量。

### R5. 止损修改频率与券商限制
- 追踪止损设最小更新步长（价格单位，事前登记），避免每个 Tick 都发修改请求。
- 修改前检查 `SYMBOL_TRADE_STOPS_LEVEL` 和 `SYMBOL_TRADE_FREEZE_LEVEL`。距离不足时不发请求，保留当前已生效止损。
- 价格进入冻结区时不能修改，这属于正常状态，不是错误。

### R6. 单位统一
接口中所有距离字段必须带单位后缀：`_price`（品种价格差）、`_points`（MT5 Point）、`_usd`（账户货币）、`_pct`（百分比）。禁止无单位的 `distance`、`offset`。

## 二、函数失败状态与恢复行为

统一状态码（建议 enum，所有函数返回其中之一，并附原因文本）：

| 状态 | 含义 | 恢复行为 |
|---|---|---|
| `OK` | 成功且已获服务器确认 | — |
| `OK_PENDING` | 已发送，等待交易事件确认 | 在途锁保持，等 `OnTradeTransaction` 或对账 |
| `REJECT_RISK` | 超出单笔或组合风险上限 | 不下单，记录原因 |
| `REJECT_VOLUME` | 合规手数无法满足预算（小于最小手数） | 不下单，不向上凑手数 |
| `REJECT_IN_FLIGHT` | 同策略同品种有在途订单 | 不下单 |
| `REJECT_NETTING_CONFLICT` | 净额账户品种已被其他策略占用 | 不下单 |
| `REJECT_APPROVAL` | 审批不存在、已用、过期或条件已变 | 不下单，要求重新审批 |
| `REJECT_MARKET` | 交易关闭、品种禁止交易、停盘 | 入场放弃；保护动作排队，市场恢复后重试 |
| `REJECT_STOPS_LEVEL` | 止损距离不满足券商限制 | 入场：放弃或按规则调整后重审批；修改：保留当前止损 |
| `RETRY` | 可重试错误（requote、价格变动、交易繁忙） | 有限次重试（次数事前登记），超过后转对应失败状态 |
| `FAIL_SERVER` | 服务器拒绝且不可重试 | 记录 retcode；保护类动作进入告警状态 |
| `DATA_UNAVAILABLE` | 行情、账户或品种属性读不到 | 入场放弃；保护动作使用最近一次有效数据中能安全执行的部分，不放宽止损 |

通用规则：
- 内部状态只在服务器确认后更新。`CTrade` 返回 true 只代表请求已提交。
- 保护类动作（止损、退出）失败不能静默，必须保留“待处理保护动作”记录，下一个 Tick 或 Timer 继续处理。
- 任何失败路径都不得放宽已生效的止损。

- **T** = 策略测试器回测
- **F** = 测试器 + 故障注入
- **D** = Demo 账户实测

## 四、净成本保本计算（供实现对照）

多单保本价：
`BE_price = 实际开仓均价 + 成本价格偏移`

`成本价格偏移_price = (往返佣金_usd + 已产生隔夜费_usd(为负时计入) + 预留缓冲_usd) ÷ (持仓量 × TICK_VALUE ÷ TICK_SIZE)`

- 空单方向相反。
- 用 `SYMBOL_TRADE_TICK_VALUE` 与 `SYMBOL_TRADE_TICK_SIZE`，或用 `OrderCalcProfit` 反推；两者结果写入日志交叉核对。
- 点差已体现在实际成交价中，不再加入。
- 保本价还需满足止损距离和冻结区限制；不满足时等待，不放宽。
- 跳空、滑点、执行失败仍可能造成亏损，日志与报告中不得标为“零风险”。
