**两项改动分开，不能合称“单变量”：**
- **B4B1**只改**入场成交在 250 ms 到期时如何取价**，并按事件顺序确定成交时刻；

## 2. B4B1 定义（唯一主动改变：入场取价及其执行时刻）
- **截止时刻：**`T_deadline = T_req + 250`，其中 T_req 是 core 预留时那一行的 ServerMs，与 B4A 的 `DueMs` 完全相同。
- **截止报价（边界规则，设计决定，需复审）：** 采用 B4A 的 flag 驱动生效报价，按原始行序依次应用**所有 ms ≤ T_deadline 的行**（含截止毫秒上的全部同毫秒行），得到的状态即截止报价。即**含截止时刻**。
  - 依据：B3 中返回时报价就是 ≤ T_deal 的最后一行，与“测试器把 tick 流推进到 T_deal 为止”一致；但截止毫秒上恰好有行的情况**没有证据**。
  - 处理：每次入场都记录 `deadline_ms_rows`（截止毫秒上的行数）。全月中只要 >0 就逐笔列出，标为“未验证边界”，不当作已证实的语义。
- **执行时刻（不引用未来）：**只有等到**第一个 ms > T_deadline 的行 r** 到来，才能确定截止毫秒上的行已经全部出现。因此 B4B1 在处理行 r **之前**、应用 r 的 flags **之前**，取当时的生效报价快照作为截止报价，然后执行入场。这个快照只包含 r 之前的行，**不读取 r 或之后任何行的价格**。
  - 被跳过的行（未就绪或生效报价交叉）也会更新报价状态；快照在越过截止时刻的第一行上取，不受该行是否交给 core 的影响。
  - 截止报价无效（bid ≤ 0 或 ask < bid）时，按模型拒单（`INVALID_QUOTE_AT_DEADLINE`），结构不复用，并计数。
  - 截止之后、窗口结束之前没有任何行时，与 B4A 相同，在 End 时取消请求并记录。
- **与 B4A 唯一行为差异的位置：**
  - (a) 成交价：B4A 用“第一行 ≥ due 的当前行报价”，B4B1 用“截止状态”；
  - (b) 持仓开始存在、开始接受服务器保护的行：B4A 是第一行 ≥ due，B4B1 是第一行 > due。只有截止毫秒上恰好有行时，两者才不同。
  
  (a) 和 (b) 都是“按截止时刻定价”这一改动的组成部分，都会逐笔记录。
- **入场时的风险与 stops 检查：**StopsValid 改用截止报价（模拟服务器在成交时刻的检查），其余入场逻辑不变（InitialR、预算超支检查等），只是基于新的成交价。
- **不变部分：**
  - 平仓和管理请求（kind 2 平仓、kind 1 改 SL）**保留 B4A 语义**：在第一行 ≥ due 时，用当前报价执行。B3 显示平仓 DEAL 也遵循截止规则（2/2），但本登记把 B4B1 限定为只改入场，平仓规则可在之后单独登记；改 SL 的延迟语义没有证据。
  - 服务器 SL/TP **每一行都照常执行**，不被抑制。
  - 组合风险的维护、日锁和紧急锁都不变。
- **对 8 月的预测（事前写明）：**B4A 全月 56 笔入场已经与原生一致。原因是截止后的第一行通常是 flag 280（LAST）行，在 flag 驱动下保留前一个报价；例如 8 月 3 日 slot1，.378 是 280 行，生效报价仍为 4052.88。因此预计 B4B1 在 8 月的入场价 56/56 不变；任何变化都要逐笔解释。B4B1 的价值在于模型保真度，以及把 B4A 依赖的这一“巧合”变成可以检查的规则；它**不是**策略改进。

## 3. LEAN 订单时间的限制
- 截止时刻已经过去时，LEAN 不能在过去的时间下单。真实的 QC MarketOrder 在行 r 的算法时间提交，OrderEvent 的时间也是 r 的时间（fill model 中 `Utc = tickUtc`）。**不伪造** OrderEvent 时间。
- 模型时刻单独记录：`model_request_msc`（T_req）、`model_deadline_msc`、`model_fill_quote_row`（截止状态最后一行的行号和 ms）、`engine_submit_msc`（r 的 ms）、`engine_lag_ms`（r.ms − T_deadline）。成交价由 fill model 按截止报价设定（与 B4A 一样，由 core 决定价格）。
- 对账使用当前行的修正报价（LEAN 缓存）对持仓估值，仍是单一公式加 0.05 容差，不受成交价来源的影响。

## 4. core 的隔离与复用（不改 S4Core）
- **新目录与命名空间：**`lean/algorithms/S4B4B/`，命名空间 `TradingBrain.S4B4B`，独立程序集和候选 ID `TB500_S4_BE125_LEAN_B4B1`。
- **core 分叉：**把冻结的 `S4Core.cs`（ee509e1d…）复制为 `S4CoreB4B.cs`，命名空间改为 `TradingBrain.S4B4B`，只做最小差异：
  1. 新增公开只读属性 `PendingEntryDeadlineMs`（无在途入场请求时为 null）；
  2. 新增可选钩子 `Func<S4Book, EntryQuote?> EntryQuoteAtDeadline`；
  3. `ProcessDue` 中，**只有入场请求**在钩子存在时改为“第一行 > due 时执行，使用钩子返回的报价”（ExecuteEntry 的价格和 StopsValid 都用这个报价）；钩子为 null 时与原版逐字节同语义；
  4. 入场事件的 trace 增加上述模型时刻字段。
- **管理请求、服务器保护和统计不改。**分叉附带 `S4CoreB4B.diff`（相对冻结 S4Core 的统一 diff），复审时逐行核对。
- **等价 fixture：**同一组合成行情和信号序列，分别交给原版 `S4Core`（链接冻结文件）和 `S4CoreB4B`（钩子为 null），要求 Books、trace 和账户结果**完全相同**，以证明分叉只在钩子路径上有差异。另外**原样**跑 B1 的 90 项和 B4A 的 27 项 fixture。
- **报价适配与 sidecar：**链接 B4A 的 `QuoteFieldAdapter.cs`（哈希绑定，不复制、不修改）。B4B1 算法在每一行应用 flags **之前**检查：存在在途入场请求、`row.ms > deadline` 并且尚未取快照时，取当前生效报价作为快照。钩子只返回这个快照。
- **B4B1 专用边界 fixture（计划，一组）：**
  - 截止毫秒上有行（包含进快照，在下一行执行）；
  - 截止毫秒上有多行，按顺序全部应用；
  - 截止后第一行价格不同（不被使用）；
  - 截止后第一行被跳过（未就绪或交叉）；
  - 截止状态交叉时拒单；
  - 窗口结束时没有截止后的行（End 取消）；
  - B3 slot1 的真实形态：.279 为 4052.88，.378 原始首行为 4052.87 → 成交 4052.88；
  - 钩子为 null 时与原版等价。

## 5. B4B2 的边界（另行登记，这里不设计实现）
- **要研究的现象：**阻塞期间 EA 回调被抑制，即 [T_req 行之后 … T_deadline] 内的行不交给 EA 的 Step（扫描、管理、新单），但服务器 SL/TP 和组合风险维护**不能**被抑制；回调在发起请求的那一步结束后、下一次 EA 步骤之前送达。
- **前提：**需要把 core 中的“服务器保护”和“EA 步骤”拆开调用，这是另一项结构性改动。
- **证据缺口：**阻塞期间测试器对其他持仓的 SL/TP 处理时点没有证据（见第 1 节第 2 项），必须先登记取证方式或明确保守假设，不能猜测。
