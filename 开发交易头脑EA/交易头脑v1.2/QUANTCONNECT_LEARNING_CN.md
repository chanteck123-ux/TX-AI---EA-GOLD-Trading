唯一上游资料源：[QuantConnect-LEAN 资料库](../../research-library/QuantConnect-LEAN/README_CN.md)。优先读[本轮学习指南](../../research-library/QuantConnect-LEAN/LEARNING_GUIDE_CN_20260920.md)、[阅读状态](../../research-library/QuantConnect-LEAN/LEARNING_STATUS_20260920.json)、[归档回执](../../research-library/QuantConnect-LEAN/snapshots/20260920/_provenance/IMPORT_RECEIPT.json)。不在 v1.2 目录重复复制另一套数千文件，避免两份库版本漂移。

六策略 v1.2 与旧 GSM 三 SOP 计划分开。共同工程原则可参考，本次不把旧项目资金、杠杆、风险上限、评分锚点和验收条件复制为 v1.2 默认值。

## 2. 哪些知识进入交易头脑，怎样用

| 知识模块 | 上游依据 | 在 v1.2 的研究用途 | 不能误用为 |
| --- | --- | --- | --- |
| 多模型调度与来源 | CompositeAlphaModel | 保留六策略独立扫描、StrategyID／Magic／SetupID、信号来源与拒绝原因。 | 六策略必须共同投票，或一个 Symbol 目标就能保留六套独立订单。 |
| 信号／组合／风险／执行分工 | QCAlgorithm.Framework | 同一机会从原资格到指标辅助、风险准入和服务器执行均可追溯。 | 必须推倒现有可用架构、套用 LEAN 默认模型。 |
| 事件与状态、数据预热 | EMA 模型、RollingWindow、Warm Up | 分清交叉、方向、斜率；记录决策时点的已完成源柱。 | 将 E1 EMA20 三根差值门换成默认 EMA12／26 交叉。 |
| 目标数量与订单对账 | ImmediateExecutionModel | 查重复下单、部分成交、已有持仓与在途订单造成的数量偏差。 | 按资金表固定手数，或把净额目标当独立策略账本。 |
| 费用与执行真实性 | SpreadExecutionModel、费用／滑点模型 | 新仓点差准入、订单过期、报价异常与成本压力的独立研究。 | 紧急退出也必须等点差缩小；把百分比当 MT5 Point。 |
| 退出与组合状态 | TrailingStop、MaximumDrawdown | 分别登记保本、追踪、分批退出、账户暂停和恢复候选。 | 已经实现服务器 SL、永久停机锁，或默认参数已经适合小资金。 |
| 实验可重复性 | lean-cli | 借鉴运行身份、冻结配置、保存源码、输出目录、错误和结果绑定。 | 将现有 Node／PowerShell／MT5 闭环替换成 Python 或 LEAN。 |
| 研究方法与市场信息 | Research Notebook、额外数据源索引 | 按问题考虑均值回归、趋势／震荡、Kalman、HMM、关联市场或新闻数据。 | 历史画图状态就是当时可见信号；黄金／美元永远反向。 |

该表是有来源的研究知识，不是所有模块同时开启的清单。暂未阅读或未接入的内容保留其状态。

## 3. 研究知识到实际候选的流程

```text
读取原工作区最新证据与已授权任务
→ 定位具体问题、查现有功能和指标库
→ 选择一个用途或有明确交互假设的少量组合
→ 记录固定上游提交、函数、参数、单位、数据时点和假设
→ 在独立 MQL5 候选中接入真实决策路径
→ 实际编译并绑定源码／依赖／EX5
→ 固定资金、行情、风险、SL/TP、成本与测试条件进行原生回测
→ 对照固定参照及当前条件下最佳
→ 查原因、调整／替换／淘汰、重新编译与回测
→ 取得本轮标准支持后冻结，进入跨期／成本／真正未见验证
→ 更新研究状态和完整证据，继续挑战当前最佳
```

本次只做到知识接入；上面的候选开发环节尚未开始。后续获授权执行时，不以只显示指标、只写报告或长期 OBSERVE 代替开发交付。源码或依赖变动要重新实际编译；只改 SET 时可引用已核验且匹配的 EX5，但新实验仍须保存参数和新回测证据。

## 4. 原项目边界保持不变

EA 继续由 MQL5 独立读取执行配置、下单、管理持仓和本地风控。Agent 负责研究配置、编写候选和调用现有编译／MT5 回测工具。Python 仅服务本项目 MCP 监控；本轮存档的 Python／C# 不加入实时运行依赖，监控断线不应阻断 EA 的持仓管理。

用户自己的 Scalping SOP 按已确认范围保护；确认非用户原创的策略按已授权研究范围优化，来源不明先核对。研究风险偏好不自动批准修改风险上限或实盘。退出研究与纯指标组合研究分开，不在同轮同时改入场、初始 SL/TP、仓位和退出后声称找到了唯一改善原因。

开发新指标用途前，先读取 `chanteck123-ux/gsm-mt5-indicators` 最新 README、`indicator_manifest.json`、所选源码、缓冲区与验证说明，记录提交及源码／EX5 哈希。已有功能不重造，不默认叠加所有指标。数据未就绪、EMPTY_VALUE、有效零、柱确认与多周期快照分开检查；Volume Profile 的当前快照不能回填历史信号。

原有完整实验预算和工具边界继续生效。历史说明中的每批最多 4 次新增完整原生回测是批次单位，不是授权无限重置额度，也不是整个研究只能运行 4 次；按当前明确的总预算执行。本次新 MT5 回测次数为 0。

## 5. 比较成绩与保留版本

主表必须同时有：扣费净利润 USD、最大净值回撤 USD、最大相对净值回撤百分比、PF、完整原始交易决策数、总成本 USD 及每往返标准手成本；再补初始资金、窗口、胜率、平均盈亏比、连续亏损、停机／恢复及各策略贡献。两种最大净值回撤字段可以对应不同峰谷，不强行由同一峰谷反算。

沿用项目已接受的起始权重：净利润 35%、净值回撤 25%、PF 20%、交易数 10%、成本 10%。具体公式、尺度、参照、成本口径和本轮推进条件必须从原工作区已冻结 criteria 读取，不在资料入库时另设新阈值，也不把旧三 SOP 的锚点代入。

分数是研究排序规则，不是胜率、收益率或未来盈利概率。缺失费用、PF 不可定义、零交易等不能伪造满分或擅自重分配权重。少亏只称少亏；较高回撤可保留为明确的取舍版本，不能借高净利宣称未来安全。

固定原始参照、当前条件下有证据的最佳、最新候选分开保存。已用于调参的六月／八月等窗口不再称未见 OOS；若原工作区有更完整的使用记录，以该记录为准。提款后的持续运作必须另用明确现金流方案验证，不能由某月重置资金的漂亮成绩替代。

## 6. 每次复用知识要留下什么

知识记录字段建议：`knowledge_id`、来源仓库／commit／文件／函数或 cell、原实现单位、实际阅读范围、目标问题、拟接入决策位置、项目边界、已知限制、状态和引用实验。

实际实验字段按原项目维护：父版本、候选 ID、改动原因、策略归属、源码／指标／EX5 哈希、有效 SET、编译日志、原生 HTML／CSV、行情与经纪商条件、原始指标、评分、停机／恢复、失败原因与下一步。知识卡不能代替这些真实证据。

建议根据当前未解决问题选择的首批知识审查是：A 信号与目标数量对账、B 决策时点与预热、C 新仓执行门与紧急退出分流。只有出现对应问题才登记候选，不抢占已有未完成批次、不凑测试次数。本页保存不启动这三项开发。
