# 交易头脑：500 USD 起步的 LEAN＋FxPro 验证计划

版本：v1.0，2026-09-27。状态：计划与只读盘点；新候选未实现、未编译、未回测。

## 1. 目标、口径与项目边界

- 初始资金500 USD，无追加资金、无重置账户。挑战目标为连续12个完整自然月成本后净利润合计不少于12,000 USD，即月均不少于1,000 USD；亏损月、无交易月、暂停月全部计入。
- 主口径为不提款、资金留在账户内的路径；月均净利=12个月净利合计/12，不是每月固定赚1,000，也不是每月固定回报率。以初始500计算，单月1,000为200%；若12个月从500增长至12,500，等效月复合增长率约30.766%。这是挑战目标，尚无验证证据。
- 月末提款作为独立资金路径运行，不能由复利利润表直接推算。每月最后一日23:59:59 UTC由独立日历事件检查一次，不依赖当天是否有Tick；只有无持仓、无挂单、无未知结果请求、费用结算完成且对账一致时，才模拟提款。金额为向下取USD分位的`max(0, min(1000, min(已结算USD现金, 可用保证金)-500))`。缺少有效账务快照或条件不满足，则当月记0，不延期补提、不为提款强制改变原退出。以账户/路径/年月唯一键去重，同时真实扣减该模拟账户的可交易现金和风险计算本金，交易净收益与累计提款分开。
- 本专项沿用此前选择的纯C# LEAN＋FxPro cTrader路线：C#负责策略、执行与本地风控，Python只作MCP监控。原MT5项目继续由MQL5独立执行，已有MQ5/EX5及用户Scalping恢复版保留。这份专项计划不把C# DLL称为MT5 EX5，也不覆盖旧版GSM升级计划。
- S4 C7 ON优先，S1 C7 ON随后。S2/S3/S5/S6及用户Scalping单独研究；不把其现有MQL5代码说成已迁移的C#策略。用户Scalping的核心改法另记问题、依据、改动和影响。
- 风险、数据及验证条件优先于收益目标。未达到目标就报告差额；不通过补资、挑月份、放宽已冻结风险或抹去暂停期达标。

## 3. 先做数据和小资金可执行性盘点

将证据明确分为两类：

1. **工程诊断**：使用现有2026年8月MT5 FxPro真实报价与原生闭柱，固定登记成本模型，检查500 USD现金、手数、拒单、停机和账务。结果标`ENGINEERING_DIAGNOSTIC / MT5_SOURCE / USED_DEVELOPMENT`，不能用于宣称cTrader盈利或挑战目标达成。
2. **正式cTrader验证**：取得对应cTrader账户品种规格、历史bid/ask与闭柱语义、佣金、swap、交易时段、动态保证金及历史变更依据。数据满足要求后，才能登记正式开发和独立验证区间。

每份数据保存来源、抓取时间、事件时间/可用时间、时区与夏令时规则、起止、粒度、行数、文件哈希、缺口、重复及异常报价。相同毫秒允许多条真实报价；分页边界不得按时间戳简单去重而丢行情。无报价形成的空柱与缺失数据分开识别。

合约规格由账户和品种查询驱动，核对symbolId、报价精度、tickSize、lotSize、minVolume、stepVolume、maxVolume、账户币种、moneyDigits、止损距离、交易权限、保证金及强平规则。不得直接沿用“黄金一手100盎司、最小0.01手”的MT5快照到cTrader。

最小量每笔预计风险=实际买卖侧入场至策略初始SL的预计损失＋未包含的佣金/费用＋登记的不利滑点储备；向下取合法步长。初始止损保持策略定义，不为凑最小量临时缩窄。预期将来保本不抵扣初始风险。点差已体现在bid/ask成交价时不重复扣。

输出拒单归因：完整合格setup数、唯一setup被最小量/保证金/点差/时段/风险暂停挡下的数量、最终成交数，以及逐次尝试日志；重试不得膨胀拒单率。旧成交机会的静态测算只作诊断，不当完整信号拒单率。

**门槛**：同源数据、成本或单位无法校准时，暂停正式cTrader收益排名和大规模调参，列出具体缺口；可以继续有明确标识的工程诊断。历史swap缺失不得填0或冒充真实历史；快照/不利假设必须另表，并限制结论。

## 4. 研究风险政策

下列为待实现、待测试的专项研究政策，不是已生效的实盘配置。

| 项目 | 政策 |
|---|---|
| 基础风险 | 固定1%为基准，固定2%为主档；3%仅在后续单独登记对照，不因前一笔亏损升档 |
| 同时占用 | 初版最多1个黄金仓位或1个新增风险请求；挂单、在途/未知成交、未确认平仓均占用；未知状态阻止新增 |
| 初始风险 | 同一净值快照核算全部仓位、挂单、预留风险；单仓也不省略组合账本；现有原始风险不因动态倍率降低而少计 |
| 保证金 | 预计总占用不超过净值25%；以券商规格、动态档位及预估保证金响应校准，不能只用名义杠杆公式 |
| 日损/连亏 | UTC日基线净值损失达到6%，或3笔连续净亏完整交易，暂停新风险至少24小时；既有保护继续执行，恢复须数据及对账有效 |
| 紧急停机 | 资金流校正后净值回撤达到15%即锁定、取消入场请求并尝试平仓；保存未知/失败结果，查询重试、报警。本批回放锁至冻结窗口结束，不人工挑时点解锁；未来Demo/实盘须复核，若研究恢复规则另登记候选 |
| 动态风险候选 | 回撤达到5%→基础风险×0.5；达到10%→×0.25；恢复分别要求回撤低于3%/8%持续24小时且对账/数据有效，每次最多恢复一级 |
| 资金受限 | 合规最小量风险超预算时记`CAPITAL_CONSTRAINED`并拒绝新增，不提高风险、不重置净值高点；保持诊断，可改研究假设 |

15%是触发线，不是保证损失上限；跳空、流动性、断线或拒单可能越过。正式验证若最大相对净值回撤超过15%，标风险目标未通过，不能因总分高而覆盖。

固定档与动态档分开比较；固定档不使用5%/10%衰减，但保留共同的账户停机边界。日暂停不延长12个月收益目标窗口。连亏的统计和每次暂停触发点持久化，避免恢复后因旧触发事件立刻反复暂停；不通过清除历史亏损制造恢复。

动态档降风险后可能已无法承接任何最小量信号，无仓净值也就无法自然回升至恢复线。这是该政策可能造成的持续资金受限结果，须报告持续时间和余下零收益月份；不能因为等了24小时就恢复基础风险。若要解决这一弱项，另登记替代降风险/恢复政策并从相同起点重测，原路径不改写。

初始风险金额/初始SL/原始R永久保留，当前SL风险和当前净值至SL风险另列。止损只有服务器确认后才记生效，只能收紧；保护缺失或失效时，停止新增并尝试市价退出，记录未完成退出，不能只写“已保护”。

现金流采用份额净值法：入金/提款按资金流发生前份额净值变更份额，不改变单位净值及其历史高点；同时记录实际可交易权益。提款不被误计为亏损，也不能清空旧回撤。仅改一列虚拟余额不算有效提款模拟。

## 6. 优化顺序与停止盲试的条件

- 先查不成交/亏损/回撤的具体原因，再提出可验证假设。每批记录假设、变量、基准、预期作用、预算和失败解释。
- 退出模块在固定信号、原始SL、基础风险、行情及成本下比较：原退出、仅成本保本、仅ATR追踪、两者组合；分批出场另批研究。成本保本首次候选可登记1R触发；追踪首次候选可登记1.5R触发、2倍已收盘M15 ATR距离、0.25 ATR步长。这些是待测试候选值，不是胜出默认值。0.01手不能假装分成0.005手。
- S1/S4组合必须共同运行、共享风险和同一时间线，先确认者优先，同时间S4优先；不能相加独立利润。记录冲突、同时亏损及不同市场状态的表现。
- 新指标先核对用户指标库当前README、manifest、缓冲接口和时间语义，按用途/位置/触发选择。C#迁移要验证数据和指标一致性，不直接运行EX5或仅复制名称。初批不新增指标，避免同时改变资金、信号和退出。
- 动态市场风险后续分批研究趋势/震荡、黄金与美元相关输入、新闻与日历；只使用当时可得数据。历史日历缺失不填为“无新闻”；相关性不预设反向；模型分数不直接升风险。
- 同一假设方向连续两批各最多4个候选都未在有效同条件证据上改善约束内表现，则结束该方向的当前试验，转向已记录的下一原因或数据问题。研究仍保留恢复点，不无限重跑同组，也不因一次失败断言所有方法无效。
- 独立12个月窗口完成后若净利不足12,000，明确该冻结候选未达挑战目标及差額；不延长/挑选窗口补成绩。样本和成本不完整则是证据不足。低于挑战目标的正收益候选可保留研究身份，不能自动降级为实盘运行。

## 7. 接入与压力验证的关键要求

1. 固定依赖和源码提交；旧工程引用自身vendor/Lean，未经重新构建核验不混用独立安装目录DLL。
2. cTrader动态查symbolId及完整规格。协议数量为单位的百分之一，与手数不同；relativeStopLoss/relativeTakeProfit另有价格缩放单位。全部通过规格表和经过测试的转换层处理。
3. MARKET订单按官方相对保护字段提交，收到成交及仓位事件后确认服务端SL/TP。入场前保存原结构SL和目标；相对保护可能因成交滑点偏离原结构SL。首次接入候选允许偏差最多1个合法价格增量，并须满足预算；超出时仅可向更保护的方向校正并等待确认。若恢复原结构SL需要放宽、预算超限或校正未确认，则停止新增并尝试市价退出，成本计入结果。容差、超时和退出处理在正式测试前固定，不按结果选择。请求返回不当成交；clientMsgId只作关联，不假设服务端保证幂等。
4. 持久化策略setup、请求、orderId、positionId、dealId和成交分配。断线、超时、未知结果先查询对账再决定是否补发。部分成交、重复/乱序事件和重启需专门验证。
5. 请求限流低于官方每连接非历史50次/秒、历史5次/秒上限；保留必要保护和查询余量。合并同一仓位待发SL收紧请求，拒绝过期放宽，追踪请求/确认版本。
6. 保护性SL不能因为撤销入场单而被错误撤销；平仓请求未确认期间仍保留保护与风险预留。账户存在外来仓位/订单则停止新增并记录原因，不擅自接管。
7. 压力场景分开记录：正常/双倍佣金、不利滑点、250ms/1秒延迟、跳空越过SL、断线与重连、报价过期、修改失败、部分成交。无真实深度数据时“流动性枯竭”只能是合成压力模型。
