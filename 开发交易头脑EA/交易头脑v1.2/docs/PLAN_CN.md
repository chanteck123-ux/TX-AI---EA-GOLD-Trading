# 开发交易头脑 V1.2 黄金 EA 计划

长期执行版｜更新日期：2026-10-03

这份计划用于持续研究、开发、回测、复审和改进黄金 EA。每轮从最近的有效证据和恢复版本接续，按“查问题 → 提出调整 → 实际修改 → 验证 → 比较 → 保留或回退”推进。主计划保持稳定，阶段成绩、当前版本和下一步更新在现有研究记录中，不需要每轮重写整份计划。

用户要求修改计划时，完成计划维护；用户要求按计划开发或继续时，在已授权范围和登记预算内执行研究。保存计划不等于已经启动后台任务、编译、回测、Demo 或实盘。

**开始前先选择使用 Claude 或只用 Codex，具体按第2节执行；不默认沿用上一次模式。**

## 1. 长期目标

初始研究资金为 500 USD。重点是扣除成本后的净利润、账户持续运作能力，以及提取利润后能否继续按规则交易。

保留挑战目标：无追加资金、无重置账户，在事前固定的连续 12 个完整自然月内，成本后交易净利合计不少于 12,000 USD，即月均不少于 1,000 USD。亏损月、无交易月和风险暂停月全部计入。月均目标不表示每月固定盈利，也不构成未来收益保证。

不提款的连续账户和月末提款账户分别完整测试。目标未达到就报告实际差额，查明原因并登记新候选；不通过挑月份、改写旧结果、补资或放宽既定风险来制造达标。达到某轮标准后保留该版本，仍可继续研究挑战它。

## 2. 技术路线与职责

交易和本地风控使用 FxPro MT5 / MQL5。AI 负责研究和开发流程，EA 不等待 AI、MCP、远程桌面或云服务才管理已有仓位。Python 仅用于本项目 MCP 监控端。

每次开始新的开发任务或接续研究前，先让用户选择：

1. **使用 Claude**：Codex 与 Claude 共同讨论和复审，Claude 写改代码，Codex 协调、编译、测试及整理证据。
2. **不用 Claude，只用 Codex**：Codex 负责分析、写改代码、编译、测试、复审和研究记录。

当前请求已明确选择时直接采用，不重复问；否则等待选择，不默认任何模式，也不启动该轮研发。已授权的文档维护和只读核对可以继续。选定后同一次任务内不在每个技术步骤重复询问；下一次新任务或用户另行发起接续时重新给选择。两种模式沿用相同的策略权限、风控、验证和恢复规则。

## 3. 每次开始或继续时

先完成第2节的模式选择，再启动该轮研发；以下只读核对可在等待选择时进行。

1. 读取最新计划、[当前研究记录](../research/CURRENT.json)、本轮候选及原始证据；先核对 GitHub 与本地是否有较新修改，不覆盖其他任务的工作。
2. 找到各策略当前保留版本、恢复版本、源码默认配置、匹配 EX5 和已完成运行；“最新文件”不自动等于“当前最好版本”。
3. 检查上次任务是完成、运行中、中断还是失败。核对编译／测试进程、输出和检查点，确认无人占用固定终端，再决定接续或重测；已经核验完成的项目不无故重跑。
4. 核对数据使用记录、成本校准、评分政策、剩余预算和未解决问题。旧记录有冲突时回到源码、原报告、日志和哈希查证；缺证据就注明，不能补造。
5. 根据最新弱项选择下一项工作，说明为什么先处理它、怎样验证。不能把某一历史轮次的优先顺序永久写死。

现有 MT5 与 LEAN 报告继续保留原日期和平台身份，研究从它们接续。历史成绩不写成此次新测试；主计划不重复维护某个月的收益表。

## 4. 七套策略怎样研究

S1–S6 与用户 Scalping 分别登记、比较和保留版本。每套策略先讲清三个问题：

- 用途：解决什么交易问题，适合什么行情，各条件承担什么判断。
- 位置：机会发生在哪个有效价格、结构或区域。
- 触发：什么事件发生后入场，何时确认、按什么顺序执行，以及何时失效。

策略来源登记为 USER_OWNED、NON_USER 或 UNKNOWN。用户自己的 Scalping SOP 保留已确认规则；确需改动核心、初始 SL/TP 或持仓管理时，先说明问题、依据、具体改法和影响，按明确授权执行。确认非用户原创的策略可在已授权研究中自主优化；未知来源先核对，不按策略名称推定权限。

开发或修改前读取用户 [MT5 指标库](https://github.com/chanteck123-ux/gsm-mt5-indicators) 的最新 README、indicator_manifest.json、相关接口和验证说明。候选池为 EMA_20_50_100_200 / SMA_Ribbon，GSM_SNR / GSM_SND / SMC_Structure，ZeroLag_MACD / CM_MACD_Ult_MTF，Bollinger_RSI_ChartArt / Stoch_RSI / GSM_ADX_Trend，Saty_ATR_Levels，Volume_Flow_Indicator / Volume_Profile。

按策略用途自主选择周期、参数和搭配，不默认全部开启。登记指标介入哪一步、AND/OR或先后关系、冲突与缺失处理；核对缓冲区、BarsCalculated、CopyBuffer、EMPTY_VALUE、有效零、闭柱和多周期确认。Volume Profile 当前快照不能回填历史；逐时重算须先验证当时可得数据。

默认先做单项对照；有明确交互假设可登记少量组合，再用单项及移除组件对照判断贡献。合理假设通过接口检查后，继续接入候选决策、编译、回测和比较；只显示指标或长期 OBSERVE 不算开发完成。

保本、移动止损、两者组合和分批出场分别研究。退出对照固定入场、初始风险、行情和成本；改变初始 SL/TP 或信号时，明确它已是另一类实验，不把收益增加全部归功于退出模块。

## 5. 每轮固定执行的循环

| 步骤 | 实际工作 | 完成依据 |
| --- | --- | --- |
| 找问题 | 复核亏损、不成交、回撤、费用、异常停机或收益集中的原因 | 具体交易、日志或数据，而非猜测 |
| 定方案 | 提出少量有依据的改法，写清预期作用和如何被否定 | 假设、改动变量、固定条件和验收标准 |
| 登记 | 固定父版本、比较组、资金、区间、风险、成本、执行延迟及预算 | candidate_id、run_id、配置和政策 |
| 实现 | 按所选模式由 Claude 或 Codex 修改真实候选，保留原版；对应复审者检查需求和受影响逻辑 | 源码差异及复审记录 |
| 验证 | 必要编译、工程检查和新回测，核对账务与报告身份 | 匹配日志、EX5、配置及原报告 |
| 比较 | 对照固定基准和当前同条件最佳，列出全部关键差额 | 净利、回撤、PF、交易数、成本及运行状态 |
| 决定 | 保留、继续研究、回退或淘汰；注明原因 | 证据支持的选择和恢复点 |
| 接续 | 更新最新状态、剩余预算和下一项具体任务 | 下一次无需从聊天猜测进度 |

每批默认最多 4 个新候选，每候选使用两个事前固定的开发区间，并有同条件对照。同策略、同版本及同条件的有效对照可以复用；不同策略、不同风险或成本不能共享不匹配的基准。

开跑前登记候选总数、完整回测、工程复跑、压力测试和时间／计算预算。四候选两区间通常为八场候选测试，对照另计；失败运行同样计入已用预算，不通过改名或自动开新批重置总额度。

已授权范围和预算内主动推进，不为常规技术选择反复确认。一条方法失败先查原因，有依据就调整或换方法；同一方向连续两批仍无改善，结束该方向的当前试验，转向已记录的其他原因。整个研究保留最佳和失败经验，避免重复盲试。

预算用完、缺少必要数据或授权、环境无法继续时，保存可恢复状态并说明具体缺口；能独立完成的工作继续完成。下一批在既有授权内登记；超出授权范围再提出具体决定，不默默扩大风险、工作量或实盘范围。

## 6. 数据、资金与风险

每批读取真实账户及品种属性：账户币种／模式、GOLD 实际符号、报价精度、Point、合约、最小量与步长、止损限制、保证金及 Stop Out。行情记录来源、时区／夏令时、范围、粒度、哈希、缺口、异常和真实 Tick／生成回退情况。正式收益验证使用 MT5 Every tick based on real ticks，并核对实际覆盖与回退；工程快测另行标识。

手数由净值、风险预算、入场至初始止损的预计损失、未含成本和合约共同决定，必要时用 [OrderCalcProfit](https://www.mql5.com/en/docs/trading/ordercalcprofit) 估算账户货币损益，并另核对保证金。向下取合法步长；最小量超预算时记 CAPITAL_CONSTRAINED，不向上凑量或临时缩 SL 隐瞒风险。

每轮先固定基础风险上限及账户／策略限制。下面保留为可独立比较的研究政策，采用前登记并实际验证，不能因列在计划里就成为现有 EA 默认值：

| 研究项 | 候选定义 |
| --- | --- |
| 固定风险 | 1% 基准与 2% 主研究档比较；3% 另行登记，不因上一笔亏损升档 |
| 并发与保证金 | 单仓／单新增风险请求、预计总保证金不超过净值25%作为独立对照；原槽位改变须明示 |
| 日暂停 | UTC 日基线净值损失6%，或连续3笔完整净亏交易，暂停新增风险至少24小时；恢复须数据及对账有效 |
| 紧急退出 | 资金流修正后净值回撤15%触发新增锁定、取消入场并尝试平仓；记录失败与未知结果 |
| 动态风险 | 回撤5%时基础倍率0.5，10%时0.25；分别低于3%／8%持续24小时且状态有效时，最多恢复一级 |

固定档与动态档分开比较。采用紧急锁定候选时，测试锁定维持到冻结窗口结束；其他恢复方式另立候选。降风险后若最小量已不可交易，须记录持续受限和零收益时段，不因等待24小时就自动升回基础档。15%是触发条件，不保证未来最坏亏损上限。

已有仓位、挂单、在途／未知结果和未确认平仓均计入风险；动态倍率下降不减少既有风险的计量。初始风险、原始R、当前SL风险分别记录。保本不能抵扣入场风险，价格保本不等于费用后的净收益保本。

先独立执行已有仓位保护、对账与已登记紧急管理，再处理新增风险。点差、时段、新闻、新K线或AI过滤不得提前返回阻断保护。保护性SL只收紧，确认服务器接受后才记生效。平台或EA停止后不会计算新的追踪位置，服务器已接受的SL仍按券商规则执行。

请求返回成功不等于成交。订单、仓位、部分成交、重复／乱序事件、超时和重启分别核对，不假设每个报价都被OnTick处理，也不假设交易事务按固定顺序到达。[MQL5交易事务说明](https://www.mql5.com/en/docs/event_handlers/ontradetransaction)

## 7. 持续研究市场状态与外部信息

分批研究趋势／震荡识别、动态风险、黄金／美元关联、新闻及经济日历，按问题选择用途，不将所有模块同时启用。

输入记录观察时间、发布时间、可用时间、修订及数据年龄；缺失或过期明确标记。历史没有新闻记录不等于当时没有新闻，事后AI分析不能倒灌进历史决策。美元与黄金不预设固定反向，AI分数不直接当胜率或加仓理由。

分别测试无该模块、加入模块及必要的移除对照。新风险过滤、正常新闻暂停及恢复，与异常停机分开评价；不能为凑笔数强行交易。保护执行始终由MQL5独立负责，监控反馈进入后续研究，不自动热更新实盘。

## 8. 每轮怎样判断成绩

同条件比较至少报告：初始资金和测试长度、净利润USD、最大净值回撤USD、最大相对净值回撤%、MT5原生PF和自算净PF、完整交易数／Setup数／Deals数、总成本及每往返标准手成本。

同时检查胜率、平均盈利／亏损、成本后期望、连续亏损、收益集中、保证金、Stop Out、暂停／恢复、恢复时长和期末未恢复。原生Recovery、Equity Recovery、夏普分别标明定义；夏普仅辅助，不额外计权。交易数和History Quality都不能单独证明样本可靠。

综合评分固定为100分，显示百分比：

| 项目 | 权重 | 输入 |
| --- | ---: | --- |
| 净利润 | 35% | 同区间净交易利润P，排除入金和提款 |
| 净值回撤 | 25% | 全程最大相对净值回撤D，金额回撤另列 |
| PF | 20% | MT5原生PF F，自算净PF另列 |
| 完整交易数 | 10% | 同口径完整开平仓N，不用拆分Deals凑数 |
| 单位成本 | 10% | 相同合约每已匹配往返标准手成本C |

先登记P_target、D_good/D_bad、F_target、N_target、C_good/C_bad及其依据，固定同条件比较组和政策。挑战目标1,000 USD、PF 2等示例不自动成为评分锚点，不能看结果改尺度抬分。正式指标和固定尺度换算沿用已保存的§11.1及§13.10评分规则。

    clip01(x) = min(1, max(0, x))
    S_profit = 100 * clip01(P / P_target)
    S_dd     = 100 * clip01((D_bad - D) / (D_bad - D_good))
    S_pf     = 100 * clip01((F - 1) / (F_target - 1))
    S_trades = 100 * clip01(N / N_target)
    S_cost   = 100 * clip01((C_bad - C) / (C_bad - C_good))
    Score    = 0.35*S_profit + 0.25*S_dd + 0.20*S_pf + 0.10*S_trades + 0.10*S_cost

锚点必须有效：P_target为正、N_target为正整数、F_target>1、0≤D_good<D_bad、0≤C_good<C_bad；全部输入为有限值，D/F/C非负、N为非负整数，单位统一。PF极大哨兵值、无亏损分母及零有效往返量不能当作有效输入。政策不完整时总分为 N/A / SCORE_TARGETS_UNSET；关键数据缺失或PF无定义时为 N/A / INCOMPLETE。不补满分、不重分权重；可继续原始指标诊断与授权内研究。

成本C以匹配开平仓量归一：开1手平1手为1往返手。成本评分统计非负摩擦支出，正swap／返佣另列；点差与滑点按冻结基准拆分，避免重叠。实际净利已含的费用不重复扣除，不能把只有显性费用的字段冒充完整摩擦成本。

每轮展示原始值、分项、总分与相对当前同条件最佳的差额，直说多赚／少赚多少USD、回撤和成本怎样变化。收益因提高风险增加时单独说明，不称为纯策略改善。

80%表示80/100分，不是胜率或通过线。评分、基本达标、独立验证、Champion与部署状态分开；高分不覆盖亏损、样本不足、强平或异常停机。没有合格最佳时如实记录，仍可保留研究候选和较低风险恢复版。

## 9. 冻结后验证与提款研究

开发区间可以反复调整并保留全部尝试。候选达到事前标准后冻结源码、EX5、默认配置和依赖，再做跨期、成本／延迟／跳空压力、真正未参与选择的样本外及故障恢复验证。

成本压力覆盖佣金、隔夜费、点差与不利滑点；执行压力至少比较已登记基准延迟与更差延迟，并核对断线、过期报价、修改失败、部分成交和重启。无真实深度依据的流动性场景标为合成压力。任何验证数据一旦用于调整，改标已使用，后续另留独立数据。

七策略先独立验证，组合必须在同一账户时间线共同运行，核算共享资金、风险、冲突和相关亏损；不能把单独净利相加当组合成绩。

连续账户从500 USD开始，在固定12个月内不补资、不重置。不提款和提款使用独立账户路径完整重跑，包含全部暂停及资金受限月份。

月末提款候选检查时点为每月最后一日23:59:59 UTC，每月一次。只有无仓位、无挂单、无未知结果请求、费用结算完成且对账一致，才按下式向下取USD分位提款；条件不足当月为0，不补提、不为提款强改原退出：

    max(0, min(1000, min(已结算USD现金, 可用保证金) - 500))

提款必须真实扣减模拟账户可交易现金和风险本金，以账户／路径／年月去重。采用份额净值法校正资金流，记录交易净收益、累计提款、剩余权益、历史回撤和提款后可交易能力；提款不算交易亏损，也不重置旧回撤。

MT5的UTC转换、无Tick月末、重启漏事件、实际检查时点及现金扣减须专门实现并核验。未证明时标 WITHDRAWAL_PATH_UNVERIFIED，不用报告上减一列余额或下一Tick补查冒充有效月末提款。

冻结验证后才进入对应版本的前瞻Demo。保留“至少3个完整月且50笔完整交易”为待登记研究方案；按实际已选前瞻标准判断，样本不足不强行交易。修改后重做受影响验证。Demo、目标达成和实盘授权分别确认。

每个candidate_id/run_id关联：EA与指标源码、对应默认参数、EX5、SET/INI、编译日志、数据清单、订单／净值审计、原报告、评分政策、复审结论和SHA256。
